## Unity 선택의 판단 근거

2D 그리드 화면과 C# 규칙 테스트 반복에 적합하다고 판단했다. Unreal도 구현·자동 테스트가 가능하고 기존 경험을 활용할 장점이 있으나, 이번 프로젝트는 새로운 시뮬레이션 중심 구조이며 이전할 기존 소스가 없었다. 이는 비교 벤치마크 결과가 아니다.

- 개발 일정과 가용 시간, 최종 게임명·아트 스타일·목표 규모.
- 패키지 버전은 0-A에서 고정 완료했으며 미정 항목에서 제외한다. 실제 목록은 [Setup.md](Setup.md) 참조.
- 작업 소요 시간, 게임 내 하루 길이, 욕구 회복량·능력 저하 수치.
- 세부 경로 비용, 저장 포맷, 대규모 성능 목표.
- 전투 명중·제압·확률 규칙의 수치와 Fog of War의 세부 시야 알고리즘.

미정 사항은 필요한 작업 직전에 최소한으로 결정한다. 이전 결정 변경 시 이력을 지우지 말고 대체 결정과 이유를 추가한다.

## 전체 로드맵 다중 세션 계획 (2026-11-15)

사용자는 전체 로드맵 기준의 세션별 기능, 병렬 순서, 공통 계약, 파일 소유권, 통합/완료 기준을 문서화하도록 요청했다. [전체 계획](Plans/MultiSessionRoadmap.md)과 [공통 계약](Contracts/ParallelFeatureIntegration.md)에 반영했다. 기존 작업0~3 완료를 기반으로 건설/재배부터 데모까지 묶음을 나누고, 작성 병렬성과 완료 순서를 구분한다.

운영 권장안은 통합 S0+기능2세션, 기존 폴더 유지+기능별worktree 추가다. 분리 비용은 별도 Library/import이며 혼입·전역 동결을 줄이는 이점이 있다. 실제 전환은 미실행·미확정이다. 공유 폴더 유지 시 파일 소유권과 전체 입력 동결 규칙을 유지한다. 공통 코드는 S0만 변경하고 전용 기능은 UI·검사까지 함께 소유한다. 같은 프로젝트는 물론 초기에는 폴더 간 Unity 검사도 직렬 운영한다.

후반부 전투/정보전 수치와 범위를 확정된 것으로 취급하지 않는다. 현재는 계획 승인 범위이며 구현·worktree/세션 생성·커밋·원격 연결·push는 하지 않는다.


## 현재 구현 범위와 세션 수 확정 (2026-11-15)

사용자는 건설·재배·조리·작업계획·저장까지만 현재 구현 대상으로 정했고, 작업계획은 개인 우선순위·작업 끄기·자동 배정임을 확인했다. 이번 요청은 그 범위의 문서 작성이며 실제 구현/커밋 승인이 아니다.

[현재 실행 계획](Plans/SettlementFiveFeatures.md)에 통합S0+기능SA/SB를 고정했다. SA는 건설→조리→저장, SB는 재배→작업계획→연결 검사. QA역할을 SB에 포함해 세션 수를 늘리지 않는다. 전체 로드맵은 보존하되 장기 자급·전투·치료·정보전·데모는 현재 범위에서 제외한다. 시험용 입력 검사와 실제 다섯 기능 연결 검사를 분리하고, 공유 파일/실제 Unity 실행은 S0에 집중한다.

현재 공유 폴더를 유지하며 worktree 추가는 실행 전 선택할 권장안이다. 현재는 문서만 변경했고 구현·세션/worktree 생성·커밋·원격 연결·push는 하지 않는다.

## G0-D 확정과 G0-C 분리 (2026-11-15)

사용자는 기능 구현/커밋 없이 G0 준비 규칙을 확정하도록 요청했다. [준비 확정서](Plans/G0-Preparation.md)에 `settlement-five-v2`를 고정했다. 기존 폴더를 통합용으로 유지하고 기능 착수 때 SA/SB 별도managed worktree를 사용한다. 이번에는 실제 폴더/브랜치/세션을 생성하지 않았다. 공통 접점·시험 수치·조작·한 슬롯 저장 정책을 확정했으며, 기존 안정 상태의 단일 권한을 유지하도록 반입 시 집기 순간 목적지 권한으로 교환한다. 기존 운반 집기/놓기는 각각 도착 다음1Tick임을 소스에서 확인해 유지한다. 문서 확정 G0-D와 실제 코드 연결/회귀 G0-C를 구분하고 후자는 별도 구현 요청 후 진행한다.

## 2026-11-15 G0-C 최소 연결

기존 Gather/Haul을 실제 공통 후보·시작·취소 경로로 연결한다. 전체 후보를 모든 프레임에 수집하는 방식보다 기존 재평가 시점과 운반 우선 단계를 보존하는 방식을 선택했다. 기존 검색/행동 순서를 유지하는 대신 G0-C의 후보 목록은 모든 종류를 한 번에 제공하지 않는다. 개인 우선순위 통합(J2) 때 전체 후보 선택으로 바꾼다. 후보는 불변 값/경로 스냅샷이며 동일 월드·Pawn·ActionId·Tick·가용성/통행 revision의 S0 발행 후보만 시작 가능하다. `NoAllowedStorage`, `DestinationReserved`, `StorageFull`을 WorkReasonCode에 추가해 기존 표시 이유를 잃지 않는다. 기존 운반 후보 TargetId/SourceId는 모두 출발 스택이며 저장 목적지는 집기 때 정한다. 미래 반입 후보는 TargetId가 최종 현장이다. 계약 v2의 명칭/게임 규칙을 바꾸지 않는 G0-C 구현 범위 명세다.

## 2026-11-15 건설·재배 병렬 착수

사용자 승인으로 S0 통합+SA 건설+SB 재배 역할과 별도 managed worktree를 사용한다. 검증된 미커밋 G0-C 제품156개를 해시 대조해 전달했다. 기존폴더와 사용자의 AGENTS 수정은 보존한다. 건설은 실물 목재를 출발 스택에서 현장에 옮기고 완공 시 소비한다. 재배 칸은 수확/재파종 동안 ID를 유지하며 단계/진행과 새 요청순으로 상태를 구분한다. 조리대 건설은 이번 범위이나 조리 생산은 다음 범위다. 새 화면은 물류/생산 패널 전환으로 기존 표시 공간을 유지한다. 계약/소유권 상세는 실행 카드에 기록한다.

## 2026-11-15 미소집 이동 및 건설 정보 수정

사용자 보고에 따라 과거 대기 중 미소집 수동 이동을 허용한 규칙을 폐기한다. World.QueueMove에서 소집 상태를 검사하며 접수 거부는 기존 자동행동/점유를 건드리지 않는다. 큐 적용에서도 다시 검사한다. 자동 생활/작업 경로 설정은 별도라 영향이 없다. 건설 패널은 선택한 Pawn의 반입 의도/실행 대상을 따라 현장 정보와 명령 대상을 함께 연결한다. 이미 선택 중인 Pawn이 건설을 시작하는 경우도 표시를 갱신한다. 이동 시험의 입력은 명시적 소집으로 바꾸고 기존 이동시간/경로/시간조작 기대는 유지한다.

## 2026-11-15 조리·개인 작업계획 연결

사용자 정상 확인 이후 S0/SA/SB 세 역할로 조리와 작업계획을 병렬 구현한다. 소유권/API는 [인계 카드](Plans/Sessions/CookingWorkPolicy-Handoff.md)를 따른다. 공통 루프·상태 변경은 S0, 전용 규칙/상태/패널/검사는 각 기능 담당에게 둔다. Unity import/검사/빌드/Player는 S0만 직렬 실행한다.

조리 목표 회차는 주문 재생성 여부와 무관하게 시설ID순으로 재평가한다. 구조상 접근 불가·담당 설정 없음은 새 생산 예정량을 선점하지 않는다. 보류한 진행/내부 자재는 보존한다. 출력은 기존 음식 스택과 공유 점유를 사용하고, 기존 출력에 추가 생산해도 CreatedTick을 갱신하여 스택 전체의 새 일반 운반을 다음Tick부터 허용한다.

정책은 수행 가능한 전체 작업 후보를 비교한다. 숫자 우선순위 변경은 현재 작업을 유지하고, 끔은 해당 작업을 즉시 취소한다. 생활과 소집은 정책에 앞선다. 진단 조회는 읽기이며 화면 갱신 때문에 Tick·점유·경로 검색 계수가 바뀌지 않는다. 실제 결과와 제한은 [검증](Verification/2026-11-15-cooking-work-policy.md), 검토 근거는 [교차 검토](Reviews/2026-11-15-cooking-work-policy-review.md)에 남긴다. 커밋·원격·파일 저장 구현 승인은 포함되지 않는다.

## 2026-11-16 한 슬롯 저장·불러오기

조리·개인 설정의 사용자 정상 확인 이후 저장 S1/S2 구현 승인을 받았다. BCL DataContractJsonSerializer와 명시적 DTO를 사용하고 패키지는 추가하지 않는다. 저장 전·임시 파일 재읽기 뒤에도 후보 복원을 검증하고, 정상 파일 교체가 실패하면 기존 슬롯을 유지한다. 입력 캡처/검증은 현재 월드를 바꾸지 않으며 새 후보만 완성 후 교체한다.

수면 진행은 경과 시간으로 보존하고 식사 기간과 구분한다. 삭제된 조리 주문의 점유는 시설과 같은 객체이며 출력 삭제 후 분리된 권한은 별도로 복원한다. 물자 장부는 long으로 대조한다. 동기 파일 I/O 직후 첫 자동 프레임을 생략하고 이후 정상 진행해 지연 시간이 게임 Tick에 추가되지 않게 한다. 저장된 시간잔여/배속/정지 상태 자체는 바꾸지 않는다. 파일이 없는 경우/손상/미지원 버전은 한국어 오류로 표시하고 현재 상태를 유지한다. 세부 근거는 [교차 검토](Reviews/2026-11-16-save-load-review.md), 실행 증거는 [검증](Verification/2026-11-16-save-load.md)이다. 커밋/원격 승인은 없다.
