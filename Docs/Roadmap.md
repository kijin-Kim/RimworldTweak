# 개발 작업과 완료 기준

## 현재 착수 범위

작업4 건설, 작업5 재배/조리, 작업6 개인 작업 우선순위·끄기·자동 배정, 작업7 파일 저장/복원까지만 현재 범위로 정했다. [3세션 실행 계획](Plans/SettlementFiveFeatures.md)의 G0~G5와 [공통 계약](Contracts/SettlementFiveFeatures.md)을 사용한다. 작업8 전체 자급 검증과 작업9~12는 장기 계획으로 남기며 현재 인계/완료 기준에 포함하지 않는다. 다섯 기능의 실제 연결·중단·복원 회귀는 이번 범위 안에서 수행한다. 이번 요청은 문서 작성뿐이며 구현 착수 승인은 아니다.


아래는 순서와 범위다. 실제 진행 상태는 [Status.md](Status.md)가 단일 기준이다. 일정은 미정이며 작업 ID는 이후 기록에서도 유지한다.

## 작업 0: 프로젝트와 검증 기반

| ID | 기능 결과물 | 완료 기준 |
|---|---|---|
| 0-A | 고정 버전의 Unity 프로젝트 | 버전·패키지 고정, 2D URP 설정 확인, 컴파일 오류 없음, 템플릿 Play Mode 진입·종료와 화면 확인 |
| 0-B | 독립적인 초기 상태 | 같은 시나리오 재현, 월드 간 상태 독립, 잘못된 초기 데이터 거부 |
| 0-C | 시뮬레이션과 화면 연결 | 작은 맵·정착민·자원 표시가 데이터와 일치 |
| 0-D | Tick과 재시작 | 지정 Tick 진행, 초기화 후 중복 개체·구독·상태 잔류 없음 |
| 0-E | 반복 가능한 검사 | CLI로 Edit/Play Mode 검사와 결과·로그 확보. E1 기반을 B와 병렬 준비하고 E2 통합으로 완료. 0개 실행은 실패 |
| 0-F | Windows 실행 파일 | CLI 빌드·실행으로 초기화·상태·재시작·종료 검사. 렌더 증거와 수동 확인은 별도 기록 |

작업 0의 시험 맵은 약 8×8이다. 정착민 이동·식사 경쟁 시험은 작업 1·2로 남긴다. 사용자 지시에 따라 작업 0의 Windows 데모를 구현하고 자동 검증했다. 기존 데모의 화면·조작은 사용자 정상 확인 보고를 받았으며 현재 증거는 Status와 데모 검증 기록을 따른다. 작업 1 이후는 후속 지시에 따른다.

## 병렬 실행 순서

[병렬 작업 계획](ParallelWork.md)을 따른다. 공통 계약 확정 후 B+E1 작성, B 통과 후 C+D+E2 검사 작성, 단일 통합 검증, F 실행 순서다. 동일 프로젝트 Unity 실행은 직렬이다. 기존 작업 번호는 유지하며 완료 의존성과 코드 작성 병렬성을 구분한다.

E1은 실제 B 검사를 실행해 결과 판정까지 확인해야 완료다. E2는 실제 Play Mode 통합 검증을 포함한다. B 초기 독립성은 입력 변경 격리로 검사하며, 실제 Tick 이후 비간섭은 D에서 검사한다. 장면·재시작 표시 통합 전에는 C/D 전체를 완료 처리하지 않는다. 시각 기준을 생략하지 않고 증거가 없으면 미검증으로 남긴다.

## 중간 확인 지점

- 작업 2: 생활이 막히지 않는 시험 장면.
- 작업 4: 채집 자재로 거처를 만들고 사용.
- 작업 6: 화면에서 부족 원인을 찾아 노동 배분으로 해결.
- 작업 8: 저장 가능한 자급 정착지.

각 작업은 관련 [검증 계획](Testing.md)을 실제 실행한 후 완료 처리한다. 자동 검증과 화면 검증 중 하나만 끝났으면 나머지를 미검증으로 남긴다.

## 이후 단계

다음 번호는 추적용 확장이다. 세션 배정과 병렬 순서는 [전체 세션 계획](Plans/MultiSessionRoadmap.md)을 따른다. 기본 방향은 GameDesign을 유지하며 후반부 수치/세부 규칙은 착수 전에 확정한다. 현재 구현 범위가 아니다.

| ID | 기능 | 완료·통합 선행 | 완료 기준 |
|---|---|---|---|
| 9 | 기본 습격·치료·복구 | 8 | 고정 습격 진행·피해와 실제 치료 연결, 실패 후 정착지 운영 복귀 |
| 10 | 정보전/Fog of War | 9 | 미탐색/기억/현재 관측, 차단과 갱신, 화면·명령·적 AI 정보 누출 방지 |
| 11 | 준비형 전투·습격 평가 | 10 | 정면/우회/장거리 상황에 준비·대응 효과 확인, 완전작전 정확한 판정과 실패 복구 |
| 12 | 짧은 데모 | 11 | 운영→정찰→준비→교전→결과/복구의 실제 빌드 흐름 |

선행은 전체 완료·통합 기준이다. 독립 규칙·전용 UI·시험용 입력의 작성은 공통 계약 고정 후 앞당길 수 있다. 작업5는 재배5a와 조리5b로 나누고, 작업7의 기존 상태 저장 형식 및 작업8의 시험 설계는 준비를 앞당긴다. 실제 연결 검증을 준비 작업으로 대체하지 않는다.

작업2는 식사·수면·이동 연계 및 자동 검증 완료, 사용자 정상 확인 보고를 받았다. 기능별 완료 상태는 [Status](Status.md), 실제 증거는 [생활 검증](Verification/2026-11-15-living.md)을 따른다. 작업3의 구현과 검증 상태는 Status 및 작업3 검증 기록을 따른다.

반영된 변경은 [R 소집·상호작용 단일 점유 계획](Plans/Interaction-Occupancy-Draft.md)이다. 명령 취소와 점유 해제, 바닥 수면자의 빈 침대 재선택을 포함하며 구현·자동검증했다.

현재R/점유규칙과최종87개검사·Windows결과는 [점유검증](Verification/2026-11-15-occupancy.md)을따른다. 이전검증수치는당시버전의기록이다.

작업3은 3-A 공통 행동·운반 기반 → 3-B 저장 구역/3-C 채집 → 3-D 운반 → 3-E 생활·실패 복구 → 3-F 조작·표시 → 3-G 통합 검증 순으로 계획했다. 사용자가 승인해 구현했으며 자동 검사와 사용자 확인 상태를 구분한다. 상세 완료 기준은 작업3 계획을 따른다.

## 작업3 이후 UI 개선

사용자가 물류 기능 정상 작동을 확인한 뒤 검증 가독성 개선을 승인했다. [UI 계약](Contracts/ReadableSettlementUI.md)의 UI-1 정착민 식별 → UI-2 오브젝트 식별 → UI-3 저장 바닥/경계 → UI-4 하단 정보 → UI-5 선택 연결 → UI-6 회귀/렌더 순서로 구현했다. [검증 기록](Verification/2026-11-15-readable-ui.md)과 [사용자 확인](ReadableUiDemo.md)을 구분하며 다음 생산/건설 작업의 완료로 취급하지 않는다.

## 세션별 실행 계획

[다중 세션 로드맵](Plans/MultiSessionRoadmap.md)의 P0~P7에 담당 기능·선행·인계 단위·파일 소유권·G4~G12 완료 기준을 정리했다. 기존 작업0~3은 완료 기반이며 재구현하지 않는다. 이번 갱신은 문서만이며 구현/커밋/worktree 전환 승인이 아니다.

## 현재 건설·재배 구현 상태

현재 범위 G1 건설/G2 재배는 통합 자동 검증을 마쳤고 사람 조작 확인은 대기다. [검증 결과](Verification/2026-11-15-construction-farming.md)를 따른다. 조리 G3/작업계획 G4/저장 G5는 아직 착수하지 않았다. 장기 로드맵의 전체 자급 목표와 혼동하지 않는다.
