# 전체 로드맵의 다중 세션 작업 계획

> 현재 실행 범위는 건설·재배·조리·작업계획·저장으로 한정한다. 실제 배정은 [3세션 지시서/계획](SettlementFiveFeatures.md)을 우선한다. 본 문서의 전체 역할과 후반부 묶음은 장기 참고이며 추가 세션/구현 범위가 아니다.

2026-11-15. 기준 커밋 `d0069af`. 문서 작성만 요청된 상태다. 아래 배정은 계획이며 세션·브랜치·worktree를 생성하거나 구현·커밋을 시작한 것이 아니다. 현재 구현 결과는 [Status](../Status.md), 기능 규칙은 [Settlement](../Settlement.md)와 [GameDesign](../GameDesign.md)을 따른다.

## 한눈에 보는 운영 방식

기능을 만드는 일은 동시에 하고, 합쳐서 확인하는 일은 순서대로 한다. 통합 세션 S0을 유지하고 기능 담당은 동시에 두 세션부터 운영한다. 아래 세션 이름은 장기 담당 역할이며 모두 동시에 실행하는 세션 수가 아니다. 품질 담당도 별도 작업 슬롯을 차지하며 담당이 없는 기간에는 S0이 통합 검증을 맡는다.

기존 폴더는 통합용으로 유지하고 기능별 worktree를 추가하는 방식을 권장한다. 서로 다른 폴더에서도 공통 규칙과 파일 소유권은 지킨다. worktree 전환은 아직 실행·확정하지 않았으며 착수 시 작업 공간과 승인 범위를 확인한다. 공유 폴더 유지 시 동일 소유권을 적용하되 검사 동안 모든 제품 파일 작성을 멈추므로 병렬 효율은 낮아진다. 폴더 격리는 변경 혼입을 줄이지만 별도 Library·초기 import·디스크 비용과 통합 비용이 든다. 처리량 개선 수치는 측정 전 약속하지 않는다.

공통 규칙과 미정 접점의 기준은 [기능 통합 공통 계약](../Contracts/ParallelFeatureIntegration.md)이다.

## 담당 세션

각 기능 담당은 전용 시뮬레이션 규칙, 최소 조작/표시, 해당 기능의 단위·통합 검사와 인계 문서를 함께 맡는다. UI·검사를 마지막까지 미루지 않는다.

| 세션 | 담당 기능 | 인계 결과 | 직접 맡지 않는 일 |
|---|---|---|---|
| S0 통합 | 계약·공유 코드·기능 연결·검사 실행·전체 문서 | 검증된 통합 상태, 현재 기준 커밋/입력 해시 | 기능별 구현 전체를 대신 작성하지 않음 |
| S-BUILD | 작업4 건설·철거 | 지정→자재 반입→완공→시설 사용 | 공통 운반/취소 경로 직접 변경 |
| S-FARM | 작업5a 재배 | 파종→성장→수확→재파종, 중지 설정 | 생활 임계값/하루 길이 임의 변경 |
| S-COOK | 작업5b 조리 | 재료 반입→조리→출력, 목표량 유지 | 건설 담당의 조리대 생성 로직 |
| S-JOBS | 작업6 노동 배분·진단 | 개인 우선순위/끄기·실패 이유·재개 표시 | 공통 작업 실행 루프 독자 교체 |
| S-SAVE | 작업7 저장·복원 | 버전 있는 저장 데이터·복원 검증·실패 처리 | 기능 소유자의 상태 필드 직접 추가 |
| S-QA | 작업8 및 최종 통합 시험 | 자급/중단/복원 시나리오와 관측·회귀 검사 | 제품 코드 수정·독자 Unity 실행 |
| S-COMBAT | 작업9a 기본 전투·습격 진행 | 소집 명령·사격/피해·기본 적/승패 | 정보전 판정과 완전작전 기준 임의 변경 |
| S-RECOVERY | 작업9b 부상·치료·복구 | 부상자 대응→치료→운영 복귀·시설 복구 | 피해 발생 원인/시점을 별도 판정 |
| S-VISION | 작업10 정보전 | 관측 판정·기억·Fog 표시·조회 제한 | 실제 월드 상태를 표시용 기억으로 대체 |
| S-TACTICS | 작업11a 준비형 전투 | 사선·예고·전술 명령과 준비 효과 검증 | 기본 피해/관측 루프 독자 교체 |
| S-RAIDS | 작업11b 습격 유형·평가 | 정면/우회/장거리 시나리오·완전작전 집계 | 플레이어 배치를 읽어 습격을 사후 변경 |
| S-DEMO | 작업12 짧은 데모 | 안내·시나리오 흐름·결과 설명·배포 체크 | 새 게임 규칙이나 콘텐츠 범위 확대 |

작업9~12는 기존 '기본 습격·치료·복구 → 정보전 → 준비형 전투 → 짧은 데모'에 추적 ID를 붙인 것이다. 상세 무기·치료 수치와 전술 기능은 미확정이며 새 구현 승인을 뜻하지 않는다.

## 병렬 작업 순서

'준비'는 규칙·표·검사 사례 작성이다. '기능 작성'은 계약과 해당 묶음의 구현 승인을 받은 뒤만 가능하다. 시험용 입력은 분리된 테스트 시나리오이며 실제 연결 완료의 증거로 사용하지 않는다.

| 묶음 | 선행 조건 | 동시에 맡을 두 기능 세션 | S0의 작업과 합치는 순서 | 묶음 완료 기준 |
|---|---|---|---|---|
| P0 착수 준비 | 현재 기준 상태 유지 | 기능 담당 배정 전 | C0~C6 계약의 미정 항목 확정, 파일 목록·접점·검사 큐 준비 | 후보 상태 조회·자재 반입·취소·시설/생산 읽기 접점을 명세하고 실제 연결용 최소 기반을 검증. 모든 후속 규칙을 한꺼번에 구현하지 않음 |
| P1 건설·재배 | P0 통과 | S-BUILD + S-FARM | 건설 지정/자재/완공 순으로 반영하고 재배 파종/성장/수확을 연결. 저장/자급 검사의 항목표는 S0이 준비 | G4 건설 통과 후 G5a 재배 통합 통과. 건설된 조리대가 존재하고 수확물이 기존 운반으로 저장됨 |
| P2 조리·노동 | G4/G5a 및 작업 후보/생산 계약 | S-COOK + S-JOBS | 조리의 개별 단계와 우선순위 정책을 작성 → 조리 연결 → 실제 모든 작업을 배분 정책에 연결 | G5 식량 재생산과 G6 노동 배분 통과 |
| P3 저장·자급 | G6, 저장 대상 목록 고정 | S-SAVE + S-QA | 기존 상태 저장/복원 → 진행 중 생산 복원 → 자급 시험에 저장/복원 포함 | G7 복원과 G8 자급 정착지 통과 |
| P4 기본 전투·복구 | G8, 전투/부상/팀/관측 접점 상세 계약 | S-COMBAT + S-RECOVERY | 전투 진행/피해 이벤트 → 실제 부상 연결 → 치료/시설 복구 | G9 습격 실패 후에도 치료·복구하고 운영 지속 |
| P5 정보전·습격 준비 | G9, 시야 차단/관측 소비 계약 | S-VISION + S-RAIDS | 관측 판정 → 화면/선택/명령/적 AI의 정보 제한. 습격 담당은 고정 구성 시나리오/평가 입력 준비 | G10 정보 누출 검사 통과. 습격 유형은 아직 전술 검증 완료 아님 |
| P6 준비형 전투 | G10, 무기·예고·전술 범위 상세 계약 | S-TACTICS + S-RAIDS | 전술 한 단위씩 연결 → 각 습격 유형 연결 → 완전작전/실패 평가 | G11 준비의 효과와 실패 후 운영 복구 검증 |
| P7 짧은 데모 | G11, 데모 시작/끝·콘텐츠 범위 고정 | S-DEMO + S-QA | 운영→정보→준비→습격→결과 안내 연결, 최종 저장/초기화/빌드 확인 | G12 다른 세션의 시험용 데이터 없이 한 흐름으로 플레이 가능 |

P1 진행 중 조리의 규칙·시험 입력을 미리 정리할 수 있고, P2 진행 중 저장 형식과 관측 지표를 미리 정리할 수 있다. 별도 세션으로 수행하려면 기존 기능 세션의 인계 뒤 슬롯을 넘기거나 병렬 수를 재검토한다. 준비가 가능하다는 이유로 모든 세션을 동시에 열지 않는다. 저장의 기존 상태 왕복 검사는 전용 계약이 먼저 고정되면 앞당길 수 있지만, 최종 G7은 노동·생산 상태가 연결된 뒤에만 통과한다.

각 묶음을 통째로 기다리지 않는다. 아래 결과 단위 하나가 준비되면 다른 기능이 작성 중이어도 통합 큐에 넣는다. 다음 단계가 소비할 계약이 바뀌면 영향 있는 기능만 멈춰 합의한다. 의존하지 않는 기능 작성은 계속한다.

후반부 착수 전 확정할 항목: 피해·부상·사망/납치의 최소 모델, 무기 사거리/공격 간격/예고 길이, 치료 재료·회복 규칙, 시야 범위·차단·관측 갱신 시점, 보호 목표의 판정, 전술 명령 중 첫 구현 범위, 데모 종료 조건. 위 완료 기준은 검증 질문을 고정한 것이며 숫자나 미정 전술을 승인한 것이 아니다. 기분·관계·연구·전력·날씨·센서 교란 등 기존 제외 범위는 추가하지 않는다.

## 인계·통합·검증 절차

1. S0이 작업 카드에 기준 커밋, 계약 버전, 허용 파일, 결과 단위, 선행, 검사 사례, 제외 범위를 기록한다. 기능 세션은 실제 파일/계약이 카드와 일치하는지 읽고 시작한다.
2. 기능 세션은 전용 코드·UI·검사와 연결 요청을 작성한다. 공유 파일을 수정해야 하면 파일/이유/예상 영향/기대 결과를 S0에게 전달한다. 다른 세션 파일을 대신 고치지 않는다.
3. 인계 시 상태를 '작성 완료, 미검증' 또는 '개별 검사 통과, 통합 미검증'처럼 구분한다. S0은 기준 차이와 계약 변경을 먼저 검토한다. 오래된 계약이면 범위를 다시 맞춘다.
4. S0이 해당 검증 대상 폴더 쓰기를 동결하고 Unity를 직렬 실행한다. 처음에는 worktree 간 검사도 단일 큐다. 검증 중 다른 분리 폴더의 독립 작성은 가능하다. 공유 폴더라면 모든 제품 입력을 동결한다.
5. 개별 검사 후 통합 폴더에 한 결과 단위씩 반영한다. 기능 브랜치의 검증된 커밋 전달은 커밋 승인이 있을 때만 사용한다. 미승인 시 변경 목록/패치로 검토하며 임의 커밋·merge·cherry-pick하지 않는다. 충돌 해결은 S0, 기능 의미 확인은 해당 소유자다.
6. 통합 상태에서 관련 EditMode/PlayMode와 기존 회귀를 실행한다. G 경계에서는 전체 검사와 Windows 빌드·Player·렌더 확인을 수행한다. 임시 시험용 조리대/자재/피해 입력을 실제 연결로 교체해 확인한다.
7. 성공한 기준과 새 계약 버전을 S0이 게시한다. 다음 기능은 그 기준을 받아 진행한다. 실패하면 실패 단위의 통합을 보류하고 해당 담당이 수정한다. 다른 미완성 파일까지 함께 저장하지 않는다.
8. 코드·검사·문서가 준비되면 기능별 커밋을 제안한다. 커밋 실행은 별도 승인 범위를 따른다. 외부 게시·원격 연결·push는 하지 않는다.

에이전트 실행 가능: 파일/CLI, Unity EditMode·PlayMode, Windows 빌드·Player, 실제 PNG 정적 검토, 소스 해시/입력 동결 검사. 사용자 확인: 실제 조작감·읽기 쉬움·준비형 전투의 납득 가능성. 사용자 검토가 남으면 자동검증 완료와 사용자 확인 대기를 구분한다. 현재 계획 작성에서는 Unity 실행을 하지 않는다.

공통 회귀: 이동/배속/Reset, 식사·수면, R 소집/해제, 단일 점유/오래된 ActionId, 취소 낙하, 바닥 수면 빈 침대 재선택, 물자 보존/저장 필터, 정지 중 즉시 적용, 저장 구역 도구 한 번 사용. 새 기능의 명령도 정지 중 상태와 UI를 갱신하며 자동 진행을 몰래 실행하지 않아야 한다.

## 세션 재개용 작업 카드

각 기능 계획 문서에 다음 양식을 사용한다. 전체 Status는 S0만, 기능 문서는 해당 소유자만 갱신한다. 서로 다른 세션의 대화 내용 전달을 전제로 하지 않는다.

```text
담당 세션 / 결과 단위:
기준 커밋 / 작업 폴더 / 계약 버전:
목표와 제외 범위:
수정 허용 파일 / 공유 파일 연결 요청:
선행 조건 / 완료 기준:
현재 상태: 계획 / 작성 중 / 인계 대기 / 개별 검증 / 통합 검증 / 사용자 확인
완료한 내용 / 다음 행동:
검사 명령·입력 해시·실행 폴더·결과:
미검증·실패·막힌 이유:
계약 변경 요청과 영향받는 세션:
커밋 승인 범위 / 인계 커밋 또는 변경 파일 목록:
```

실행 전 남은 결정은 작업 공간(권장: 통합 폴더 유지+기능별worktree)과 첫 묶음의 실제 구현/커밋 허용 범위다. 본 문서 작성 요청은 이 실행을 승인한 것으로 해석하지 않는다. 지금은 계획·소유권·완료 기준만 정리하며 모든 신규 기능은 미구현이다.
