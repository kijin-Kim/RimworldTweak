# 작업9: 기본 습격·치료·복구 구현 계획

2026-11-18 작성, 후속 사용자 승인에 따라 구현·자동 검증 완료. 아래 최소 규칙과 9-A~G 완료 기준을 구현 기준으로 사용한다. 수치는 기능 검증용 시험값이다. 실제 코드와 검증 상태는 [Status](../Status.md)를 따른다.

기준 제품은 `37b457a`. 기존 생활·생산·저장과 사용자 정상 확인을 유지한다. 이번 목표는 **습격 예고 → 직접 전투 → 실제 피해 → 치료·시설 수리 → 자동 작업 복귀**를 한 실행 파일에서 확인하는 것이다. 장기 자급·난이도·적정 자원량은 완료 조건이 아니다.

## 1. 핵심 설계

### 1.1 최소 범위와 선택 이유

| 선택 | 추천안 | 대안과 감수할 제한 |
|---|---|---|
| 교전 | 정착민의 단일 사격, 적의 단일 근접 공격 | 양쪽 근접만 쓰면 단순하지만 사선·위치 선정과 후속 전술 연결이 약하다. 무기 교체·투사체·명중 확률은 제외한다 |
| 인명 피해 | 체력 0이면 전투 불능, 현장 치료로 회복 | 사망·출혈·신체 부위·납치는 생활/실패 처리를 크게 늘린다. 이번에는 치명상과 영구 손실을 표현하지 못한다 |
| 치료 | 의약품 1개를 실제 운반해 1회 치료 | 무료 자동 재생은 운반·소비·담당 교체를 검증하지 못한다. 의약품은 시험 초기 물자로만 제공하며 생산·구매는 제외한다 |
| 시설 피해 | 내구도 0이면 고장, 수리 후 재사용 | 완전 파괴·잔해·재건은 개체 제거와 물자 반환 분기가 늘어난다. 이번에는 고장 시설의 ID·내부 물자를 보존한다 |
| 회복 작업 | 치료를 새 작업 종류로 추가하고 수리는 기존 건설에 포함 | 독립 회복 전용 스케줄러를 만들지 않는다. 작업 설정 UI·후보 선택·저장 포맷은 확장해야 한다 |
| 시험 환경 | 작은 전용 전투 시나리오, 고정 적 구성, 수동 습격 시작 | 큰 맵·랜덤 습격·시간 기반 반복 출현은 뒤로 미룬다. 기존 생활 데모는 그대로 선택 가능하게 유지한다 |

기존 R 소집/해제, 정지 중 명령 즉시 반영, 단일 점유, 운반 중 취소 시 한 번 낙하, 후보 월드 검증 후 저장 복원 규칙은 유지한다. 소집이 자동 치료·자동 수리보다 우선하지만 전투 불능은 소집 명령 자체를 거부한다.

### 1.2 이번에 포함하지 않을 것

Fog of War, 엄폐 확률, 제압, 탄약·장비 인벤토리, 여러 무기, 공격 애니메이션에 의존하는 판정, 사망·시체·포로·납치, 환자 운반·의료 침대, 출혈·감염, 의약품 생산, 완전 파괴·자동 재건, 자동 반복 습격은 제외한다. 공격 표적·피격·전투 불능·고장·보류 이유를 구별할 최소 표시는 포함한다.

전체 기획의 완전작전 기준은 유지하지만 작업9는 습격 결과와 피해 기록만 제공한다. 사망/납치가 없는 단순 모델을 전체 완전작전 평가 기능의 완료로 보고하지 않는다. 관측은 양측 모두 전부 공개인 시험 조건이며 작업10에서 같은 표적 조회 경로에 관측 제한을 연결한다.

### 1.3 기존 코드에서 확인한 연결 지점

| 현재 코드 | 확인한 역할 | 이번 계획의 연결 방향 |
|---|---|---|
| `WorldState.Step` | 생활·생산·이동을 정해진 Tick 순서로 진행 | 이동 뒤 전투 판정, 피해 정리, 회복 완료와 습격 종료 판정 순서를 추가 |
| `WorldState.SetDrafted`, `EndLife` | 생활/작업 취소, 점유 해제, 이동 큐 정리, ActionId 무효화 | 소집·전투 불능·시설 고장도 같은 정리 경로를 사용. 별도 점유 해제 구현을 복제하지 않음 |
| `WorldState.Features`, `WorkPolicy` | 후보 비교·시작 유효성 검사·개인 정책 | 치료 후보와 수리 단계를 연결. 현재 우선순위 배열은 5칸 고정이라 enum 추가만으로 끝나지 않음 |
| `BuildingState`, `BedState`, 조리 상태 | 건물과 기능별 상태 연결. 침대는 건물 없이 초기 배치될 수도 있음 | 건물 내구도와 기능 사용 가능 여부를 연결. 초기 침대도 동일 피해 조회 대상에 등록하고 건설 침대의 중복 등록을 금지 |
| `WorldState.Save`, `SaveValidation` | 행동·점유·물자 장부 복원, 현재 버전1만 허용 | 전투·회복 데이터와 참조/장부 검증을 함께 확장 |
| `SimulationRunner`, `SettlementView` | 명령 전달과 읽기 표시 | 새 명령·선택 정보·시험 시나리오 선택 추가. 화면에서 HP나 결과를 직접 변경하지 않음 |

표의 현재 코드는 작업9 착수 직전 기준이다. 실제 결과는 검증 문서에서 확인한다.

## 2. 최소 규칙과 동작 흐름

### 2.1 습격 시작과 종료

1. 전투 시험 시나리오는 정착민 3명, 의약품과 수리 목재, 정상 조리대 1개를 제공한다. 기본안은 16×12 맵이며 큰 맵 성능 보장을 뜻하지 않는다. 실제 건설한 조리대를 보호 대상으로 쓰는 연결 검사도 별도로 둔다.
2. 플레이어가 정상 조리대를 보호 대상으로 지정하고 ‘시험 습격 시작’을 누른다. 보호 대상·예고 시간·적 수·진입 칸·시간 제한은 이때 고정한다. 습격 중 보호 대상 철거는 거부한다.
3. 예고 카운트다운은 Tick으로만 감소하고 진입 위치를 표시한다. 정지 중 시작은 설정만 바꾸며 적을 생성하거나 시간을 진행하지 않는다.
4. 예고 종료 때 정해진 적 2명을 한 번 생성한다. 진입 칸의 건설·새 차단은 예고/교전/철수 동안 거부한다. Pawn 겹침은 기존 규칙대로 허용하며 다른 곳으로 몰래 생성하지 않는다.
5. 적은 경로로 도달 가능한 행동 가능 정착민 중 경로 길이→ID 순으로 목표를 고른다. 없으면 보호 조리대로 간다. 경로가 없으면 접근 불가를 표시하고 통행 변경 또는 10Tick마다 재평가한다. 벽을 부수는 우회 AI는 이번에 넣지 않는다.
6. 적이 모두 무력화되면 방어 성공. 보호 조리대가 고장 나면 방어 실패 후 적 철수. 1200Tick 교전 제한에 도달하면 시간 종료로 적 철수. 막힌 경로를 영원히 기다리지 않는다.
7. 철수 중 적은 공격하지 않고 지정 출구로 이동한다. 출구 도착 시 제거하며 100Tick 동안 탈출하지 못하면 ‘철수 시간 종료’로 제거한다. 순간 소멸을 정상 탈출처럼 표시하지 않는다.
8. 아군 전원이 전투 불능이면 복구 가능한 사람이 없으므로 패배 화면에서 시간을 멈추고 불러오기/초기화를 제공한다. 전원 전투 불능과 적 전멸이 같은 Tick이면 아군 패배 판정을 우선한다.
9. 결과는 신규 피해 인원, 전투 불능 인원, 시설 피해량, 보호 목표 상태, 종료 이유를 보존한다. 체력이 회복돼도 해당 습격의 부상 기록은 지우지 않는다.

예정 상태는 `Idle → Warning → Active → Retreating(필요 시) → Resolved`다. 전원 전투 불능은 즉시 패배 결과와 시간 정지로 간다. 결과를 확인하고 보호 시설 정상·아군 전원 회복·적 잔류 없음 조건을 만족하면 수동으로 다음 시험 습격을 시작할 수 있다. 자동 반복 습격은 없다.

### 2.2 플레이어 전투와 공격 판정

- R로 소집한 행동 가능 정착민만 공격 명령을 받는다. ‘공격’ 버튼으로 표적 선택 모드를 켜고 적을 클릭한다. 기존 바닥 이동 입력은 유지한다. 이동 명령을 내리면 공격을 취소하고, 공격 명령은 현재 이동을 중단한다.
- 공격 명령은 그 자리에서 지정 적을 반복 사격한다. 자동 추격·자동 표적 교체는 하지 않는다. 범위 밖·사선 차단이면 이유를 표시하며 조건이 풀리면 다음 Tick부터 재개한다.
- 사거리는 맨해튼 거리 4칸. 사선은 타일 중심 간 supercover 선분이 지나가는 중간 칸을 검사하고 모서리에 닿는 차단 칸도 차단한다. 일반 장애물·정상 벽·정상 문은 사선을 막고 침대·조리대·Pawn은 막지 않는다. 통행 가능한 문도 이번 고정 규칙에서는 사선을 막는다. 이는 향후 문 열림 상태 구현과 별개다.
- 사격은 준비 10Tick 뒤 피해 25, 이후 대기 10Tick. 적 근접은 상하좌우 인접에서 준비 10Tick 뒤 피해 10, 이후 대기 10Tick이다. 범위/사선 이탈 또는 명령 취소는 준비를 0으로 만들지만 이미 발생한 공격의 대기 시간은 유지한다. 명령 재입력으로 연사 속도를 높일 수 없다.
- 준비 완료 직전에 표적 생존·팀·거리·사선을 다시 검사한다. 조건이 맞을 때만 정확히 한 번 피해를 적용한다. 투사체 비행·확률·치명타·아군 오사는 없다.
- 적 근접 이동도 기존 5Tick/칸 기준을 사용한다. 적 AI는 별도 상태로 두고 정착민의 식사·작업 선택 루프에 섞지 않는다. 경로 검색의 4방향 규칙과 통행 정보를 공유한다.
- 전투 판정 시작 시 유효한 공격들을 수집한 뒤 목표별 피해를 합산 적용한다. 같은 Tick에 서로 공격 준비를 마쳤다면 양쪽 피해가 모두 발생한다. ID 순서 때문에 한쪽 공격만 사라지지 않게 한다.
- 정착민 HP는 100, 적 HP는 50. 적 HP 0은 무력화·전장 제거이며 시체/전리품은 생성하지 않는다. 과거 공격은 대상 ID가 제거되면 취소하고 다음 습격에 재사용하지 않는다.

### 2.3 부상과 현장 치료

- 정착민 HP 1~99는 부상 상태지만 이동·기존 작업 능력은 유지한다. HP 0이면 전투 불능으로 이동·공격·생활·노동을 중단하고 기존 점유와 운반물을 한 번 정리한다. 소집도 해제한다.
- 전투 불능 중에는 욕구 감소를 동결한다. 사망·급식·환자 운반이 없는 이번 단계에서 회복 불가능한 기아 상태를 만들지 않기 위한 명시적 임시 규칙이다. HP가 회복되면 욕구 진행도 재개한다.
- 새 `Medicine` 자원과 `Care` 작업 종류를 제안한다. 의약품은 저장 필터·운반·장부에 포함하지만 먹거나 조리할 수 없다. Care 기본 우선순위는 1, 기존 다섯 작업의 설정은 유지한다.
- 비소집·행동 가능 치료자가 대상 1명을 점유하고 의약품 1개를 가져와 상하좌우 인접 칸에서 치료한다. 스스로 치료하는 경우도 허용하며 같은 운반·소비 규칙을 쓴다. 전투 불능자는 자가 치료할 수 없다.
- 치료 대상은 비소집 부상자만 허용한다. 같은 Care 우선순위 안에서는 전투 불능→현재 HP가 낮은 대상→경로 길이→ID 순으로 고른다. 다른 작업 종류와의 비교는 개인 우선순위를 먼저 따르고, 동일 우선순위에서는 긴급한 치료가 먼저 배정된다.
- 대상 확보가 성공하면 환자의 기존 일반 작업을 공통 취소 경로로 중단하고 그 자리에서 대기시킨다. 긴급 식사·수면 중인 행동 가능 환자는 새로 확보하지 않는다. 대기 중 긴급 생활이 필요해지거나 환자가 소집되면 치료를 취소하고 점유를 해제한다. 전투 불능자는 긴급 생활 판정을 받지 않는다.
- 환자 점유는 치료자 ID와 ActionId로 관리한다. 의약품 출발 스택 점유와 환자 점유가 동시에 존재할 수 있으며 시작 실패 시 확보한 점유를 모두 되돌린다. 자가 치료는 자기 점유를 무효 대상이나 교착으로 오판하지 않게 검사한다.
- 치료 40Tick 완료 시 보유 의약품 1개 소비와 HP +40을 한 번 적용하고 최대100으로 제한한다. HP 0→40이면 다음 Tick부터 행동 가능하다. 남은 부상은 새 1회 치료 후보로 처리한다.
- 치료 중 치료자/환자 피격, 소집, 작업 끄기, 환자 이동·무효화, 접근 차단으로 취소되면 치료 진행은 0으로 초기화하고 미소비 의약품은 한 번 내려놓는다. 부분 치료 효과는 없다. 완료 직전 취소는 소비·회복0이어야 한다.
- 치료자 자신도 긴급 식사·수면과 소집이 우선한다. 행동 가능한 환자는 예약이 풀리면 기존 개인 설정에 따라 다음 Tick에 작업을 다시 고른다. 이전 작업을 강제로 재개하지 않는다.

### 2.4 시설 손상·고장·수리

- 완공된 벽·문·침대·조리대와 초기 배치 침대에 내구도100을 부여한다. 설계도·작물·저장 구역·바닥 물자는 이번 공격 대상에서 제외한다.
- 내구도1~99에서는 기능을 유지한다. 0이면 고장 표시를 하고 침대 사용·조리·사선 차단을 중지한다. 벽과 조리대의 이동 차단도 해제한다. 조리대는 기존 코드에서도 설치 시 통행을 막으므로 수리로 복원할 때 벽과 동일한 끼임 방지 검사를 쓴다. 시설 ID와 배치 칸은 유지하여 같은 칸 재건설을 막는다.
- 고장 난 침대의 사용자를 해제해 다른 침대/바닥 수면을 재선택하게 한다. 조리대는 작업자 점유를 정리하되 내부 투입물·진행·기존 출력은 보존하고 새 조리를 중지한다. 시설 고장은 철거 함수를 호출하지 않으며 자재를 반환하지 않는다.
- 플레이어가 ‘수리 지정’을 켠 시설만 건설 작업 후보로 제공한다. 기능 단계는 목재 반입→수리이며 시설별로 한 작업자가 담당한다. 철거 지정은 수리를 취소한 뒤 기존 철거 흐름으로 전환한다.
- 수리 1회는 목재2개를 시설 수리용 보관량으로 옮긴 뒤 40Tick 진행하여 내구도 +40. 최대100으로 제한하고 아직 손상됐으면 다음 회차를 제공한다. 부분 손상에도 같은 시험 비용을 쓰며 비용 최적화는 하지 않는다.
- 작업자 소집·욕구 개입·교체는 시설의 반입 목재와 진행을 보존한다. 추가 피격도 진행을 초기화하지 않는다. 수리 지정 해제 또는 철거 전환은 미소비 수리 목재를 한 번 반환하고 진행을 초기화한다.
- 내구도0인 벽을 수리해 다시 통행 차단하기 전 해당 칸의 Pawn·진입 예정 이동을 검사한다. 비워질 때까지 완료와 소비를 보류하고 ‘공간 비우기 대기’를 표시한다. 강제로 끼워 넣거나 순간 이동시키지 않는다.
- 수리 목재 소비는 별도 장부로 기록한다. 철거는 기존 건설 비용만 반환하며 이미 소비한 수리 목재를 반환하지 않는다. 수리용 미소비 목재와 조리대 내부 물자의 정리는 각각 한 번만 수행한다.
- 수리 후 침대는 사용 가능 상태, 조리대는 보존한 진행에서 다시 작업 가능 상태가 된다. 기존 초기 침대에는 건설 비용을 임의 부여하지 않으며 이번 단계에서 철거 대상을 새로 늘리지 않는다.

### 2.5 Tick 순서·저장·실패 처리

예정 순서: 기존 설정/통행 변경 → 기존 생활·생산 처리 → 회복 후보 선택/이동 준비 → 아군·적 이동 → 공격 준비/유효 공격 수집 → 피해 일괄 적용 및 전투 불능/시설 고장 정리 → 치료·수리 진행/완료 → 습격 종료 판정 → Tick 증가.

기존 생활·생산 완료는 전투보다 앞서므로 같은 Tick에 먼저 완료된 식사·생산을 피해 발생 뒤 소급 취소하지 않는다. 치료는 피격 시 취소 규칙에 따라 해당 Tick 완료보다 피해 처리가 우선이다. 보호 목표 고장과 전원 전투 불능은 그 순간 실패로 기록해 같은 Tick 수리가 실패를 지우지 못하게 한다. 기능 작업의 기존 도착 다음 Tick 진행 규칙을 회복에도 유지한다. 정확한 호출 분리는 구현 시 기존 회귀로 확인한다.

저장 대상: 팀·HP/내구도, 적 ID·위치·경로/칸 진행, 공격 표적·준비/대기, 습격 단계·남은 시간·고정 구성·보호 목표·피해 이력, 치료 양측 점유·의약품·진행, 수리 지정·반입·진행·소비 장부, Care 설정. 원시 참조 대신 ID를 저장한다. 저장/복원 뒤 다음 공격·치료·수리가 정확히 한 번 완료돼야 한다.

새 스키마/규칙 버전2와 새 계약 버전을 제안한다. 기존 v1 저장은 자동 변환하지 않고 명확한 오류와 현재 상태 보존을 보장한다. 저장 파일명도 `settlement-v2.json`으로 분리해 기존 v1 슬롯을 덮어쓰지 않는 안을 권장한다. 한 버전당 한 슬롯 원칙은 유지한다. 구버전 자동 이전이 필요해지면 별도 작업으로 다룬다.

전투 중 저장을 막는 임시 구현으로 완료 처리하지 않는다. 결과 확인창 시간 정지와 일반 저장 확인창의 기존 정지/취소 복귀 규칙이 충돌하지 않게 한다. Reset은 적·습격·피해·회복 상태와 신규 선택/버튼 리스너를 모두 초기화하고 해당 시나리오 시작 상태로 돌아간다.

### 3.2 코드 변경 경계

새 이름은 예정이다. `CombatState/CombatRules`, `RaidState`, `HealthState/RecoveryRules`, `WorldState.Combat/Recovery`, `CombatPanel/RecoveryPanel`에 상태·규칙·표시를 나누되 모든 실제 월드 변경은 WorldState가 소유한다. UI는 명령 전달과 읽기 조회만 수행한다.

### 4.2 사용자 직접 확인 (구현 후)

예정 실행 파일은 `E:/Dev/RimworldTweak/Builds/Windows/RimworldTweak.exe`다. 최종 빌드와 현재 조작 기준은 [검증 결과의 직접 확인](../Verification/2026-11-18-raid-recovery.md)을 따른다.

1. 전투 시험 시나리오를 선택하고 습격을 시작한다. 적 수·진입 위치·예고 시간이 보여야 한다.
2. 일시정지 후 R로 소집하고 공격 대상을 지정한다. 시간·체력은 멈춘 채 명령 표시만 바뀌어야 한다.
3. 재개해 사격·적 근접 공격을 확인한다. 사선 차단·범위 밖·전투 불능을 화면에서 구분할 수 있어야 한다.
4. 습격 종료 뒤 소집을 해제하고 치료 작업과 시설 수리를 지정한다. 실제 의약품·목재가 이동하고 회복 뒤 자동 작업을 다시 해야 한다.
5. 공격 또는 치료·수리 도중 저장/불러오기 후 재개한다. 진행과 물자가 맞고 피해·소비가 중복되지 않아야 한다.
6. 복구 후 두 번째 습격과 초기화를 확인한다. 이전 적·표적·점유·결과가 새 회차에 섞이지 않아야 한다.

답변 예: ‘모두 정상’, ‘치료자가 약을 가져와도 환자가 계속 이동함’. 자동 검사·정적 이미지와 실제 조작감/상황 이해도는 별도 증거다.

## 최종 요약

추천 범위는 단일 사격/근접 습격, HP와 전투 불능, 의약품 현장 치료, 시설 고장과 목재 수리다. 기존 작업·점유·시간·저장 구조에 연결하여 실제 피해 후 운영 복귀를 검증한다. 장기 자급과 수치 조정은 하지 않는다. [자동 검증과 직접 확인 순서](../Verification/2026-11-18-raid-recovery.md)에 결과를 기록했다.
