# 이전 기획 · 동쪽에서 온 두 명

조리대를 선택해 시작하는 아래 내용은 이전 기획과 시험 배치의 기록이다. 이후 구현 기준은 [디버그 전용 습격 기획](DebugRaid.md)을 따른다.

2026-11-19 기획안. 첫 판의 목표는 **정착민을 소집해 조리대를 지키고, 교전 후 누가 다쳤는지 확인하는 것**이다. 기존 전투 시험의 맵·사격·근접 공격·승패 판정을 사용한다. 이번에 보완할 부분은 보호 목표와 다음 조작 안내, 선택한 사수의 표적 표시, 화면 조작만으로 한 판을 끝낼 수 있는지에 대한 검증이다.

## 1. 첫 판은 어떻게 진행되는가

| 장면 | 플레이어의 행동 | 화면에서 읽어야 할 것 |
|---|---|---|
| 정지한 정착지 | 보존할 진행을 저장한 뒤 ‘전투 시험’으로 전환한다. 조리대 (5,5)를 선택해 ‘시험 습격’을 누른다. | 전환 버튼은 현재 월드가 새 시험으로 교체된다는 점을 누르기 전에 안내한다. 시작하면 보호할 조리대와 동쪽 진입 칸 두 곳을 구별할 수 있다. |
| 예고와 배치 | 1번 정착민을 선택해 R로 소집하고 (12,5)를 우클릭한다. 2번도 소집해 (12,6)으로 보낸다. 3번은 생활을 계속한다. 시간을 재개한다. | 예고는 100틱이다. 정지 중에는 이동 명령만 접수되고 재개하면 두 사람이 지정한 칸으로 간다. 예고가 끝나면 표시된 두 칸에 적이 한 명씩 나타난다. |
| 첫 교전 | 출현 직후 정지한다. 두 사수를 차례로 선택해 각각 ‘공격 지정’을 누르고 (15,5)에 출현한 같은 적을 클릭한 뒤 재개한다. | 사수를 선택하면 그 사수의 표적이 지도에서 강조된다. 준비를 마친 두 사수가 각각 피해 25를 입혀 체력 50인 첫 적을 쓰러뜨린다. |
| 두 번째 표적과 종료 | 첫 적이 쓰러지면 정지하고, 두 사수에게 각각 남은 적의 **현재 칸**을 클릭해 새 공격을 지정한다. 재개한 뒤 결과를 확인하고 R로 소집을 해제한다. | 마지막 적이 쓰러지면 방어 성공과 피해 집계가 표시된다. 부상자가 있어도 조리대를 지키고 적을 모두 제압하면 성공이다. 행동 가능한 정착민은 생활로 복귀한다. |
| 목표 상실 예시 | 별도 검사 배치에서 정착민에게 이르는 길을 막고 적에서 조리대로 가는 길은 열어 둔다. | 접근할 정착민이 없으므로 적이 조리대를 친다. 내구도 0에서 방어 실패, 적 철수, 이후 수리로 이어진다. 기본 맵에서 가만히 기다렸을 때는 정착민을 먼저 공격할 수 있다. |

**대표 승리의 기준 장면.** Windows 빌드에 포함된 시뮬레이션 DLL에 위 순서대로 소집·이동·공격 명령을 주었다. 좌표는 맵 왼쪽 아래가 (0,0)이다.

| 게임 시간 | 실제 관측 |
|---|---|
| 100틱 | 두 사수는 지정한 방어 칸에 도착했다. (15,5)와 (15,6)에 체력 50인 적이 한 명씩 출현했다. 이때 두 사수에게 첫 적을 지정했다. |
| 110틱 | 첫 적이 쓰러졌고 남은 적은 (13,6), 체력 50이었다. 이때 두 사수 모두에게 남은 적을 지정했다. |
| 130틱 | 방어 성공. 적 0명, 조리대 내구도 100, 정착민 체력은 번호순으로 100·90·100이었다. |

틱은 게임이 상태를 한 번 진행하는 단위로 1배속에서 0.1초다. 위 숫자는 같은 시점에 명령한 자동 비교의 기준이다. 사람이 더 늦게 정지하거나 다른 배치를 택한 판은 그 판에서 발생한 피해와 승패로 평가한다.

## 2. 반드시 충족할 요구사항

| 번호 | 규칙과 합격 기준 |
|---|---|
| R1 시작 | 16×12맵, 정착민 3명 체력 각 100, 조리대 내구도 100으로 시작한다. 전원 체력 100, 선택한 조리대 내구도 100·철거 미지정, 유효한 진입 칸 두 곳, 습격 대기 또는 이전 회차 종료일 때 수동 시작한다. 진입을 막는 지형·청사진·대기 중 차단 명령이 있으면 거부한다. 버튼과 명령은 같은 읽기 전용 판정을 사용하고, 거부 시 해소할 조건을 하나 이상 표시한다. 거부해도 단계·직전 결과·시간은 보존된다. |
| R2 예고와 출현 | 예고 동안 보호 조리대와 두 진입 칸을 따로 표시한다. 99틱까지 적 0명, 100번째 틱 종료 시 체력 50인 적 2명이며 이 틱의 피해는 0이다. 중복 시작 입력으로 적이 늘지 않는다. 보호 표시는 예고·교전·철수 동안 유지한다. |
| R3 명령과 식별 | 행동 가능하고 소집한 정착민만 교전 중 살아 있는 적을 지정한다. 새 표적은 기존 이동과 공격 준비를 취소하되 남은 공격 대기는 보존한다. 정지 중 틱·위치·체력 변화는 없다. 같은 표적 재지정은 준비도를 유지한다. 지정 모드에서 우클릭하면 모드만 닫히고 기존 공격은 유지된다. 사수를 바꾸면 해당 사수의 표적만 강조한다. 두 적이 겹친 칸은 맨 위에 그린 적을 선택한다. 그 적이 쓰러지면 강조를 지우고 남은 적을 다시 지정할 수 있다. |
| R4 정착민 사격 | 가로·세로 거리 합 4칸 이내, 사선이 열린 상태로 10틱 연속 준비하면 피해 25가 한 번 적용된다. 이후 10틱 대기 후 다시 준비한다. 거리 5칸이면 사격하지 않는다. 발사 직전 사선이 막히면 준비 0, 피해 0이다. 사거리가 부족하면 플레이어가 이동 후 다시 공격을 지정한다. 선택 정보에서 준비·대기·사거리 밖·사선 차단을 구별한다. |
| R5 적의 근접 공격 | 적은 쓰러지지 않은 정착민 중 인접 칸까지의 경로가 가장 짧은 상대에게 접근한다. 대상이 없으면 조리대로 간다. 5틱당 1칸 이동하고 상하좌우 인접한 상태에서 10틱 준비 후 피해 10, 이후 10틱 대기한다. 경로가 없으면 통행 변경 또는 10틱 후 재탐색한다. 아군 체력 0은 전투 불능이며 추가 명령과 적의 표적 선택에서 제외된다. |
| R6 종료와 복귀 | 매 틱 피해를 모두 반영하고 **전원 전투 불능 → 보호 목표 고장 → 적 전멸 → 교전 1200틱 만료** 순으로 종료를 판정한다. 목표 상실·시간 만료 시 남은 적은 공격을 멈추고 최대 100틱 안에 철수한다. 전원 불능은 시간을 멈추고 불러오기·초기화를 안내한다. 결과에는 종료 원인, 부상 인원, 전투 불능 인원, 시설 피해량을 표시한다. |
| R7 시간·저장·재시작 | 같은 틱에 같은 명령을 내리면 1·3배속 결과가 일치한다. 예고 1틱이 남은 저장을 복원하면 다음 틱에 두 명이 한 번만 출현한다. 단독 사수가 준비 9/10에서 복원되면 조건 유지 시 다음 틱에 피해 25가 한 번 들어간다. 로드 직후 선택·지정 모드를 해제하고 사수를 다시 선택하면 복원된 표적이 강조된다. 초기화 시 적·표적·예고·결과가 사라진다. |

## 3. 무엇을 구현할 것인가

1. **습격을 시작하고 방어 위치를 잡는다.** 기존 시작 판정과 화면의 버튼 조건을 일치시킨다. 전투 시험 전환 안내, 선택할 조리대, 예고 중 보호 목표와 진입 칸, 다음 조작을 단계에 맞게 표시한다.
2. **선택한 정착민의 공격을 끝까지 읽는다.** 기존 공격 명령과 피해 처리를 사용하고, 지도 표시와 클릭 대상에 같은 적 ID와 겹침 순서를 적용한다. 표적 소멸·사수 변경·복원 때 기존 월드 상태에서 강조를 갱신한다. 이를 위해 저장 형식을 바꿀 필요는 없다.
3. **한 판을 끝내고 생활로 돌아간다.** 결과에서 적을 모두 제압했는지, 보호 목표를 잃었는지, 누가 다쳤는지 확인한다. 소집 해제 후 기존 치료·수리·자동 작업으로 이어진다. 정보전, 신규 무기·탄약, 무작위·자동 반복 습격, 난이도 조정은 후속 범위다.

## 4. 검증과 완료 조건

| 확인 주체·환경 | 입력과 통과 조건 |
|---|---|
| 에이전트 · 규칙 검사 | R1~R7 경계와 종료 우선순위를 검사한다. 마지막 적과 마지막 아군이 같은 틱에 쓰러지면 전원 불능, 철수 중 추가 피해는 0이어야 한다. 대표 승리와 목표 상실·시간 만료·전원 불능은 별도 배치에서 재현한다. |
| 에이전트 · PlayMode | 버튼·맵 입력 경로로 두 사수를 선택·이동·공격시킨다. 시작을 거부하는 이유, 정지 중 지정, 겹친 적 클릭과 강조의 일치, 재선택·로드·초기화 직후 표시를 검사한다. |
| 에이전트 · Windows Player | 일반 시간 진행과 화면 명령으로 두 적을 직접 지정해 방어 성공·적 0명·조리대 내구도 100을 확인한다. 자동 표적 재지정이나 직접 체력 변경 없이 진행한다. 예고·교전·결과 화면을 남겨 보호 표시·표적 강조·결과 문구의 가림을 확인한다. |
| 사용자 · 직접 플레이 | 구현·빌드 후 새 판에서 화면만 보고 보호 시설, 적의 진입 방향, 현재 사수의 표적, 종료 이유를 각각 짚을 수 있는지 확인한다. 직접 조작 결과를 따로 기록한다. |

기존 Player 검사는 한 명이 실제로 쓰러진 뒤 나머지 두 명이 같은 칸에서 싸워 승리한 경우다. 기존 PlayMode 검사는 첫 표적을 지정한 뒤 초기화했다. 위 대표 승리는 시뮬레이션에서 확인했고, 새 안내·표시와 화면 입력으로 끝까지 승리하는 검사는 구현 후 수행한다.
