# 작업 3: 채집·운반·저장 상세 계획

작성일: 2026-11-15. **사용자가 추천안 구현을 승인했다. 구현·자동 검증은 완료했고 실제 사용자 조작 확인은 대기 중이다. 아래 완료 기준의 근거는 Status와 검증 기록으로 구분한다.** 기준 코드는 `7d20688`이다. 현재 구현된 규칙은 [점유 계약](../Contracts/InteractionOccupancy.md), 실제 진행 상태는 [Status](../Status.md)를 따른다.

## 목표와 추천 결론

플레이어가 식물·나무와 저장 구역을 지정하면, 정착민이 먹고 쉬면서 채집물을 운반한다. R로 소집하면 즉시 작업과 점유를 해제하고 운반물을 보존한다. 다른 정착민은 남은 요청을 이어받을 수 있다.

추천하는 핵심 선택은 두 가지다.

1. **출발 스택을 점유하고 접근한 뒤, 집는 순간 저장 칸 점유로 전환한다.** 안정된 상태에서 Pawn이 점유하는 상호작용 대상은 하나라는 기존 규칙을 유지한다.
2. **중단 시 운반물은 현재 논리 타일에 내려놓고, 생활 종료·소집 해제 후 작업을 새로 선택한다.** 중단한 작업으로 강제 복귀하지 않는다.

이번 범위는 유한한 나무·식용 식물, 채집 지정, 운반, 저장 구역·필터, 최소 자동 작업 선택과 상태 표시다. 농사·재성장·조리·건설, 개인별 우선순위 편집, 저장 구역 우선순위, 무게·도구·품질, 파일 저장/불러오기는 제외한다. 여기서 저장은 물자 보관이며 파일 저장은 작업 7이다. 자체 식량 재생산과 장기 자급 달성을 이번 완료 조건으로 삼지 않는다.

## 구현 전 기준 코드와 연결 지점

계획 작성 당시 Simulation에는 생활 행동, 고정 위치 자원 스택, 침대와 행동 ID가 있다. 채집 대상·작업 요청·운반물·저장 칸은 없다. `ResourceState.AccessibleAmount`는 다른 Pawn이 점유하면 0이며, 운반할 때도 남은 수량을 다른 Pawn에게 공개하지 않는다. 기존 자원 소비 집계는 운반을 소비로 기록하지 않도록 확장해야 한다.

- 생활·노동·수동 이동이 동시에 진행되지 않게 현재 행동의 종류와 취소 경로를 연결한다. 생활에 노동을 억지로 포함하거나 화면에서 별도 작업 상태를 관리하지 않는다.
- `ActionId`는 모든 행동의 세대 검사에 사용한다. 취소·종료 후 증가시키며, 같은 운반의 접근→집기→운반→내려놓기는 같은 행동이다.
- 상태 변경·작업 선택·경로·수량 보존은 Simulation 책임이다. Runtime은 입력 명령과 Tick, Presentation은 선택·미리보기·상태 표시를 담당한다.
- 새 개체 ID는 월드 안에서 재사용하지 않는다. 합칠 때 도착 스택 ID를 유지하고, 빈 칸 생성·바닥 낙하는 새 ID를 부여한다. Reset은 별도 월드로 초기화한다.

## 작업 요청과 점유 계약 확장안

### 요청과 실행 행동을 구분한다

채집 지정은 월드에 남는 요청이다. 특정 Pawn이 요청을 배정받으면 그 실행 행동에 점유가 붙는다. R·생활 중단은 **그 Pawn의 실행 행동만** 취소하며 요청은 남긴다. 플레이어의 ‘채집 지정 취소’는 요청 자체를 제거하고 해당 실행 행동도 취소한다. 운반 요청은 미보관 물자와 저장 공간에서 자동 생성되며 수량 변화 후 다시 계산한다.

| 대상 | 독점 범위 | 해제 시점 |
|---|---|---|
| 채집 식물·나무 | 대상 하나 전체, 접근 전에 획득 | 완료, 생활 중단, R, 지정 취소, 대상 무효 |
| 출발 자원 | 스택 전체, 접근 전에 획득 | 집기 성공 후 전환, 취소, 경로·수량 무효 |
| 도착 저장 칸 | 타일 하나와 그 칸에 보관된 스택 | 저장 완료, 취소, 필터·구역·경로 무효 |
| 운반물 | 운반 Pawn에게 귀속, 다른 Pawn이 접근할 월드 대상이 아님 | 저장 또는 바닥에 내려놓기 |

점유자는 `(Pawn ID, Action ID)`로 검사한다. 늦게 도착한 취소·해제·완료 명령은 새로운 행동이나 다른 Pawn의 점유를 바꾸지 못한다. 저장 칸과 그 안의 보관 스택은 **하나의 점유 권한**을 공유한다. 칸에 입고 중인 Pawn과 그 스택에서 먹는 Pawn이 동시에 점유하는 이중 권한을 만들지 않는다. 구역 전체를 잠그지는 않으므로 다른 칸은 다른 Pawn이 이용할 수 있다.

### 운반의 점유 전환

1. 출발 스택과 도달 가능한 허용 저장 칸을 조회한다. 저장 칸은 아직 점유하지 않는다.
2. 출발 스택을 독점하고 접근한다. 다른 Pawn은 잔량을 먹거나 운반할 수 없다.
3. 집기 완료 시 목적지와 여유를 재검사한다. 목적지 확보와 `출발 수량 감소 → 운반물 생성 → 출발 점유 해제`를 하나의 원자적 전환으로 처리한다. 중간 상태는 다른 행동 선택·화면·이벤트에 노출하지 않는다.
4. 목적지를 확보하지 못하면 집지 않고 출발 점유를 해제한다. 물자는 원래 위치에 남는다.
5. 도착 후 저장 완료 시 `운반물 감소 → 보관 수량 증가 → 목적지 점유 해제`를 원자적으로 처리한다. 완료 직전에도 필터·경로·수량·행동 ID를 확인한다.

출발과 도착을 처음부터 동시에 장기 점유하는 대안은 헛걸음을 줄이지만, 한 행동의 복수 점유·교착 방지·취소 정리가 필요하다. 이번에는 기존 단일 점유 규칙을 유지하는 전환 방식을 추천한다. 대신 접근 중 저장 공간이 없어져 재선택하는 경우를 정상적인 보류로 표시한다.

## 자원·채집·저장 규칙

아래 작업 시간·용량은 첫 시험값이다. 기존 욕구·이동·식사·수면 수치는 바꾸지 않는다.

| 항목 | 추천 초기값과 의미 |
|---|---|
| 벌목 | 나무 1개, 현장 작업 60Tick, 목재 10개 |
| 식물 채집 | 식용 식물 1개, 현장 작업 30Tick, 식재료 4개 |
| 운반량 | 종류에 관계없이 한 번에 최대 10개, 한 종류만 운반 |
| 저장 칸 | 타일당 한 종류 최대 50개, 여러 칸의 동일 자원 보관 허용 |
| 집기·내려놓기 | 각각 현장 1Tick. 도착한 Tick에는 진행하지 않음 |
| 재탐색 | 관련 변경 후 다음 선택 단계, 변경이 없으면 최대 10Tick 간격 |

10Tick/초 기준 채집 작업 시간은 1배속에서 각각 6초·3초다. 이동 시간은 별도다. 운반으로 인한 추가 감속은 이번에 넣지 않고 기존 기아 이동 감속을 유지한다.

- 채집 대상은 이번에는 통행을 막지 않고 대상 타일에서 작업한다. 통행 장애물인 나무·인접 작업 타일 규칙은 제외한다. 해당 단순화를 화면과 시나리오에도 동일하게 적용한다.
- 채집 진행도는 대상에 남는다. 생활·소집·지정 취소 시 생산량은 0이고 진행도는 보존한다. 재지정하거나 다른 Pawn이 맡으면 남은 작업을 수행한다. 완료 시 한 번만 산출하고 대상을 소진시킨다. 다음 Tick부터 산출물을 운반할 수 있다.
- 산출물은 현장에 새 미보관 스택으로 생성한다. 저장 공간 부족 자체는 유한한 대상 채집을 막지 않는다. 반복 생산의 출력 포화 규칙은 작업 5에서 다룬다.
- 저장 구역은 비용이 없고 중첩 불가다. 사각형 전체가 맵 안의 통행 가능한 시설 없는 타일일 때 생성한다. 잘못된 사각형은 전체 거부하고 이유를 표시한다. Pawn·느슨한 물자는 생성 장애물이 아니다.
- 필터는 목재·식재료·식사를 각각 허용한다. 기본은 모두 허용, 모두 끄기도 가능하다. 서로 다른 종류는 한 칸에 섞지 않는다.
- 정상 보관된 물자는 운반 후보에서 제외해 구역 간 왕복을 막는다. 필터로 금지하거나 구역을 삭제한 물자는 같은 위치의 미보관 물자로 전환한다. 수량은 보존하며 다른 허용 구역이 있으면 재운반한다.
- 보관 중인 식사·식재료도 기존 식사 규칙으로 먹을 수 있다. 저장 구역을 거쳐야만 먹을 수 있는 것은 아니다. 음식 스택 독점 규칙은 유지한다.
- 목적지는 출발지에서 실제 경로가 짧은 칸, 구역 ID, 타일 좌표 순으로 선택한다. 좌표 순서는 Y 다음 X 오름차순이다. 이동·선택 동률의 재현성을 유지한다.
- 느슨한 스택은 같은 타일에 여러 개 있을 수 있고 저장 칸의 용량과 별개다. 구역 안에 놓였다는 이유만으로 보관된 것으로 세지 않는다. 해당 타일의 미보관 물자를 보관할 때도 집기·입고 절차를 거친다.

## 중단·생활·플레이어 명령 우선순위

우선순위는 **소집 중 플레이어 명령 → 해결 가능한 식사 → 수면 목적 유지 → 기존 일반 작업 계속 → 새 일반 작업**이다. 소집 중에는 자동 식사·수면·노동을 모두 억제하되 욕구 감소는 기존대로 계속된다.

- 포만도 30 이하이고 도달·점유 가능한 음식이 있으면 노동을 취소하고 식사한다. 기존 식사 우선, 없으면 식재료 4개 생식을 유지한다.
- 음식이 없거나 모두 타인이 점유해 지금 먹을 수 없으면 ‘음식 부족/점유 중’을 표시한다. 수면이 필요하면 자고, 아니면 노동을 계속할 수 있다. 굶주렸다는 이유로 매 Tick 채집을 취소해 식재료를 만들지 못하는 순환을 금지한다.
- 자신이 운반·점유한 음식은 작업을 정리하면 먹을 수 있는지 평가에 포함한다. 먹을 만큼 있다면 먼저 작업 취소·내려놓기를 끝낸 뒤 기존 식사 점유를 새로 획득한다. 운반물 안에서 바로 먹는 별도 규칙은 만들지 않는다. 타인의 점유를 빼앗지 않는다.
- 휴식 20 이하 또는 기존 `HasSleepIntent`가 유지되는 동안 노동을 선택하지 않는다. 휴식 90에 도달할 때까지 침대/바닥 수면을 이어간다. 바닥 수면자의 빈 침대 재선택은 일반 작업보다 우선한다.
- 식사·수면이 끝나면 현시점의 요청에서 다시 선택한다. 기존 채집 진행도는 현장에 남지만 이전 Pawn에게 복귀를 보장하지 않는다.
- 노동 중에는 더 가까운 요청이 생겼다는 이유로 교체하지 않는다. 새 작업의 고정 우선순위는 **운반 → 채집**이다. 불가능한 운반은 채집을 막지 않는다. 같은 종류는 실제 접근 거리, 요청 생성 순서, 대상 ID 순이며 Pawn 배정은 ID 순이다. 개인별 우선순위 UI는 작업 6이다.
- 소집되지 않은 일반 수동 이동은 도착까지 노동 배정을 보류하지만 생활이 필요하면 중단될 수 있다. 생활·노동 중 우클릭은 거부하고 ‘R로 소집 후 이동’을 안내한다. 명시적으로 소집한 뒤 내린 명령이 모든 자동 행동보다 우선한다.

### 중단 처리표

| 상황 | 같은 처리 안에서 해야 할 일 | 이후 |
|---|---|---|
| 집기 전 취소 | 출발 점유·이동·진행 중인 행동 제거 | 출발 수량 그대로 |
| 운반 중 취소 | 도착 점유 해제, 운반물을 현재 논리 타일의 새 미보관 스택으로 전환, 운반량 0 | 생활 또는 소집 이동으로 전환 |
| 채집 중 취소 | 대상 점유·이동 해제, 현장 진행도 유지 | 지정이 남으면 다른 Pawn 배정 가능 |
| 저장 구역 삭제·필터 변경 | 해당 입고 행동 취소, 운반물 안전 낙하, 보관 물자 자격 재계산 | 허용 목적지 재선택 |
| 경로 차단 | 유효한 우회 경로면 계속, 없으면 취소·필요 시 낙하 | 통행 변경/재시도 시 새 선택 |
| R 소집 | Tick을 기다리지 않고 현재 행동·대기 이동·점유를 취소하고 낙하, 수면 목적 해제 | 전역 채집 지정·저장 구역은 유지 |
| R 해제 | 소집 이동도 취소 | 다음 Tick에 생활부터 새 선택 |
| Reset | 월드·요청·점유·운반물·선택 상태 폐기 | 시나리오 초기 수량·지정 없는 상태 복원 |

안전한 낙하는 현재 논리 타일에 별도 스택을 생성하므로 저장 칸이 가득 차거나 다른 Pawn이 같은 위치에 있어도 실패하지 않는다. 점유된 기존 스택에 합치지 않는다. 통행 변경으로 현재 타일이 막혔어도 물자는 남기며, 접근 가능해질 때까지 운반 불가로 표시한다. 표시 위치와 수량을 숨기거나 삭제하지 않는다.

### Tick 순서와 경계 조건

일시정지 중 R·행동 취소·채집 지정·구역 편집은 즉시 적용한다. 무효 행동과 점유도 즉시 정리하며 자동 행동 선택은 다음 Tick이다. 상세 기준은 [즉시 명령 계약](../Contracts/ImmediatePlayerCommands.md)을 따른다.

Tick에서는 외부 명령/대상 무효 처리 → 욕구 갱신 → 노동을 중단해야 할 생활 조건 판정 → 기존 생활 행동 진행·완료 → 생활 선택·점유 → 기존 노동 진행·완료 → 일반 작업 선택·점유 → 이동·도착 순으로 처리한다. 같은 Tick에 취소가 적용되면 채집 산출·집기·입고 완료보다 취소가 먼저다. 새로 시작하거나 도착한 행동은 다음 Tick부터 진행한다. 기존 식사·수면 완료와 신규 회복 시작 시점은 회귀 검사로 유지한다.

## 조작과 화면

| 조작 | 결과 |
|---|---|
| 기본 모드 좌클릭 | 기존 Pawn 선택, 물자·채집 대상·구역 정보 선택. 겹친 개체는 정보 목록에서 ID별 선택 |
| ‘채집 지정’ 버튼 후 대상 클릭 | 나무·식물 지정. 이미 지정된 대상은 중복 요청하지 않음 |
| 대상 정보의 ‘지정 취소’ | 요청 제거, 진행 중 담당자의 행동·점유 취소 |
| ‘저장 구역’ 버튼 후 두 모서리 클릭 | 사각형 미리보기 후 생성 명령. 첫 클릭만으로 생성하지 않음 |
| 구역 선택 후 필터 체크/‘구역 삭제’ | 즉시 적용. 물자 삭제가 아님을 표시 |
| Esc | 도구 미리보기 취소, 기본 모드에서는 기존 선택 해제. 이미 접수한 명령 취소가 아님 |
| R / 소집 버튼, 우클릭 | 기존 소집 토글과 이동 유지. 도구 사용 중 우클릭은 도구 취소만 하고 이동 명령은 내리지 않음 |
| Space, 1, 3, . | 기존 정지·배속·한 Tick 조작 유지 |

UI 위 클릭과 텍스트 입력 중 단축키는 월드 명령을 생성하지 않는다. R은 Pawn 선택이 있을 때 기존 동작을 유지한다. 표시 항목은 Pawn 행동/목적지/운반 종류·수량, 대상 진행도/담당자, 저장 칸 보관량/50/점유자, 자원별 미보관·운반 중·보관·총량이다. ‘식사용 접근 가능 수량’은 총량과 별도로 표시한다.

보류 이유는 최소한 ‘지정 없음’, ‘대상 점유 중’, ‘접근 불가’, ‘허용 저장 구역 없음’, ‘저장 공간 부족’, ‘도착 칸 점유 중’으로 구분한다. 구역·필터·수량·점유·통행 변경 시 다음 선택 단계에 재평가하고, 실패 후보를 매 프레임 다시 탐색하지 않는다.

기존 이동·생활·R·음식 독점·바닥 수면 재선택 87개 검사는 회귀 기준이다. 신규 검사 수는 구현 후 실제 실행 결과로 기록하며, 저장 때문에 기존 식사가 막히거나 욕구 임계 Tick이 달라지면 원인을 해결한 뒤 완료 처리한다.

## 사용자 조작 확인과 최종 완료 조건

새 실행 파일과 확인 순서는 [WorkDemo](../WorkDemo.md)를 따른다. 자동 검증은 완료했고 아래 실제 사람 조작 확인은 대기 중이다.

1. 나무·식물과 저장 구역을 지정한다. 지정한 대상만 작업하고 산출물이 허용 칸으로 이동하는지 본다.
2. 운반 중 R을 누른다. 즉시 멈추고 물자가 바닥에 남으며, 다른 Pawn이 남은 요청을 이어받는지 본다.
3. R 해제 후 허기·피로가 높은 Pawn을 본다. 식사·수면이 먼저이며 끝난 뒤 노동을 새로 선택하는지 본다.
4. 구역 필터를 끄거나 구역을 삭제한다. 물자는 남고 보류 이유가 보이며, 허용 공간을 다시 만들면 운반이 재개되는지 본다.
5. 정지·한 Tick·배속·Reset을 확인한다. 표시량과 실제 물자가 일치하고 초기화 후 남은 지정·운반 표시가 없는지 본다.

전체 완료는 지정→채집→운반→저장의 자동 순환, 모든 중단 경계에서 수량 보존과 점유 해제, 생활·플레이어 우선, 실패 해소 후 재개, 기존 회귀 통과, Windows 실행 증거를 충족해야 한다. 실제 조작·화면 확인이 남으면 자동 검증 완료와 분리해 미검증으로 기록한다. Computer Use는 사용하지 않는다. 구현 후에도 커밋은 별도 승인 대상이다.
