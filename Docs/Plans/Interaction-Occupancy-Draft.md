# 상호작용 점유와 소집의 공통 규칙·개발 계획

작성: 2026-11-15. **사용자가 R 토글·음식 스택 독점을 승인하여 구현·자동검증을 완료했다.** 사용자 최신 요청은 X/Stop 대신 R 소집 통일, 오브젝트별 단일 Pawn 점유, 명령 취소와 점유 해제의 결합, 해제된 침대의 재선택이다. 이 문서는 관련 기존 계획보다 우선하는 다음 변경 기준이다. 현재 실행 파일 동작과 구분한다.

## 결론과 결정 구분

확정 요구: 침대·음식 등 상호작용 오브젝트는 한 번에 한 Pawn만 점유한다. 접근 행동을 시작하기 전에 점유를 확보한다. 소집 시 해당 행동과 아직 실행되지 않은 예약 명령을 모두 취소하고 점유를 해제한다. R을 소집 조작으로 통일하며 X 소집/Stop 경로는 제거한다.

승인한 구체화 기준은 두 가지다.

1. **R 한 키와 버튼 하나로 소집/해제 토글.** 비소집에서 R은 소집, 소집 중 R은 해제. 버튼은 현재 상태에 따라 Draft [R] / Undraft [R]로 바뀐다. 별도 Stop·Release 버튼과 X 단축키는 제거한다. 소집 중 새 우클릭은 이동 재지정, 현재 타일 우클릭은 현재 이동 중단으로 사용한다. R 재입력은 이동 정지가 아니라 해제라는 점을 명시한다.
2. **현재 음식 스택 하나를 오브젝트 하나로 취급.** 식사18개가 든 스택도 동시에 한 명만 점유한다. 다른 Pawn은 다른 스택/생식 대안을 찾거나 기다린다. 음식 개별 낱개 분리·운반·식사 좌석은 이번 범위에 넣지 않는다. 이는 단일 점유 요구를 현재 데이터에 적용한 기준이며 여러 음식이 물리적으로 한 개라는 뜻은 아니다.

R의 소집/해제 의미와 음식 스택 경계 외에는 추가 선택을 요구하지 않는다. 아래 세부 정책과 [공통 계약](../Contracts/InteractionOccupancy.md)을 이번 구현 기준으로 적용한다.

## 공통 개념

- **행동 명령:** Pawn이 수행하려는 목적과 생명주기. 예: 침대에서 휴식90까지 수면, 음식1개 먹기. 요청·진행·완료·취소 상태를 구분한다.
- **점유:** 그 행동이 오브젝트를 독점할 권리. 오브젝트 ID, Pawn ID, 행동 식별자를 묶는다. 거리나 실제 위치와 무관하다.
- **접근/사용:** 같은 점유를 유지하는 두 단계다. 침대 접근 중과 침대에서 수면 중 모두 다른 Pawn은 점유할 수 없다. 위치가 같다고 자동 소유자가 되지 않는다.
- **수량 확보:** 소비 행동이 완료 때 사용할 양. 점유와 별개다. 식사1개/생식4개를 확보하되 오브젝트 전체에는 소유자가 한 명뿐이다.
- **대체 행동:** 최선 대상 확보에 실패해서 수행하는 행동. 바닥 수면은 휴식을 회복하면서 빈 침대를 다시 찾을 수 있다. 오브젝트 점유가 없는 대체 행동이다.

타일 통행과 오브젝트 점유는 다른 규칙이다. 현재처럼 Pawn끼리 같은 타일을 통과할 수 있어도 동일 침대·음식을 동시에 사용할 수는 없다. 개인 침대 배정 같은 영구 소유권도 이번 점유와 다르다.

## 명령과 점유의 생명주기

`욕구/요청 → 유효 후보·경로 확인 → 독점 점유+명령 등록 → 접근 → 사용 → 완료·해제`

1. 비소집 Pawn만 자동 생활을 선택한다. 먹을 수 있는 식사를 우선하고 수면을 다음으로 판단한다.
2. 대상 존재·사용 자격·수량·도달 가능성을 검사한다. 아직 실행하지 않을 장기 대기 작업까지 오브젝트를 잠그지 않는다.
3. 점유 획득과 현재 행동 등록은 한 번의 성공/실패로 처리한다. 실패한 Pawn은 대상 이동을 시작하지 않는다. 중간 실패 시 점유만 남겨 두지 않는다.
4. 접근 중에도 같은 점유를 유지한다. 도착 시 오브젝트와 명령의 소유 일치를 다시 확인하고 사용 단계로 바꾼다. 점유를 해제했다가 재획득하지 않는다.
5. 식사는 완료 순간에만 확보 수량을 차감하고 회복한다. 수면은 기존 회복률로 진행하여90에서 끝난다. 완료와 점유 해제는 한 번만 처리한다.
6. 완료·취소·대상 삭제·경로 완전 차단·소집·월드 초기화에서 명령과 점유를 함께 정리한다. 동일 취소를 두 번 처리해도 추가 소비·환불·다른 Pawn 점유 해제가 생기지 않는다.

점유 권한은 `(World, ObjectId, PawnId, ActionId)`로 검증하는 구조를 추천한다. 취소된 이전 명령의 도착/완료/해제 결과가 늦게 처리돼도 새 명령이나 새 소유자를 건드릴 수 없다. 동시 스레드나 대규모 범용 작업 시스템을 지금 도입할 필요는 없다. 단일 시뮬레이션 안에서 동일한 계약으로 구현하면 된다.

## 취소와 소집

R로 소집하면 시간 정지 중에도 즉시 다음을 처리한다.

1. 먼저 소집 상태로 전환해 새로운 자동 명령 생성을 차단한다.
2. 현재 행동과 미적용 생활/이동 요청을 취소하고 이전 행동 식별자를 무효화한다.
3. 해당 행동의 점유·확보 수량·경로·진행도를 제거한다. 아직 먹지 않은 음식은 소비하지 않으며 완료된 소비는 환불하지 않는다.
4. 해제된 오브젝트의 가용 상태 변경을 기록한다. 다른 Pawn의 재평가는 다음 시뮬레이션Tick에 처리한다. 일시정지 중 다른 Pawn이 이동하거나 수면 회복을 진행하지는 않는다.

소집 Pawn은 우클릭 이동/재지정만 수행하고 자동 식사·수면을 시작하지 않는다. 욕구 감소는 계속된다. R로 해제하면 수동 명령을 정리하고 다음Tick 현재 상황에서 새 행동을 선택한다. 이전 명령이나 이전 점유를 복원하지 않는다. Reset은 모든 소집·명령·점유를 초기화한다.

## 빈 침대 발생과 바닥 수면 재평가

예시: A가 침대를 점유하고 접근 중, B가 침대 부족으로 바닥 수면 중이다. A를 소집하면 A의 접근 명령과 침대 점유가 즉시 사라진다. 다음Tick에 B는 빈 침대를 후보로 평가하고, **먼저 점유를 얻은 뒤** 바닥 수면을 끝내고 침대로 이동한다. 도착하면 같은 수면 목적을 이어간다.

- B의 휴식도가20을 넘었어도 수면 목적이 아직 끝나지 않았다면 재평가한다. `현재 Rest<=20`만으로 재선택을 제한하면 안 된다.90에 도달해 기상한 Pawn은 제외한다.
- 탐색/점유가 실패하면 바닥 수면을 유지한다. 빈 침대가 있다는 이유만으로 먼저 깨우지 않는다.
- 침대 확보 후 이동하는 동안 수면 회복은 멈추고 기존 깨어 있는 감소량을 적용한다. 누적 휴식도는 보존한다. 도착Tick에는 추가 회복하지 않고 다음Tick부터 침대 회복률을 적용한다.
- 바닥→침대 전환은 수면 완료로 세지 않는다.90에 도달할 때 한 번만 수면 완료 처리한다.
- 이미 침대를 점유/사용 중인 Pawn은 더 가까운 침대가 생겨도 옮기지 않는다. 현재 유효 점유를 빼앗지 않는다.
- 해제·복원·통행 변경 등의 가용 상태 변경에 반응하고, 실패 중에는 최대10Tick 간격 보조 재시도를 둔다. 매 프레임 모든 Pawn이 경로를 재계산하지 않는다.
- 신규 수면 요청과 바닥 수면 개선 요청은 같은 후보 집합에서 휴식도 낮은 순→Pawn ID 순으로 경쟁한다. 후보 침대는 실제 경로 길이→오브젝트 ID 순이다.
- 이동 중 침대 삭제/완전 차단이면 점유를 해제하고 대체침대 또는 바닥 수면을 선택한다. 이미 시작한 수면 목적은90 도달 전까지 유지한다.
- 먹을 수 있는 허기가 동시에 발생하면 식사 우선 규칙을 유지한다. 기존 수면 목적은 식사 뒤에도 이어가고,90 미만이면 새 침대/바닥을 선택한다. 목적을 유지하더라도 식사 중 침대 점유는 보유하지 않는다.

이 마지막 규칙은 수면 목적과 잠시 수행하는 행동을 분리한다. 소집·명시 취소는 목적 자체를 취소하고, 대상 변경·대체 수면·허기 해결은 자동 목적을 유지하는 것으로 구분한다.

## 음식과 다른 상호작용에 적용

음식 스택 총량이18이어도 A가 식사1개를 확보하면 B는 해당 스택을 점유할 수 없다. A의 확보량은1이고 재고는 완료 전18이다. 나머지17개는 재고상 미확보량이지만 타 Pawn이 지금 사용할 수 있는 양은0이다. UI는 `총량 / 확보량 / 소유자 / 접근·사용 단계`를 보여주고 미확보량을 '누구나 사용 가능'으로 표시하지 않는다.

A가 취소하면 확보량0·소유자없음·총량18. A가 식사를 완료하면 총량17·확보량0·소유자없음이다. B는 다음 결정 단계에서 점유할 수 있다. 생식4개는 한 스택에서 전량 확보하며 여러 스택을 동시에 점유하지 않는다. 음식 여러 스택은 각각 다른 Pawn이 점유할 수 있다.

한 스택 독점은 규칙이 단순하고 요청과 일치하지만 식량이 충분해도 대기가 늘어날 수 있다. 여러 Pawn이 동시에 먹게 하려면 별도 스택/오브젝트를 배치한다. 재고 부분 예약을 그대로 유지하는 대안은 현재 사용자 단일 점유 요구와 충돌하므로 채택하지 않는다. 자동 스택 분할·운반 도입은 별도 계획으로 남긴다.

향후 작업대·채집 대상에도 같은 획득→접근→사용→해제 규칙을 적용할 수 있다. 이번 구현 범위는 침대·음식에 한정하며 여러 사용 슬롯이나 복수 오브젝트 동시 확보는 제외한다.

## Tick 순서와 불변 조건

소집 입력의 즉시 취소 이후 Tick은 외부 대상 변경/무효 점유 정리→욕구/기존 사용 진행·완료→자동 목적/후보 경쟁·점유→이동/도착 순으로 처리한다. 한Tick에 한 행동이 두 번 진행하거나 바닥과 침대 회복을 중복 적용하지 않는다. 같은Tick에 해제된 대상은 뒤의 결정 단계에서 재획득 가능하다.

항상 검사할 조건:

- 오브젝트 소유자는0명 또는1명. 현재 범위에서 Pawn은 상호작용 오브젝트를 최대1개 점유한다.
- 유효 행동의 대상·Pawn·ActionId와 점유가 일치한다. 소유권 없는 접근/사용/완료는 금지한다.
- 소집 Pawn은 자동 목적·명령·점유0. 다른 Pawn의 유효 점유를 해제하지 않는다.
- 취소된 명령은 다시 실행되지 않는다. 점유 해제는 수량 추가가 아니다.
- 초기량+추가량−실제소비량−외부제거량=현재량. 확보량은 소비량과 분리한다.
