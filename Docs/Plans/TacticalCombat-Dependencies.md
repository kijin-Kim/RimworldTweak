# 전투 기능 의존성과 단계별 구체화

> 2026-11-17 사용자 지시로 현재 실행 방향은 [림월드식 기본 전투부터 확장하는 계획](Combat-Baseline-Incremental.md)으로 대체한다. 아래 C0~C9는 이전의 전체 확장 가정에 따른 참고 이력이며 고정 실행 순서·필수 기능 목록이 아니다. 기본 엄폐·교전은 제압/탄약/Fog of War보다 먼저 완성한다. 제압에 유한 탄약, 공격에 현장 보급·Fog of War가 반드시 필요하다는 아래 수락 의존도 현재 계획에는 적용하지 않는다. 각 확장을 선택할 때 실제 필요한 선행만 다시 판단한다.

작성일: 2026-11-17. [전투·원정·보급 초안](TacticalCombat-Offense-Logistics.md)의 후속 제안이다. 구현 착수·일정·세부 규칙 확정이 아니며 현재 UI 작업의 범위를 바꾸지 않는다.

## 1. 핵심 설계

개별 정착민 지휘를 유지하는 권장안을 전제로, 작은 맵에서 실제 교전이 성립하는지 먼저 확인한다. 공격과 방어는 같은 사선·피해·제압·탄약 규칙을 사용하고 임무 목표와 배치만 다르게 한다. 상세 신체 시뮬레이션, 세계지도, 자동 분대 전술은 선행 조건이 아니다.

### 확인한 현재 기반

| 기존 코드 | 확인한 역할 | 전투를 위해 필요한 변경 제안 |
|---|---|---|
| WorldState.QueueMove / SetDrafted | 소집 검사, 이동 명령 접수, 소집 시 기존 행동 정리 | 이동·소집 해제·정지에 따른 조준/재장전 취소 및 전투 명령 권한 검사 연결 |
| WorldState.Step | 생활·작업·이동을 고정 Tick 순서로 처리 | 이동·관측·공격·결과 적용 순서를 명시하고 생활/작업과 충돌하지 않게 연결 |
| ConstructionRules.BlocksMovement | 벽과 조리대의 통행 차단 | 통행 차단을 시야/사격 차단으로 재사용하지 않음. 낮은 엄폐는 별도 특성 필요 |
| ColonistState.CargoKind / CargoAmount | 작업 중 운반 물자 | 휴대 탄약·장비·원정 소지품과 구분. 운반 행동 취소로 탄약이 사라지면 안 됨 |
| InteractionClaim 및 자원 예약 | 물자·대상 사용 권한 | 재보급/구조 중단 시 예약 해제와 실제 이전량 보존에 활용 가능. 그대로 적합한지는 구현 시 확인 |
| SaveData / WorldState.Save | 버전과 월드 상태 저장·복원 검증 | 전투 진행·탄약·관측 기억·임무 상태를 추가하는 단계마다 함께 확장 |

위 항목은 지정 파일의 소스 확인 결과다. 전투가 이미 구현됐다는 의미가 아니며 전체 코드 감사·빌드·런타임 검증은 하지 않았다.

### 먼저 나눌 세 가지 판정

- 통행: 그 칸에 들어갈 수 있는가.
- 관측: 우리 진영이 현재 그 대상의 위치를 아는가.
- 사격: 그 위치까지 무기 사거리와 사선이 유효한가.

초기 전투 시험은 모든 대상을 관측한 상태로 시작할 수 있지만, UI·자동 표적·적 AI가 직접 전체 적 목록을 쓰지 않고 '현재 알고 있는 적'을 조회하게 한다. 실제로 필요한 조회 경계만 만들고 범용 감각 시스템이나 캐시는 선행 구현하지 않는다.

### 필수 선행과 권장 실행 순서

아래는 제안한 의존 관계이며 에이전트 병렬 실행 지시가 아니다.

```text
C0 공통 판정·상태 계약
 └─ C1 기본 교전·최소 부상
     ├─ C2 휴대 탄약·재장전 ── C3 제압·방향 엄폐
     ├─ C4 관측·기억·정보 제한
     └─ C5 구조·치료·복귀

C1 + C2 + C3 + C4 ── C6 준비형 방어 임무
C2 + C4 + 기존 운반·예약 ── C7 현장 재보급
C6의 임무 공통 규칙 + C7 + C5 ── C8 공격·회수·철수 시험
C8 + 저장 호환 + 시간/소유권 결정 ── C9 정착지 출발·귀환
```

C3의 피해 없는 제압 효과만 단위 시험하는 데 C2가 꼭 필요한 것은 아니다. 하지만 지속 제압의 비용을 평가하고 기능을 수락하려면 유한 탄약이 필요하다. C4는 제압·치료 없이 만들 수 있다. C5는 기초 교전 후 진행할 수 있고, 정착지 운영 복귀와 부상자 철수를 통합 수락할 때 필수다.

권장 실행 순서는 C0 → C1 → C2 → C3 → C4 → C5 → C6 → C7 → C8 → C9다. 이는 전체 완료를 순서대로 기다려야 하는 직선 의존과 다르다. C6를 먼저 시험하는 이유는 익숙한 방어에서 원인을 구분하기 쉽기 때문이며 공격 시스템이 방어 콘텐츠 전체를 기술적으로 요구해서가 아니다. C8은 C6의 공통 임무 규칙만 필요하고 모든 습격 유형은 필요 없다.

## 2. 대표 동작 흐름과 제안 규칙

예시: 지원 인원이 적을 제압하는 동안 이동 인원이 엄폐 사이를 이동한다. 지원 인원의 탄약이 부족해지면 후퇴·교대하거나 보급 거점에서 보충한다. 이 과정은 방어 예비대 이동과 공격 목표 접근에 공통으로 사용한다.

공격 상태 후보: 대기 → 조준 → 발사 → 회복 → 다음 조준. 장전 탄약이 부족할 때는 별도의 재장전으로 들어간다. 사격 후 회복 시간과 재장전은 구분한다.

첫 시험에서 사용할 처리 순서 제안:

1. 명령 취소와 지도 변경 반영. 조준 취소는 즉시 표시하고 정지 중 시간은 흐르지 않는다.
2. 이동 진행 및 논리 위치 확정.
3. 현재 관측 정보 갱신.
4. 기존 제압·생존 상태와 새 위치로 발사 가능 여부를 확인하고 이번 Tick의 유효 발사를 모음.
5. 발사된 탄 수만큼 탄약을 소비하고 사선·명중 결과를 계산.
6. 피해·새 제압을 적용하고 무력화, 예약 해제, 임무 결과를 처리.

같은 Tick에 유효했던 두 발은 양쪽 모두 성립할 수 있게 해 목록 순서가 선제공격 보너스가 되지 않도록 한다. 이번 Tick에 생긴 제압은 이미 성립한 발사를 소급 취소하지 않고 다음 공격 준비에 영향을 준다. 사격·제압·사망 충돌의 기준은 C0에서 테스트 사례로 고정한다. 기존 생활 처리까지 이 순서로 바꾼다는 뜻은 아니며 실제 삽입 위치는 구현 시 회귀 검토한다.

초기에는 논리 발사를 해당 Tick에 판정하고 탄환 표현은 결과를 표시하는 방식으로 시험한다. 비행 중 충돌·유탄·폭발·물리 탄도는 보류한다. 시각 탄환이 살아 있는 동안 표적을 바꿔도 이미 확정된 결과가 달라지지 않게 한다. 이 추상화의 한계는 플레이 확인에서 설명하고, 탄도 구현은 필요가 확인된 뒤 선택한다.

### 각 기능에 포함해야 할 횡단 작업

- UI: 사선 차단, 조준/회복, 제압, 탄약, 관측 여부와 명령 거부 이유를 해당 단계에서 함께 표시한다. 마지막 UI 단계로 미루지 않는다.
- 저장: 새 영속 상태를 넣은 단계에서 저장·복원을 확장한다. 지원하지 않는 전투 상태를 조용히 누락한 채 저장 성공으로 표시하지 않는다. 옛 저장에는 전투 없는 기본값을 부여하는 마이그레이션을 제안하며 미지원 파일은 기존 월드 보존 후 거부한다.
- 무작위성: 초기 교전은 확률 영향을 통제해 사선·취소를 검증한다. 확률 도입 시 seed뿐 아니라 난수 진행 상태·호출 순서도 재현 조건으로 다룬다. 최종 명중/피해 분포를 확정한 것은 아니다.
- 기존 행동 회귀: 소집·해제·정지, 운반 중 전투 전환, 사망/무력화의 예약 해제, Load/Reset 때 표적과 선택 해제를 각 단계에서 확인한다.
- 정보 보호: 지도 실제 상태와 진영 지식을 구분한다. 비관측 지역 이동의 길찾기·명령 오류가 숨겨진 장애물/적을 알려주지 않도록 기억 지도에 계획하고 실제 이동 중 새로 확인된 장애물에 대응하는 정책을 C4에서 정한다. 디버그 전체 공개는 제품 경로와 구분한다.
- 보급 안전: 미확인 적까지 아는 '안전 경로'를 자동 계산하지 않는다. 알려진 위험과 접근 가능 여부를 구분해 표시하고 소집 중 재보급은 우선 명시적 명령으로 시작한다.

### 뒤로 미룰 범위와 재검토 조건

세부 신체 부위·관통·다층 방어구는 기본 부상과 차단의 인과가 이해된 뒤, 근접·폭발은 원거리 시험 뒤 별도 기능으로 설계한다. 초기 제압 결과를 근접 전투나 비인간 적에 일반화하지 않는다. 탄약 생산과 다종 탄약은 유한 탄약이 의미 있는 선택을 만들 때 검토한다. 고정 관측소 건설은 C4 판정 뒤 기존 건설에 연결하고 처음에는 배치된 관측원을 사용해도 된다.

분대 자동 지휘는 개인 명령 부담이 실제 플레이에서 과도할 때, 세계지도·보급 수송대·거점 점령은 C9 왕복이 성립한 뒤 검토한다. 보류 항목을 출시 범위에서 영구 제외한 것은 아니다.

## 4. 검증 계획과 결정 시점

첫 검증은 C1의 '아군 1명과 적 1명, 벽 하나'다. 이후 제압 지원과 이동을 구분할 수 있도록 소규모 인원을 늘린다. C3에서는 '제압 없이 이동 / 제압 후 이동 / 제압 탄약 소진'을 같은 맵·적·입력 조건에서 비교한다. C4에서는 관측원 유무로 발견 시점과 배치 도착 시각을 비교한다. C6에서는 유효한 준비 두 가지와 준비 부족 사례를 구분한다. AI·무기·확률을 동시에 바꿔 원인을 알 수 없게 하지 않는다.

자동 검사: 완전 차단, 표적 상실, 취소된 공격, 동시 발사, 탄약 장부, 제압 축적·회복, 정보 누출, 구조 중단, 임무 이력, 저장 연속 진행의 결과를 상태·Tick·수량으로 검증한다. 예: '초기 총탄 = 발사 소비 + 무기 잔량 + 휴대 잔량 + 거점 잔량 + 기록된 유실'을 확인한다. 새 탄약 반입이 있으면 좌변에 포함한다.

렌더 검사: 사선/제압/관측/잔탄 표시를 실제 화면에서 구분할 수 있는지 확인한다. 자동 규칙 검사와 별도다. 사람 확인: 같은 규칙으로 방어와 공격을 각각 플레이하며 피해 원인·제압 해제·보급 시점·철수 판단을 이해하는지, 미세 조작 반복이 과도한지 확인한다. 실행 파일과 조작 단계는 실제 빌드가 생긴 후 제공한다.

| 결정 시점 | 필요한 선택 | 권장 기본안과 이유 |
|---|---|---|
| C1 규칙 확정 전 | 무피해 보장의 범위와 노출 교전 확률 | 완전 차단·취소는 확실하게, 노출 교전은 별도 조정. 첫 시험의 결정적 결과를 제품 전체 무피해 보장으로 해석하지 않음 |
| C3 전 | 제압 중 허용 행동과 보호된 이동 | 공격 방해부터 시험하고 보호된 후퇴를 무조건 금지하지 않음. 영구 봉쇄 방지 |

| C9 전 | 본거지 동시 진행 여부와 지도 간 시간 | 첫 통합은 원정 중 본거지 일시 동결을 권장하되 사용자 확정 필요. 구현 부담이 작지만 운영 연속성이 줄어듦. 동시 진행 선택 시 다중 월드 시간·사건·저장 검증이 C9의 추가 선행 |

## 최종 요약

공통 판정을 먼저 분리하고 실제 교전 → 유한 탄약 → 제압을 확인한다. 관측과 치료는 기본 교전에서 갈라지는 별도 의존이다. 이를 방어에서 검증한 뒤 현장 보급과 목표형 공격을 연결하고 정착지 왕복은 마지막에 둔다. 초기 기획의 학습용 순서를 실제 의존 관계로 구체화한 제안이며 제품 구현·Unity 검사·플레이 검증은 아직 하지 않았다.
