# 작업 1 상세 계획: 정착민 이동과 시간 조작

작성: 2026-11-15. 상태: 사용자 승인 기준으로 구현. 실제 검증 결과와 수동 확인 상태는 Status 및 검증 기록 기준. 커밋 없음.

## 결론과 범위

정착민 한 명을 선택해 R로 소집한 뒤 목적지를 지정하면 장애물을 우회해 도착하고, 시간을 정지·1배속·3배속으로 바꿔도 같은 게임 Tick에서 같은 이동 결과를 얻는다. 현재 8×8 맵과 정착민 3명, 자원 40/18을 유지한다.

사용자가 아래 추천 조작·이동 규칙을 승인했다. 4방향·5 Tick/칸·충돌 생략·단축키를 구현 기준으로 확정했으며 [공통 계약과 파일 소유권](../Contracts/MovementTime.md)을 따른다.

포함: 선택·목적지 지정·이동 취소, 최단 경로와 접근 불가 피드백, Tick 이동, 시간 조작, 재지정·초기화, 자동 검사·Windows 데모 검증.
제외: 자동 생활·일감 선택, 운반·자원 소비, 건설 UI, 전투·징집, 다중 선택·대형·충돌 회피, 대각 이동·지형별 비용, 카메라 이동·줌, 저장. 직접 이동은 이동 기반을 확인하기 위한 조작이며 향후 모든 생활 행동을 수동 지시한다는 설계가 아니다.

## 작업 0에서 작업 1로 확장할 경계 (계획 시점 기준)

- WorldState.Colonists는 불변 ColonistSeed를 보관한다. 초기 seed는 유지하고 월드마다 독립적인 실행 상태(현재 위치, 목적지, 경로, 이동 진행, 상태)를 만든다. 외부에서는 읽기만 가능해야 한다.
- WorldState.Step은 현재 Tick 숫자만 더한다. 이동 도입 후에는 명령과 정착민 갱신을 각 Tick 순서대로 수행해야 한다. Step(N)과 Step(1) N회가 같은 상태가 되어야 한다. tick overflow는 처리 시작 전 거부한다. long.MaxValue Tick을 실제 반복하는 기존 overflow 테스트는 불가능해지므로 테스트 전용 경계 상태 구성으로 변경하고 overflow 방어 의미는 유지한다.
- SimulationSession은 0.1초당 Tick과 decimal 잔여를 관리한다. Runtime이 배속을 적용한 게임 경과 시간을 전달하고, 시뮬레이션은 배속이나 Unity 프레임을 몰라야 한다.
- SettlementView는 현재 World 참조가 바뀔 때만 맵을 갱신한다. 이동 위치·상태는 같은 World에서도 ID 기준으로 갱신한다. 바닥·정착민·선택 표시를 매 Tick 새로 생성하지 않는다.
- 기존 readonly seed·컬렉션 보호 테스트는 새 실행 상태의 외부 수정 방지까지 확장한다. 기존 26개 검증의 의미를 보존하되 구조 변경으로 필요한 assertion/이름 변경은 기록한다. 검사 수를 유지하는 것 자체를 완료 기준으로 삼지 않는다.

## 조작 방식 추천

| 행동 | 조작 | 화면과 규칙 |
|---|---|---|
| 정착민 선택 | 삼각형 좌클릭 또는 오른쪽 정착민 목록 클릭 | 선택 테두리, ID·좌표·상태·목적지 표시. 겹친 위치 클릭은 가장 작은 ID 선택, 목록으로 나머지 선택 |
| 선택 해제 | 빈 타일 좌클릭 또는 Esc | 선택/경로 강조만 해제. 진행 중 이동은 유지 |
| 이동 지정 | 선택 상태에서 맵 타일 우클릭 | 목적지·경로 표시. 명령 대기와 이동 중을 구분 |
| 이동 중지 | Stop 버튼 또는 X | 다음 Tick에서 현재 논리 타일에 정지. 선택 유지 |
| 정지/재개 | Pause/Resume 또는 Space | 마지막 1배속/3배속으로 재개 |
| 배속 선택 | 1×/3× 버튼 또는 숫자 1/3 | 선택 배속 표시, 실행 상태로 전환. 정지 중 누르면 그 배속으로 재개 |
| 한 Tick 진행 | Step +1 버튼 또는 마침표(.) | 정지 중에만 활성. 선택 배속과 무관하게 정확히 1 Tick |
| 초기화 | Reset 버튼 | 초기 배치·Tick 0, 명령·경로·진행·잔여 시간·선택·실패 메시지 제거. 정지 여부와 선택 배속은 유지 |

UI 위의 우클릭, 맵 밖 클릭, 선택 없는 우클릭은 이동 명령을 만들지 않는다. 단축키는 키를 누른 순간 한 번만 처리하며 UI 텍스트 입력이 도입되면 입력 포커스에서 제외한다. 마우스와 단축키는 같은 명령 경로를 사용해 한 입력이 두 번 처리되지 않게 한다.

정지 중에도 선택·목적지 예약은 가능하다. 위치·경로 진행은 변하지 않고 Pending 상태만 표시한다. 재개 또는 Step에서 명령을 적용한다. 명령 취소도 같은 규칙을 따른다. 빈 화면 클릭은 명령 취소와 구분한다.

## 이동과 명령 규칙 추천

- 4방향, 타일 비용 동일. 이웃 탐색 순서 동→북→서→남으로 고정한 BFS(너비 우선 탐색)를 권장한다. 최단 거리와 동률 경로를 반복 재현할 수 있다. 8×8에서는 구현·검증이 단순하다. 64×64/다수 요청에서 비용을 측정한 뒤 A* 전환을 검토한다. 대각 이동은 코너 통과 규칙이 추가되므로 이번에는 제외한다.
- 논리 위치는 정수 타일. 한 칸 이동에 5 Tick: 1배속 0.5초, 3배속은 명목상 약 0.167초. 테스트용 초기 수치이며 게임 내 하루 길이·최종 이동 밸런스는 확정하지 않는다.
- 이동 진행은 0~4의 정수. 명령이 적용되는 Tick을 첫 진행 Tick으로 센다. 4 Tick까지 출발 타일, 5 Tick에서 다음 타일로 이동하고 진행 0. 도착 시 경로와 잔여 진행을 비우고 Arrived 표시.
- 첫 구현은 논리 타일 위치를 그대로 표시한다. 부드러운 보간은 포함하지 않는다. 화면 Transform이 시뮬레이션 위치를 결정하지 않으며 이후 보간 추가도 표시 계층에 한정한다.
- 장애물만 통행을 막는다. 자원과 다른 정착민 타일은 통과·겹침 허용. 자원 수량은 변하지 않는다. 이는 생활용 자원·침대 예약을 생략하겠다는 뜻이 아니며 해당 점유 규칙은 작업 2에서 별도 검증한다.
- 명령은 World 소유 대기열에 수신 순서를 기록하고 다음 Tick 시작에서 적용한다. 같은 정착민에 한 Tick 전에 여러 이동/중지 명령이 들어오면 수신 순서대로 실행 가능성을 판정하고 마지막 유효 명령을 남긴다. 실패 명령은 직전 유효 명령을 취소하지 않으며 중간 명령 처리 중 위치를 움직이지 않는다. 정착민 갱신 순서는 ID 오름차순이다.
- 유효하지 않은 ID·맵 밖·장애물 목적지는 접수 단계에서 이유와 함께 거부하며 기존 명령을 덮어쓰지 않는다. 실행 시점에는 통행과 경로를 재검사한다. 도달 불가 새 명령도 이전 유효 이동을 유지하고 거부 사유를 표시한다.
- 이동 중 다른 목적지 재지정은 현재 논리 타일에서 새 경로를 찾고 칸 진행을 0으로 재시작한다. 같은 활성 목적지 반복 지정은 진행과 경로를 초기화하지 않는다. 현재 타일 지정은 제자리 도착으로 완료한다. Stop은 현재 타일에서 경로·목적지·진행을 지운다.
- 상태 표시: Idle(대기), Pending(접수됨), Moving(이동), Arrived(도착), Blocked(길 막힘). 명령 거부 사유는 상태와 별도 필드로 표시해 기존 이동이 유지됨을 알린다.

## 경로 변화와 재개

초기 맵은 고정이다. 건설 도구나 장애물 편집 UI는 만들지 않지만 테스트에서 통행 변경을 주입할 수 있는 시뮬레이션 명령 경계를 준비한다.

통행 변경은 Tick 시작에 이동 명령보다 먼저 적용한다. 월드 밖 변경 또는 현재 정착민이 서 있는 타일을 막는 변경은 거부한다. 통행 revision이 바뀌면 활성 목적지의 경로를 현재 타일부터 다시 계산하고 칸 진행을 0으로 한다. 우회 가능하면 계속 이동, 불가하면 목적지를 보존한 Blocked 상태로 정지한다. 다음 통행 revision 변경 또는 새 명령에서 재검사하며 매 프레임 같은 실패 경로를 다시 찾지 않는다. 길이 열리면 원래 목적지로 자동 재개한다.

이번에는 테스트 전용 통행 변경이며, 사용자가 Windows 화면에서 벽을 생성·제거할 수 있다고 설명하지 않는다.

## 시간 규칙과 수치 검사

1배속 10 Tick/현실 초, 3배속 30 Tick/현실 초를 목표로 한다. 실제 프레임 측정 시간의 float 오차와 지연은 있으므로 정확성은 명시적으로 공급한 decimal 시간·명령 순서로 검사한다. 게임 시간의 1 Tick 길이는 언제나 0.1초다.

정지 중 경과 시간은 누적하지 않고 기존 게임 시간 잔여만 유지한다. 배속 변경도 기존 잔여를 유지한다. Step은 잔여 시간과 무관하게 1 Tick을 추가하고 잔여를 소비하거나 늘리지 않는다. 예: 1배속 0.05초 → Tick 0/잔여 0.05; 정지 10초 → 그대로; 3배속 0.05초 → 게임 시간 0.15가 더해져 Tick 2/잔여 0.

Step(100)과 100회 Step(1)의 위치·경로·진행·명령 결과가 같아야 한다. 대량 Tick을 숫자만 더하는 지름길로 처리하지 않는다. 현재 8×8·3명 범위에서는 Tick을 버리는 프레임 상한을 도입하지 않는다. 처리 시간 문제가 측정되면 처리 예산과 이월 규칙을 따로 설계한다. 향후 중간 Tick에 들어오는 명령을 한 번에 건너뛰지 않는다.

T1-03은 차단 시점 정착민이 x=3에 없는 fixture로 구성한다. 통행 변경 자체가 점유 타일 거부 규칙에 걸려 실패한 것을 길 막힘 성공으로 오인하지 않는다. T1-09의 PlayMode는 좌표 변환·입력 경계·이벤트 경로 검사이며 OS 마우스 자동화를 사용하지 않는다.

에이전트는 EditMode/PlayMode, Windows CLI build/smoke, 실제 렌더 PNG 검토를 실행할 수 있다. 사용자는 실제 클릭·키보드·배속 체감·이유 표시의 이해도를 확인한다. 계획 작성 시점에는 실행하지 않았으며 이후 실제 실행 결과는 검증 기록으로 구분한다.

## 구현 후 사용자 확인 6단계

후속 구현 완료 시 실행 파일 E:\Dev\RimworldTweak\Builds\Windows\RimworldTweak.exe를 다시 빌드해 안내한다. 최신 실행 파일에는 아래 이동 기능이 포함된다.

1. 정착민 선택 후 빈 타일 우클릭: 해당 정착민만 경로를 따라 도착하고 선택·목적지를 구분할 수 있다.
2. 장애물을 돌아가야 하는 위치 지정: 장애물 통과 없이 우회한다. 장애물 타일 자체 클릭은 오류 이유를 표시한다.
3. Pause 후 목적지 지정: 위치는 그대로, 예약 표시. Step 5회로 한 칸 이동한다.
4. 1×/3×와 Space·숫자 키 조작: 표시 속도와 실제 진행이 맞고, 정지에서는 이동하지 않는다.
5. 이동 중 재지정·Stop, UI 위 우클릭: 명령이 정확히 한 번 적용되고 UI 클릭은 맵 이동으로 새지 않는다.
6. 이동·정지 중 Reset 반복: 배치·선택·경로·상태가 초기화되고 겹친 표시나 남은 명령이 없다.

답변 예: “모두 정상”, “3배속에서 Pause 후에도 이동함”, “UI 위 우클릭이 맵 명령으로 처리됨”. 자동 통과와 사용자 확인을 모두 기록한 후 작업 1의 완료를 판단한다. 현재 구현·자동 검증 결과는 [작업 1 검증 기록](../Verification/2026-11-15-movement.md)을 따른다. 새로운 이동 조작의 사용자 확인은 별도 기록한다.
