# 저장·UI·아트 요구사항과 완료·검증 기준

작성: 2026-11-17. 문서 상태: 독립 검토·교차 의견·재검토 반영 완료. 제품 구현·수락 검증은 진행 중이며 전체 기능 완료로 판정하지 않았다. 아래 완료조건과 검사 계획의 실제 이행 결과는 [현재 상태](../Status.md)와 [진행 검증 기록](../Verification/2026-11-17-save-ui-art-progress.md)을 따른다. 작성 당시의 도구·미실행 설명은 계획 수립 시점의 배경이며 최신 실행 상태가 아니다.

## 1. 범위와 판정 원칙

기준: [전체 계획](SaveLoad-UX-Art.md), [아트 인계](../Art/Handoff.md), [프로토타입 우선 지침](RimWorld-Performance-Application.md), [현재 상태](../Status.md). 이 문서는 다음 구현의 수락 기준을 구체화한 제안 명세다. 사용자 확정 범위와 여기서 구체화한 기본값을 구분한다. 문서 승인·검토를 제품 구현 성공으로 취급하지 않는다.

확정 범위: 저장·불러오기 경험, 림월드식 UI·조작 정리, 간결한 탑다운 2D 아트. 자급 유지 플레이테스트는 제외하며 새로운 전투·생산·생활 규칙을 추가하지 않는다. 임시 그림 후 교체 의도를 반영하되 RimWorld 원본 사용 조건은 미확정이다.

이번 제안의 기본값: 수동 다중 슬롯+이어하기, 기존 파일 읽기 유지, 단일 정착민 선택, 기존 R/Space/1/3 유지, 구역 드래그, uGUI 유지+맵 월드 표시. 자동 저장/클라우드/슬롯 삭제/썸네일/F5·F9/다중 선택/설정 가능한 키 재지정은 제외한다. UI 설정은 배율 100/125/150%로 한정한다. 날짜·계절·예상 식사 일수 같은 새 계산은 넣지 않고 기존 게임 경과와 배속을 표시한다.

완료 단계는 `작성 중 → 구현 완료·미검증 → 자동 기능 검증 완료 → 실제 렌더 확인 → 사람 조작 확인 → 기능 완료`로 구분한다. 기능별 필요한 층만 적용한다. 파일 내부 기능은 자동 검사로, 가독성·조작 기능은 렌더와 사람 확인까지 충족해야 전체 완료다. 사람 확인 대기는 다른 독립 기능 작성이나 대표 Player 성능 측정을 막지 않는다.

중요 실패: 저장본 손상/현재 진행 유실, 중복 명령·생산·소비, 기존 파일 복원 실패, 잘못된 칸 선택, 필수 UI 접근 불가, 아트 교체에 따른 게임 규칙 변경. 하나라도 남으면 해당 기능 완료 불가. 시각 결함도 필수 대상 식별을 막으면 필수 실패다. 장식 품질 보완은 잔여 목록으로 분리할 수 있다.

## 2. 요구사항과 관측 가능한 완료 조건

### S1. 이름 있는 저장과 목록

- 요구사항: 별도 슬롯ID와 표시 이름을 사용한다. 새 저장/선택 슬롯 덮어쓰기를 구분하며 저장 목록은 이름·저장 시각·게임 Tick/경과·정착민 수·읽기 상태를 표시한다.
- 제안 입력 규칙: 앞뒤 공백 제거 후 1~40 Unicode 텍스트 요소. 허용 집합은 한글 완성형(U+AC00~D7A3), 한글 호환 자모(U+3131~3163), ASCII 인쇄 문자(U+0020~007E)다. 미지원 문자·제어문자는 저장 전에 이유를 안내하고 거부하며 이름을 조용히 바꾸지 않는다. 필수 검사 corpus는 `한글 ㄱㅏ Save 01 -_()[]/!`와 40/41요소 경계, emoji/결합문자 거부다. 중복 이름은 허용하며 ID가 다르면 다른 슬롯이다. 이름은 경로에 사용하지 않는다. 목록 순서는 저장 시각 내림차순, 동률은 슬롯ID순이다.
- 덮어쓰기는 대상 이름·저장 시각을 보여주고 확인/취소를 받는다. 파일명 ID와 외피 slotId가 다르거나 ID가 중복된 입력은 오류 항목으로 표시하고 로드·덮어쓰기를 거부한다. 디스크 경로는 신뢰하는 저장 루트와 검증된 파일명으로만 정한다. payload에서 계산할 수 있는 Tick·정착민 수 요약이 불일치하면 거부하며 표시명·저장 시각은 이 일치 검사에서 제외한다.
- 문자 검증은 IME 조합 중이 아니라 확정된 문자열에 수행한다. 저장 이름은 일반 텍스트로 표시하여 `<b>A</b>`나 `<size=0>A`를 서식으로 해석하지 않는다. 리치텍스트 해석을 끄거나 출력 경계에서 이스케이프하고 원래 저장명은 보존한다.
- 완료 조건: 같은 이름 A/B에 다른 진행을 저장하고 각각 선택해 정확한 진행으로 복원된다. A 덮어쓰기는 A만 바뀌며 B의 파일 해시는 동일하다. 저장 목록을 다시 열거나 앱을 재실행해도 두 슬롯이 나타난다.
- 메타데이터와 상태는 하나의 버전 있는 외피에 기록한다. 목록의 요약은 복원 보증이 아니다. 실제 불러오기에서 전체 상태 검증을 수행한다. 전체 파일 크기 제한은 기존 16MiB를 유지한다.
- 검사: V-S01, V-S02, V-S03. 파일 서비스/목록 자동 검사와 저장 화면 렌더, 수동 M1.

### S2. 기존 파일과 진행 중 작업 복원

- 요구사항: 기존 `settlement-v1.json`을 읽을 수 있다. 새 저장 형식으로 저장할 때 기존 원본을 자동 삭제/변환/덮어쓰지 않는다. 상태 payload의 규칙 버전과 목록 외피 버전을 분리한다.
- 완료 조건: 기존 파일 fixture의 Tick·시간 잔여·배속·정지·ID·욕구·작업 단계·진행·물자·점유·예약·필터·개인 설정이 복원되고, 같은 후속 명령/Tick에서 원본과 결과가 일치한다. 현재 코드로 새로 저장한 파일만으로 과거 호환을 판정하지 않는다.
- 유효 경로는 기존 진행을 유지한다. 무효 경로는 현재 복원 정책대로 후보 안에서 정리하며 운반물은 한 번만 낙하한다. 화면 선택/도구는 성공 시 초기화하고 실패 시 유지한다.
- 검사: V-S04, V-S05, V-I03. 기존 저장 왕복 검사 재사용+실제 파일+새 UI 경로.

### S3. 저장 실패·중복 요청의 보존

- 요구사항: 캡처→임시 파일 기록→재읽기/복원 검증→최종 교체의 기존 안전 경로를 유지한다. 최종 파일 삭제 후 재작성 fallback은 금지한다. 실패 원인을 사용자 문구로 표시한다.
- 완료 조건: 기존 슬롯을 준비하고 기록/재읽기/교체 실패를 각각 유도하면 기존 파일의 바이트가 같고 현재 Session과 게임 상태도 바뀌지 않는다. 성공하지 않은 신규 슬롯은 목록에서 정상 슬롯으로 나타나지 않는다. `.tmp`는 슬롯 목록에서 제외한다.
- 동시에 수락하는 파일 요청은 1개다. 저장·불러오기 중 UI와 종료의 추가 요청은 거부하고 두 번째 파일 변경이나 상태 교체가 없어야 한다. 동기 구현에서는 잠금 경로 단위 검사로 검증하고 실제 중간 프레임이 존재한다고 주장하지 않는다.
- 사용자 설정 파일만 실패한 경우 정착지 저장 성공과 최근 슬롯/설정 실패를 분리해 알린다. 게임 저장 성공을 실패로 오인해 중복 신규 슬롯을 만들지 않는다.
- 기존 `SavePendingCommands` 캡처 거부를 유지한다. 미적용 명령이 있으면 파일·Tick·대기 명령·선택을 보존하고 메뉴를 닫아 사용자가 재개한 뒤 재시도하도록 안내한다. 저장을 위해 자동으로 Tick/StepOnce를 진행하지 않는다. 원래 Pause 상태는 메뉴 취소로 해제하지 않는다. 기존 `QueueSetBlocked` fixture를 검사에 재사용한다.
- 검사: V-S06, V-S07. 실패 주입은 작은 파일 작업 경계/테스트 대역 또는 격리된 잠금 파일을 사용하며 실제 서비스 경로도 검사한다. 디스크 전체 채우기나 사용자 파일 권한 변경은 하지 않는다.

### S4. 시작·이어하기·종료 흐름

- 요구사항: 시작 화면에 새 정착지/이어하기/불러오기/설정/종료를 제공한다. 새 정착지는 기존 시나리오다. 저장이 없으면 이어하기 비활성과 이유를 표시한다.
- 이어하기는 마지막 성공 슬롯을 우선한다. 해당 파일이 사라지거나 손상되면 이유와 목록을 보여주고 다른 진행으로 자동 진입하지 않는다. 최근 슬롯 기록만 없으면 최신 후보를 목록에서 선택 표시하고 확인 후 로드한다.
- 진행 중 새 정착지/메인 메뉴/종료는 취소·저장 후 계속·저장하지 않고 계속으로 구분한다. 저장 실패 시 전환/종료하지 않는다. 처음 저장하는 세션은 저장 화면에서 이름과 대상을 선택한다. 취소하면 현재 게임으로 돌아간다.
- 진행 중 다른 슬롯을 불러오기 전 대상 이름·저장 시각과 미저장 진행 소멸을 안내하고 확인/취소를 받는다. 취소는 파일 읽기와 상태 교체를 시작하지 않으며 Session·시간·선택·활성 저장 대상을 유지한다. 확인 후 파일 손상 등으로 실패해도 기존 진행을 유지한다.
- 새 정착지 시작 시 현재 세션의 활성 저장 대상을 비운다. 이어하기용 최근 슬롯 기록은 보존할 수 있지만 새 세션 저장 대상으로 사용하지 않는다. 첫 저장은 새 슬롯 생성으로 안내하며 기존 슬롯은 사용자가 별도 선택하고 덮어쓰기를 확인해야만 변경할 수 있다.
- 활성 저장 대상은 마지막으로 성공한 새 형식 저장/불러오기 슬롯이다. A를 불러온 후 B로 새 저장하면 B가 대상이다. legacy 파일을 불러온 세션은 원본 보호를 위해 새 슬롯 선택으로 연결한다. 저장 후 전환에서도 기존 슬롯 덮어쓰기는 S1 확인을 거친다. 설정 파일만 실패하고 정착지 파일 저장은 성공한 경우에는 전환/종료를 진행하고 경고를 기록한다. 다음 실행에서 최근 기록이 없으면 목록으로 복구한다.
- 최근 슬롯 A가 기록된 채 B 저장 성공/설정 갱신 실패가 발생하면 A 기록이 남을 수 있다. 경고는 `게임은 B에 저장됐지만 이어하기 대상 기록은 갱신되지 않았어. 다음 실행에는 불러오기 목록에서 B를 선택해줘.`처럼 저장 대상과 다음 행동을 밝힌다. 전환 전에 경고를 확인할 수 있게 하고, 정상 저장한 B를 자동으로 추측하는 복구 기능은 추가하지 않는다.
- 완료 조건: 실제 프로세스 종료 후 재실행해 해당 슬롯을 복원한다. 저장 후 종료 실패에서는 프로세스와 정착지가 유지된다. 종료 검사는 종료 요청 기록과 실제 정상 프로세스 종료를 별도로 확보한다.
- 검사: V-S08, V-S09, V-P01. 수동 M1.

### U1. 메뉴·텍스트 입력·시간 정지

- 요구사항: 입력 우선순위는 파일 처리 차단→확인창→텍스트 입력→UI→활성 도구→맵이다. 사용자 Pause와 메뉴/확인창 차단은 별도로 관리한다.
- 완료 조건: 정지/실행 × 1/3배속에서 메뉴와 확인창을 열고 닫아도 원래 사용자 정지·배속이 유지된다. 메뉴/확인창이 열린 동안 양의 unscaledDeltaTime을 누적해 1배속 기준 최소10Tick에 해당하는 시간을 입력해도 자동 Tick 증가0. 차단 해제 후 같은 시간 입력에서는 실행 상태일 때 Tick이 증가하고 사용자 Pause이면 그대로다. 성공한 불러오기는 저장 당시 시간 설정을 적용한다. 취소/실패는 현재 시간 설정을 유지한다.
- 이름 입력 중 R/Space/1/3/WASD를 입력해도 소집·시간·카메라가 변하지 않는다. 확인창 뒤의 지도와 메뉴는 입력을 받지 않는다. 파일 I/O 때문에 걸린 시간이 복원 직후 게임 Tick으로 몰려 들어오지 않는다.
- Esc는 확인창→도구→열린 패널→선택→게임 메뉴 순으로 한 단계만 처리한다. 패널 탐색과 선택만으로 시간이 정지하지 않으며 게임 메뉴/확인창만 자동 진행을 막는다.
- 한글 IME 조합 중 Esc/Enter는 조합 취소/확정에 우선 사용하고 같은 입력으로 메뉴 닫기/저장을 수행하지 않는다. 자동 조합 이벤트 검사와 실제 Windows IME의 사람 확인은 별개다.
- 드래그/키 홀드 중 메뉴 열기·Load/Reset·앱 포커스 상실 시 진행 중 제스처를 취소한다. 뒤늦은 release로 배치/이동/소집하지 않으며 정상 복귀 후 새로 누른 입력은 한 번 동작한다. 로드 실패 시 기존 선택/카메라는 유지하되 미완료 제스처는 되살리지 않는다.
- 검사: V-U01, V-U02, V-U11. 입력 이벤트 경로와 상태 관측, 수동 M1/M2.

### U2. 맵 탐색·대상 선택

- 요구사항: 휠 확대/축소, 중간 버튼 드래그/WASD 이동, 맵 경계 제한. UI 위 휠은 해당 스크롤에만 전달한다. 카메라 한계·드래그 임계값은 아래 시각 샘플 단계에서 기준값으로 기록한다.
- 완료 조건: 맵 모서리/중앙과 최소/기본/최대 줌에서 화면 좌표→칸 변환이 기대 칸과 같다. UI 위 누름/드래그/휠은 맵 선택·이동·배치·줌을 일으키지 않는다. 맵 밖 클릭은 명령을 만들지 않는다.
- 단일 정착민 선택, 초상 클릭 선택/더블클릭 카메라 이동, 같은 칸 대상 목록 전환을 제공한다. 목록은 안정적인 종류/ID 순이며 사라진 대상은 선택에서 정리한다. 선택만으로 작업이 취소되지 않는다.
- 우클릭은 도구 취소를 먼저 처리하고 같은 입력으로 이동하지 않는다. 도구가 없을 때 소집된 정착민만 이동한다. 미소집은 안내만 표시하고 기존 자동 행동/점유를 보존한다.
- 검사: V-U03, V-U04. 수동 M2.

### U3. 선택 정보·작업표·문제 안내

- 요구사항: 정착민/시설/자원/구역의 선택 정보를 실제 상태에서 읽는다. 작업표는 3명×채집/운반/건설/농사/조리, 끔/1/2/3과 1 우선 안내를 제공한다. 숫자 변경은 기존 작업 유지, 끔은 해당 작업 즉시 취소한다.
- 완료 조건: 정지 상태에서 설정 변경 후 다음 UI 갱신 프레임에 표시가 일치하고 Tick은 그대로다. 생활·소집 우선권과 운반 취소 시 한 번 낙하가 유지된다. 조리대에는 입력/진행/출력/목표/보류 이유가 실제 값으로 나타난다.
- 자원 요약은 전체 수량의 범위를 명시하고 보관·운반·공정 투입을 중복 합산하지 않는다. 정의되지 않은 예측 일수나 새 식량 경고 규칙을 추가하지 않는다.
- 문제 안내는 기존 진단의 재료 부족/담당자 없음/접근 불가/출력 포화/목표 도달을 사용한다. 목표 도달은 정상 상태로 표시한다. 같은 원인+대상ID는 한 항목으로 갱신하며 해소 후 다음 표시 갱신에 정리한다. 클릭은 대상을 선택/카메라 이동하고 작업을 자동 취소하지 않는다.
- 검사: V-U05, V-U06. 대표 원인별 UI 값/명령 검사, 수동 M3.

### U4. 건설·구역 도구

- 요구사항: 기존 시설4종·목재 비용·설계도 취소·철거, 저장/경작 지정과 필터/파종 설정을 새 UI로 연결한다. 건설 도구는 한 번 배치 성공 후 해제한다. 구역은 드래그로 미리보기 후 놓을 때 한 번 확정하고 성공 후 해제한다.
- 완료 조건: 유효/불가 위치에 색+이유 표시, 실패는 물자·ID·지정 상태를 바꾸지 않는다. 미리보기만으로 게임 상태를 수정하지 않는다. 우클릭/Esc 취소는 명령 0회다. UI 위/맵 밖에서 드래그를 끝내면 취소하고 부분 구역을 만들지 않는다. 역방향 드래그는 같은 사각형을 만든다.
- 1칸 지정은 누르고 같은 칸에서 놓기로 가능하다. 드래그 중 UI로 진입해도 UI 버튼을 클릭한 것으로 처리하지 않는다. 도구 동작 중 미소집/소집 규칙을 우회하지 않는다.
- 아래 기존 명령 이관표의 모든 명령이 새 화면에서 접근 가능해야 한다. 정지 중에는 명령과 표시만 즉시 적용되고 자동 작업은 다음 Tick에서 진행된다. 명령 삭제/취소의 물자·작물·투입 재료 처리 규칙은 기존 구현과 같아야 한다.
- 검사: V-U07, V-U08, V-U11. 수동 M3.

### A1. 교체 가능한 기준 샘플

- 요구사항: 정착민/나무/침대/지면/선택 패널을 같은 실제 Unity 장면에서 비교한다. 현재 도형·임시 그림·최종 그림을 구분하고 에셋별 출처/원본/표시용 PNG/규격/검토 상태를 기록한다.
- 완료 조건: 시점·팔레트·외곽선·광원, 표시 크기·pivot(바닥 접점)·PPU, 최소/기본/최대 카메라 줌을 기준표로 고정한다. 초안 128 PPU는 고정값이 아니라 샘플 후보이며 선택된 값만 구현 기준이 된다.
- 에셋 기준표에 작성자가 정한 이미지 내부 바닥 기준점(ground anchor)을 기록한다. 같은 카메라·해상도·Tick에서 크기가 다른 대체 그림으로 교체하고 이 기준점을 화면으로 투영했을 때 위치 차이는 1px 이내이며 논리 위치·선택 칸·통행·사용 칸·저장 서명이 같다. 투명 영역 최하단을 자동 발바닥으로 추정하지 않는다. 실제 발/시설 밑면과 기준점의 정합은 PNG/사람 확인으로 별도 검사한다. 비교용 대체 그림은 검사용이며 최종 아트로 세지 않는다.
- 샘플 채택 시 카메라 줌/경계/드래그 임계값과 비교 장면을 기록한다. 이후 식별성 실패를 숨기려고 줌 범위만 줄이지 않는다. 기준값 변경은 이유를 남기고 U2/A2를 다시 검사한다.
- RimWorld 원본 사용 조건 미확정과 PSD 색상 이상3종은 별도 미해결로 기록한다. 임시 구현을 막으면 기존 도형/자체 샘플로 진행한다. 허용 여부를 추정하거나 문제 PSD를 정상 에셋으로 표시하지 않는다.
- 검사: V-A01, V-A02. 실제 렌더 정적 검토+수동 M4. 샘플 채택이 전체 아트 완료는 아니다.

### A2. 현재 기능의 아트 전체 연결

- 요구사항: 정착민 앞/뒤/옆·3명 식별·초상·운반/수면, 시설4종·설계/철거, 나무/채집 식물·작물 성장3표현, 물자3종, 지면·저장/경작, 선택·소집·부족·UI를 목록과 실제 사용처에 대응한다.
- 벽의 4방향 연결16조합을 표현한다. 첫 묶음의 문은 정적 그림으로 표시하며 개폐 연출은 선택적 후속으로 유보한다. 현재 통행 가능한 규칙을 바꾸거나 잠금 상태를 추가하지 않는다. 성장3표현은 Growing의 0~1199/1200~2399와 Mature를 제안 기준으로 삼아 기존 GrowthTicks와 Mature에서 읽는다. 새 작물 enum/성장 수치를 추가하지 않으며 샘플에서 시각 전환점을 조정하면 기준표와 경계 검사를 함께 갱신한다.
- 완료 조건: 목록의 필수 키가 전부 연결되고 누락은 개발 오류로 검출된다. 실제 화면에서 물자3종과 작물3표현을 최소 줌에서도 형태로 구분한다. 지면3×3 반복의 틈/투명 선, 벽16조합의 끊김, 이름/운반물/선택 표시 가림이 없다. 사람 확인 전 식별성은 정적 확인 단계로만 기록한다.
- 정지 시 이동/작업 연출은 멈추고 UI 호버는 반응한다. 동일 Tick 상태를 임시/최종 그림으로 표시해도 게임 상태와 저장 복원 결과가 같다. 수량·이름·진행·선택은 원화에 포함하지 않는다.
- 완료를 임시 아트 연결과 최종 독자 아트 적용으로 나눈다. 후자의 전체 완료에는 필수 키의 독자/사용 조건 확인된 최종 에셋, 출처 기록, 실제 렌더/사용자 확인이 필요하다.
- 검사: V-A03, V-A04, V-I03. 수동 M4.

### U5. 읽을 수 있는 화면과 설정

V-S05의 진행 사례는 sleep/운반/시공은 상태 단계에서 정지시키고, 성장2399/2400·조리39/40 등 기존 경계도 포함한다. 완료를 기다리는 상한은 해당 fixture의 경로 길이/이동·작업 시간과 생활 상태로 계산하여 기록한다. 무한 대기나 임의 짧은 timeout으로 판정하지 않는다. 이 짧은 진행 복원 검사는 자급 테스트가 아니다.

V-S09에는 두 필수 하위 사례를 추가한다. (1) A 진행 중 B 불러오기에서 취소/확인/손상 B를 각각 검사한다. 취소는 파일 읽기 요청0회와 A의 Session·시간·선택·활성 대상 보존, 성공은 B 복원, 실패는 A 보존이 기대 결과다. (2) A 로드→새 정착지→첫 저장에서 활성 대상이 비워지고 새 슬롯이 생성되며 A 파일 hash가 변하지 않아야 한다.

상태 비교는 게임의 정규화된 저장 데이터와 물자 장부·ID·점유/예약을 사용한다. 아트 참조·UI 선택·실시간 저장 시각은 게임 상태 서명에서 제외하되 선택/카메라 보존 요구는 별도 비교한다. 생산/소비 총량만 같고 다른 작업자가 점유한 오류를 놓치지 않도록 전체 관련 상태를 함께 확인한다.

V-I03은 현재 표시/선택/리스너의 수명 확인이며 전역 메모리 누수가 없다는 증명이 아니다. Reset은 새 초기 상태와, Load는 저장 상태와 각각 비교한다. Reset 후 상태를 이전 진행과 같다고 요구하지 않는다. 캡처·정적 확인을 수행한 해상도/화면 조합과 수행하지 않은 조합을 결과에 구분한다.

## 4. 사람 확인과 실행 안전

아래는 사람 확인 명세다. 현재 빌드 식별·정확한 실행 파일 경로·격리 저장 경로와 단계별 기대 결과는 [사람 확인 카드](../Verification/2026-11-17-manual-acceptance.md)를 따른다. 아래 계획만으로 사람 확인을 완료 처리하지 않는다.

1. M1 저장: 실제 Windows 한글 IME로 이름 조합/취소 후 두 슬롯 저장→각각 불러오기→정상 종료/재실행. 조합 중 Esc/Enter로 메뉴/저장이 실행되지 않고 이름·시간·설정·진행이 선택한 슬롯과 일치해야 한다. 취소하면 현재 진행 유지.
2. M2 탐색: 작은 해상도/큰 UI와 기본 해상도에서 초상 선택→맵 이동/줌→UI 스크롤→메뉴 취소. 클릭 대상·카메라·시간이 의도대로 동작해야 한다.
3. M3 작업: 조리대를 선택해 목표 확인→작업표 끔/켬→건설 배치/취소→저장/경작 구역 드래그. 안내와 결과가 일치하고 중복 명령이 없어야 한다.
4. M4 아트: 세 정착민·세 물자·성장 단계 식별→나무 뒤 선택→축소/확대→정지. 이름/선택/행동이 읽히고 접점이 흔들리지 않아야 한다.

회신 예: `M1~M4 모두 정상` 또는 `M2: 작업표 위 휠로 맵도 확대됨`. 판단이 필요한 스타일 선호는 결함과 분리해 적는다. 수동 확인을 수행하지 않으면 `사람 확인 대기`로 남긴다.

에이전트는 파일/CLI/Unity 테스트·Editor 스크립트/실제 Player/생성 PNG 정적 검토까지 가능하다. 데스크톱·브라우저 UI 자동화는 금지한다. Unity 입력 이벤트 검사는 사람 손 조작 증거가 아니다. Unity 실행은 통합 담당 한 명이 직렬 수행하고 대상 입력을 동결한다. 열린 에디터 강제 종료/잠금 삭제 금지. 모든 저장 검사는 격리한 임시 루트에서 수행하며 사용자 실제 슬롯은 수정하지 않는다.

## 5. 실행 순서와 완료 기록

### 기존 도구 재사용과 필요한 확장

현재 `Tools/Run-Tests.ps1`은 EditMode/PlayMode를 `-nographics`로 실행하므로 렌더 증거로 쓰지 않는다. `Tools/Run-Demo.ps1`은 Prepare/Build/Smoke와 1280×800 단일 실행을, `Tools/RenderValidation.ps1`은 고정 이미지 크기 판정을 제공한다. 새 12조합과 프로세스 재실행은 아직 제공되지 않는다.

구현할 검사 지원은 다음으로 한정한다. 기존 Runner에 해상도/배율/화면 시나리오/격리 저장 루트 입력과 출력 규격 검사 추가, 프로세스 A 저장·정상 종료→프로세스 B 같은 테스트 루트 로드의 두 단계 실행/보고 추가, 신규 테스트 manifest와 기존 관측 조건 대응표 추가. 별도 성능 프레임워크나 브라우저 UI 자동화는 만들지 않는다. 실제 CLI 인수는 이 확장 구현 후 문서화하며 현재 명령처럼 안내하지 않는다.

V-U02/U08/U11은 `Button.onClick` 직접 호출만으로 통과시키지 않는다. Input System 이벤트→EventSystem의 UI 적중 판정과 실제 handler→게임 명령/상태까지 검사한다. 순수 명령 단위 검사는 별도로 유지한다. 렌더 크기/색 개수 판정은 가독성 증거가 아니므로 PNG 내용 정적 검토를 함께 남긴다.

하나의 V-ID 안에 묶인 모든 필수 분기와 조합은 실제 테스트명 또는 수동 사례명으로 대응시킨다. 결과 표의 최소 열은 `요구사항ID | V/M-ID | 하위 사례/조합 | 실제 테스트명·절차 | 기대값 | 관측값 | 증거 경로 | 판정`이다. 미실행·실패·환경 차단을 통과와 구분하며 한 하위 사례 통과로 V 전체를 통과 처리하지 않는다. V-U09는 12조합×8화면의 배치 검사 96사례와 별도 PNG 검토 범위를 기록한다. 해당 요구사항에 연결된 필수 자동·렌더·사람 확인이 모두 충족되어야 기능 완료로 판정한다.

후속 단계에서 그림이나 입력을 바꿨으면 영향 검사와 관련 렌더를 다시 확인한다. 사소한 문서 수정만으로 전체 Unity 검사를 반복하지 않는다. 성능 목표 수치는 현재 완료 조건으로 고정하지 않으며 프로토타입 실행 후 실제 문제만 측정·수정한다.

## 6. 이번 문서의 검토 상태

세 독립 검토자의 의견과 교차 의견·재검토를 반영했다. 채택·구체화·유보 이유는 [검토 기록](../Reviews/2026-11-17-save-ui-art-acceptance-review.md)을 따른다. 이번 문서 재검토에서는 제품 코드·아트를 변경하거나 Unity 검사를 실행하지 않았다. 작업 공간의 기존 구현 초안과 문서 검토 결과는 구분한다. 기술 기본값은 검토된 제안이며 사용자 확정으로 승격하지 않는다.
