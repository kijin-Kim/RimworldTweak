# 저장·불러오기, 정착지 UI·조작, 탑다운 2D 아트 계획

작성: 2026-11-17. 이 문서는 설계 배경과 계획을 보존한다. 현재 구현·검증은 진행 중이며 최신 결과와 남은 항목은 [현재 상태](../Status.md)와 [진행 검증 기록](../Verification/2026-11-17-save-ui-art-progress.md)을 따른다.

후속 구현의 기능별 요구사항·관측 가능한 완료 조건·검사 입력과 기대 결과는 [수락 및 검증 기준](SaveLoad-UX-Art-Acceptance.md)을 따른다. 이 전체 계획은 설계 배경이며, 세부 입력 정책/최초 문 정적 표현/기능 이관표 등은 수락 기준의 최신 구체화가 우선한다. 사용자 확정 범위와 제안 기본값은 구분한다.

## 1. 확정 범위와 제안의 구분

2026-11-17 성능 적용 기준: 이 계획의 프로토타입 사용 흐름 구현을 먼저 진행한다. [프로토타입 우선 성능·구조 지침](RimWorld-Performance-Application.md)에 따라 기존 책임과 수명을 보존하되 캐시·전용 계측·검색 개선을 선행 작업으로 추가하지 않는다. 아래 성능 관찰은 연결된 대표 실행 이후 수행하며 실제로 기능 확인을 막는 지연만 예외적으로 좁게 측정·수정한다.

사용자 확정: 지금은 자급 정착지 플레이테스트를 제외하고 저장·불러오기, 림월드처럼 이해하기 쉬운 UI와 플레이 경험, 아트를 우선한다. 아트는 **간결한 탑다운 2D, 정착민·시설이 잘 구분되는 스타일**이다.

이 문서의 슬롯 수, 단축키 추가, 에셋 규격, 단계 구성은 추천 설계다. 계획 요청은 구현·도구 설치·구매·커밋 승인이 아니다. 기존 제품 규칙은 [Decisions](../Decisions.md)와 최신 소스를 따른다.

이번 완료 기준에서 초기 식사 소진, 두 번의 재배 주기, 장기 자급 밸런스를 제외한다. 저장 파일 안전성, 입력 차단, 표시와 실제 상태 일치 등 변경 기능에 필요한 검사는 유지한다. 기존 자급 계획은 장기 참고로 보존하며 이번 작업의 선행 조건이 아니다. 전투·치료·Fog of War, 다중 선택/대형 편성, 새 생산·생활 규칙은 넣지 않는다.

최종 사용 장면: 실행 → 이어하기 또는 새 정착지 → 맵 탐색 → 정착민/시설 선택 → 건설·작업 배분 → 이름을 붙여 저장 → 종료 → 목록에서 복원. 림월드는 정보 배치·명령 흐름의 참고이며 그림, 로고, 문구와 고유 외형은 독자적으로 제작한다.

UI Toolkit은 문서 기반 배치/스타일 관리의 장점이 있지만, 현재 uGUI 통합과 테스트를 모두 교체하는 비용이 크다. 이번에는 uGUI를 유지한다. Unity 6.3의 UI Toolkit도 월드 공간 UI를 지원하므로 미지원이라는 이유로 배제하지 않는다. 작은 프로토타입에서 uGUI 유지가 장애가 되는 증거가 생길 때만 재검토한다.

Canvas 맵 유지 + 이미지 교체는 가장 빠르지만 카메라·겹침·월드 효과를 UI 좌표계에 계속 결합한다. 이번에는 화면 개선 범위에 카메라와 아트가 포함되므로 월드 렌더링 분리를 선택한다. 저장 직렬화 라이브러리, Addressables, ECS, 외부 DI, DOTween, Spine은 현 요구에 필수가 아니므로 추가하지 않는다. Figma나 웹 모형을 필수 산출물로 두지 않고 실제 Unity 화면을 검토 기준으로 쓴다.

## 4. 목표 화면과 사용 흐름

### 4.1 정착지 화면

[림월드식 UI 구현 인계](RimWorld-UI-Handoff.md)는 아래 초기 구상을 원본 화면과 현재 `SettlementShell`에 대조해 구체화한 후속 배치안이다. 기능 규칙과 인수 기준은 [수락 및 검증 기준](SaveLoad-UX-Art-Acceptance.md)을 따른다.

```text
┌ 자원 요약 ───── 정착민 초상/이름/주의 상태 ───── 시간·배속 ┐
│                                                         │
│                   확대·이동 가능한 맵           알림 목록 │
│                                                         │
│ 선택 대상 정보 + 해당 대상에 가능한 명령                  │
├ 건설 │ 구역 │ 작업 │ 메뉴 ──────────────────────────────┤
└ 선택한 탭의 세부 목록/작업표 또는 접힌 상태                ┘
```

지도에 가장 넓은 공간을 주고, 전역 명령과 선택 대상 명령을 구분한다. 현재 기능만 표시하며 연구·의료 등 비어 있는 탭을 만들지 않는다. 기본 HUD의 Tick/ResetCount/점유 ID는 개발용 패널로 이동하고 실제 작업 진행·부족 원인은 남긴다. 게임 날짜는 기존 하루 정의를 확인해 환산하며 새로운 계절·달력 규칙을 만들지 않는다.

| 화면 | 내용 | 사용 예 |
|---|---|---|
| 상단 정착민 바 | 초상, 이름, 소집, 허기/피로 주의 표시 | 클릭은 선택, 더블클릭은 카메라 이동. 선택만으로 배속은 변하지 않음 |
| 자원 요약 | 목재·식재료·식사 전체 수량 | 상세에서 보관/운반/공정 투입을 구분. 현재 장부에 없는 추정값은 만들지 않음 |
| 선택 패널 | 이름, 행동, 욕구, 운반, 대상 진행, 사용 가능한 명령 | 조리대 선택 시 가동/목표/입력/출력/보류 이유 표시 |
| 건설 메뉴 | 벽·문·침대·조리대, 비용, 배치 도구 | 놓을 수 없는 칸은 빨강+이유 문구, 가능한 칸은 유효 표시 |
| 구역 메뉴 | 저장·경작, 선택 구역 필터·파종 설정 | 영역 미리보기 후 확정. 성공 후 도구 종료 규칙 유지 |
| 작업표 | 행은 정착민, 열은 다섯 작업 종류 | 끔/1/2/3, 1 우선 안내. 끔은 즉시 취소, 숫자 변경은 현재 작업 유지 |
| 알림 | 담당자 없음, 재료 부족, 출력 포화 등 | 같은 원인을 매 프레임 쌓지 않고 원인+대상ID로 갱신. 클릭은 대상 선택/이동 |
| Esc 메뉴 | 재개, 저장, 불러오기, 설정, 메인 메뉴, 종료 | 저장하지 않은 진행을 버리는 동작만 확인창 제공 |

기본 해상도는 1920×1080 배치로 설계하고 1280×720, 기존 1280×800, 2560×1440에서도 검사한다. 추천 UI 배율은 100/125/150%. 작은 화면에서는 상세 패널을 스크롤하고 맵 클릭 영역을 침범하지 않는다. 정상/호버/선택/비활성/위험/키보드 포커스를 구분하며 색만으로 상태를 설명하지 않는다. 툴팁은 지연 표시하고 키보드 포커스에서도 내용을 읽을 수 있게 한다.

### 4.2 입력 규칙

우선순위: 파일 처리 중 차단 → 모달 → 입력 필드 → UI 패널 → 배치/구역 도구 → 월드 선택·이동.

- 좌클릭: 대상 선택. 같은 칸에 여러 대상이 있으면 선택 패널의 목록으로 전환한다.
- 우클릭: 활성 도구가 있으면 취소. 도구가 없고 소집된 정착민을 선택했다면 이동. 미소집이면 자동 작업은 그대로 두고 소집 필요 안내.
- R: 기존 소집 토글 유지. 텍스트 입력 중에는 작동하지 않는다.
- Space/1/3: 기존 정지/배속 유지. 마침표 한 Tick 진행은 개발용 기능으로 분리.
- Esc: 최상위 확인창 → 활성 도구 → 열린 하단 패널 → 선택 → 게임 메뉴 순서로 한 단계만 닫거나 연다.
- 휠: UI 위에서는 해당 목록 스크롤, 맵 위에서는 커서 지점 기준 확대. 중간 버튼 드래그/WASD로 카메라 이동. 경계와 최소/최대 확대 제한.
- 구역은 드래그로 사각형 지정하는 안을 추천한다. 드래그 임계값·UI 위 종료·맵 밖 종료·역방향 드래그를 정의하고 기존 두 점 입력은 이관 기간 검사 경로로 유지한다.
- 복수 정착민 드래그 선택과 여러 명의 자동 위치 분배는 후속 범위다.

Pause는 사용자 의도이고 모달로 인한 정지는 별도 차단 사유다. 메뉴를 닫을 때 무조건 재생하지 않는다. `사용자 일시정지 || 메뉴 || 확인창 || 파일 처리`이면 자동 Tick을 멈춘다. 성공한 불러오기는 파일에 저장된 정지/배속을 적용하고 메뉴 차단을 해제한다. 실패·취소는 기존 상태를 유지한다. 창이 겹쳐도 먼저 열린 메뉴의 정지 차단이 풀리지 않아야 한다.

## 5. 저장·불러오기 경험

### 5.1 첫 묶음의 추천 범위

기존 단일 슬롯을 없애기보다 **기존 파일 읽기 + 이름 있는 수동 저장 목록 + 이어하기**를 우선 제공한다. 자동 저장/클라우드/스크린샷 썸네일/게임 중 슬롯 삭제는 이번 첫 묶음에서 제외한다. 자동 저장은 타이밍·일시정지·디스크 비용 정책을 추가로 요구한다.

- 플레이 화면과 독립된 시작 화면에는 **새 게임**과 **불러오기**를 두고 기존 플레이 UI의 스타일을 따른다. 새 게임은 기존 새 정착지 시작 동작으로 연결한다. 배치와 기존 이어하기·설정·종료의 위치는 [메인 화면 시안과 구현 계획](Main-Menu.md)에서 검토한다.
- 수동 저장: 새 이름으로 저장 또는 선택한 슬롯 덮어쓰기. 이름은 표시용이고 실제 파일명은 생성한 안전한 슬롯 ID 사용.
- 목록: 이름, 저장 시각, 게임 내 경과 시간, 정착민 수, 버전/상태. 이름 중복은 허용하되 별도 슬롯ID로 구분.
- 이어하기: 마지막 정상 저장/불러오기 슬롯 우선. 없으면 최신 읽기 가능한 후보 제안, 손상된 슬롯을 조용히 건너뛰고 자동 진입하지 않음. 메타데이터만으로 복원 가능하다고 확정하지 않음.
- 실패: 읽기/쓰기/버전 오류를 해당 창에 표시. 현재 정착지와 정상 저장본은 유지하고 재시도 가능.
- 종료: 취소 / 저장 후 종료 / 저장하지 않고 종료. 저장 실패 시 종료하지 않는다.
- F5/F9 빠른 저장은 단축키 오입력·대상 슬롯 정책을 늘리므로 첫 묶음 이후 선택 추가.

### 5.2 데이터와 파일 구조

```text
persistentDataPath/
  Saves/
    settlement-v1.json          # 기존 파일, 명시적으로 읽을 수 있도록 유지
    <slot-id>.save.json         # 한 파일 안에 메타데이터 + 기존 상태 payload
  Settings/
    user-settings.json         # UI 배율·표시 설정·최근 슬롯ID
```

새 외피 `SaveEnvelope`는 formatVersion/slotId/displayName/savedAtUtc/summary/payload를 갖는다. 기존 SaveData의 상태 schemaVersion과 외피 버전을 분리한다. 아트 GUID·Texture·Prefab을 상태 payload에 넣지 않는다. 기존 저장 파일은 legacy reader가 읽고, 새 형식으로 저장할 때도 사용자가 대상을 선택하기 전 원본을 덮어쓰지 않는다.

메타데이터와 상태는 한 파일에서 교체해 둘이 다른 시점이 되는 문제를 줄인다. 목록 캐시는 재생성 가능하며 게임 상태의 원본이 아니다. 목록 읽기는 크기 제한과 버전 검사 후 요약만 표시하고 실제 로드는 전체 후보 복원 검증을 수행한다. 기존 BCL serializer로 구현 가능성을 작은 fixture로 먼저 확인한다. 외피 전체에도 파일 크기 상한을 적용한다.

저장 순서: 요청 잠금 → 메인 스레드에서 일관된 상태 캡처 → DTO 검증 → 같은 디렉터리 임시 파일 기록 → 재읽기/후보 복원 검증 → 최종 파일 교체 → 최근 슬롯 갱신 → 완료 알림. 실패 시 기존 파일 유지. 후속 설정 파일 기록만 실패한 경우 저장 자체의 성공과 설정 실패를 구분한다.

불러오기: 읽기 → 버전/용량/참조 검사 → 새 Session 후보 구성 → 원자적으로 참조 교체 → 기존 화면 ID 캐시·선택·배치 도구 해제 → 월드 다시 표시. 실패하면 이전 Session·선택·카메라·시간 유지. 성공하면 카메라는 맵 맞춤 또는 유효 정착민 중심으로 초기화한다. UI 배율 같은 사용자 설정은 저장 당시 게임 설정으로 덮어쓰지 않는다.

처음에는 현재 동기 I/O 경로를 유지하고 대표 파일의 캡처/직렬화/디스크/복원 시간을 각각 측정한다. 목표 응답 예산은 일반 저장 100ms 이내를 잠정 목표로 삼되 보장하지 않는다. 초과하면 불변 DTO를 캡처한 뒤 파일/직렬화 부분만 백그라운드로 옮긴다. Unity API와 live World는 작업 스레드에서 읽지 않고 최종 Session 교체는 메인 스레드에서 한다. 이 경우 취소·종료·중복 요청 테스트를 추가한다.

## 6. 구현 구조와 책임

```text
InputRouter → SelectionController / BuildToolController / MenuController
                                      ↓
                               SimulationRunner
                                ↓           ↓
                         Simulation     SaveCoordinator
                              ↓              ↓
                       Read-only state   SaveRepository
                              ↓              ↓
             HUD presenters / WorldPresenter  SaveFileService
                              ↓
                      Prefab / Sprite / Tilemap
```

신규 이름은 설계안이다. 작은 클래스는 실제 독립 책임이 생길 때 만든다. 전체 상태를 매 프레임 DTO로 복사하거나 범용 프레임워크를 구축하지 않는다.

| 위치/요소 | 책임 | 넣지 않을 책임 |
|---|---|---|
| Simulation | 기존 생활·생산·점유·명령·SaveData | 이미지·카메라·패널·슬롯 표시명 |
| Runtime/SaveCoordinator | 저장 요청 잠금·캡처·복원·결과 | 직접 UI 표시 |
| Runtime/SaveRepository | 슬롯 열거·경로·외피/legacy 읽기·파일 서비스 호출 | 게임 작업 진행 |
| Runtime/UserSettingsStore | UI 설정·최근 슬롯 | 정착지 물자·욕구 |
| Presentation/Input | UI 입력 우선권, 카메라, 선택, 도구 | 선택된 이미지 위치로 게임 좌표를 변경 |
| Presentation/UI | HUD, 선택 패널, 작업표, 저장 목록, 메뉴, 알림 | 자재 소비·작업 판정 |
| Presentation/World | 지면, ID→View 대응, 위치 보간, 오브젝트/선택 표시 | 경로 계산·충돌 판정·실제 진행도 |
| Content/Visuals | 종류별 Sprite·색·크기·pivot·애니메이션 설정 | 실행 중 mutable 작업 상태 |
| Editor | importer 검증·prefab/atlas 생성·검증 장면 구성 | 제품 실행 상태 |

후보 폴더:

```text
Assets/Game/
  Runtime/                    # 기존 Runner와 SaveFileService 재사용
  Presentation/
    Input/                    # InputRouter, CameraController, SelectionController
    UI/                       # HUD, Inspector, WorkTable, BuildMenu, SaveBrowser, Modal
    World/                    # WorldPresenter, EntityView, GroundView, OverlayView
  Content/
    Visuals/                  # VisualCatalog, UITheme ScriptableObject
    Prefabs/UI/               # 패널·버튼·행·툴팁
    Prefabs/World/             # 정착민·시설·자원
    Art/{Terrain,Pawns,Buildings,Items,Plants,UI}/
    Fonts/
  Editor/                     # BuildPresentationAssets, ValidateArtAssets
  Tests/                      # 기존 기능 검사 + 새 저장/입력/표시 검사
ArtSource/                    # 원본·생성 참조·출처 기록, Unity import 대상 밖
Docs/Art/                     # 스타일 규격·에셋 목록·사용 출처
```

VisualCatalog는 ResourceKind/BuildingKind/작물 단계→표시 정의로 매핑한다. 최초에는 기존 종류를 그대로 사용해 상태 저장 버전을 불필요하게 바꾸지 않는다. 아트 변형은 안정적인 entity ID로 선택하되 새 게임 규칙용 난수를 소비하지 않는다. 카탈로그 에셋을 바꿔도 이전 저장 파일을 읽을 수 있어야 한다.

## 7. 월드 표현과 아트 제작

### 7.1 표현 규격

추천 기본: 1칸=1 Unity unit, 128 PPU, 지면 128×128px, 높이 있는 시설/나무는 128×192 또는 256×256px 투명 캔버스. 확정 전 실제 확대/축소 화면에서 샘플로 판단한다. 비픽셀 스타일이므로 Bilinear를 기본 후보로 쓰고 경계 번짐/atlas padding을 검사한다.

낮은 대비의 지면, 명확한 외곽선의 정착민·시설, 선택/위험 표시용 제한된 강조색을 사용한다. 같은 광원 방향·선 두께·색 팔레트·바닥 접점을 지킨다. 발밑 접점/건물 기반을 pivot 기준으로 잡고 표시 크기와 논리 점유 칸을 구분한다. 침대를 크게 그렸다는 이유로 통행/점유 크기를 바꾸지 않는다.

지면 Tilemap → 구역/설계 표시 → 동적 개체와 시설 → 선택/작업 오버레이 → 화면 HUD 순으로 구성한다. 동적 개체는 발밑 Y와 안정적인 보조 순서로 정렬하고 정착민 몸/머리/운반물은 SortingGroup으로 묶는다. 나무에 가려진 선택 정착민은 외곽선/이름으로 식별한다. 정렬은 보기만 바꾸며 통행은 기존 Grid를 따른다.

이동은 기존 논리 칸 진행도를 화면에서 보간한다. 정지 시 이동/작업 애니메이션은 멈추고 UI 호버는 유지한다. 방향은 마지막 이동 방향에서 결정하며 저장 복원 후 기본 방향으로 표시해도 작업 판정은 달라지지 않는다. 초기에는 복잡한 뼈대 애니메이션보다 정면/후면/측면 3뷰+좌우 반전, 걷기 흔들림·작업 자세·수면 표시를 사용한다. 비대칭 도구는 무조건 반전하지 않고 별도 레이어로 처리한다.

### 7.2 첫 아트 묶음

다른 세션은 [아트 작업 인계](../Art/Handoff.md)부터 읽는다. 현재 상태·잠정 규격·로컬 원본·제작 도구·주의사항·검증 순서를 요약하고 아래 상세 계획과 조사 보고로 연결한다.

2026-11-17 후속 조사: [필요 아트·로컬 원본·제작 기준 보고](../Art/2026-11-17-art-production-brief.md). 사용자는 RimWorld 원본을 placeholder로 사용하고 나중에 교체하는 의도를 밝혔다. 현재는 원본 조사와 보고만 수행했으며 게임 반입·사용 조건 확정은 하지 않았다. 독자 아트는 최종 목표로 유지한다. 정착민·나무·침대·지면·선택 패널 5개 기준 샘플을 먼저 검토하는 순서도 유지한다.

| 묶음 | 기본 산출물 | 수량 관리 |
|---|---|---|
| 기준 샘플 | 정착민, 나무, 침대, 지면, 선택 패널 | 먼저 5개를 한 화면에서 검토 |
| 지면 | 흙/풀 계열 변형, 경작지, 저장구역 표시 | 바닥 4~6종과 표시 레이어. 새 지형 규칙 없음 |
| 정착민 | 앞/뒤/옆 외형, 색상 구분 3명, 초상 | 기본 몸체 공유, 머리/옷 색과 이름으로 구분 |
| 시설 | 벽 연결 변형, 문 열림/닫힘, 침대, 조리대 | 기본 4종. 벽은 이웃 연결 마스크 기반 변형 별도 계산 |
| 자연물·작물 | 나무, 채집 식물, 작물 3성장 단계 | 단계는 기존 성장 수치를 읽어 표시 |
| 물자 | 목재, 식재료, 식사 | 수량은 숫자 오버레이, 물자 산출 규칙은 동일 |
| 작업·상태 | 운반, 건설, 조리, 수면, 소집, 부족 | 별도 표시 레이어/짧은 연출 |
| UI | 탭/명령/상태 아이콘, 9-slice 패널과 버튼 | 약 20~30개를 목록화한 뒤 실제 수량 확정 |

표의 종류 수는 최종 PNG/프레임 수가 아니다. 벽 연결·방향·버튼 상태 때문에 늘어난다. 에셋 목록에 stable key, 종류, 원본, 출력 크기, pivot, PPU, variant, 사용처, 제작 출처, 검토 상태를 기록한다.

제작 순서: 스타일 보드 → 기준 샘플 5개 → 투명 배경 단일 에셋 생성/직접 제작 → 윤곽/방향/팔레트 보정 → importer와 atlas 적용 → 실제 맵 캡처 → 확대/축소 가독성 확인 → 전체 제작. 이미지 생성 도구의 결과를 바로 대량 배치하지 않는다. AI 생성이 규격을 반복해서 놓치면 해당 에셋은 단순 벡터/직접 제작으로 대체한다. 에이전트는 생성·코드 에셋 제작·Editor 스크립트·정적 이미지 검토가 가능하며 Krita GUI 작업은 사용자/아티스트 경로다.

기능별 atlas(Terrain/World/UI)를 사용하고 큰 원화는 런타임에 포함하지 않는다. 라이선스/출처 기록과 font license를 배포 목록에서 검사한다. 이미지 생성 도구 접근이나 원화 보정에 지연이 생겨도 placeholder로 UI/저장 구현을 이어갈 수 있다. 음악·효과음 전체 제작은 이번 아트 묶음에서 제외한다.

## 8. 검증 가능한 기능 단위와 진행 순서

| 순서 | 사용자가 확인할 결과 | 작업 내용 | 완료 기준 |
|---|---|---|---|
| 0 | 화면 구조와 샘플 스타일을 판단 가능 | 기존 기능 매핑, UI 배치 초안, 기준 샘플 5개, 구/신 저장 fixture 준비 | 기존 버튼의 이동 위치 누락 없음, 실제 Unity 샘플 캡처, 스타일·규격 합의 |
| 1 | 여러 저장을 구분해 다시 열 수 있음 | 외피/legacy reader, 슬롯 목록, 이름 저장, 덮어쓰기, 시작 메뉴/이어하기 | 서로 다른 슬롯 유지, 재실행 복원, 손상/잠금 실패 시 기존 상태 보존 |

| 3 | 필요한 정보와 명령을 같은 위치에서 찾음 | HUD/정착민 바/선택 패널/메뉴/모달, 한글 글꼴 | 대상별 명령 일치, 중첩 메뉴/취소의 시간 상태 유지, 작은 화면에서 주요 버튼 접근 |
| 4 | 작업·건설·구역 지정을 편하게 조작 | 작업표/건설 목록/구역 드래그/툴팁/알림 | 끔 즉시 취소·숫자 변경 작업 유지, 유효/불가 배치 표시, 명령 한 번 적용, 도구 종료 규칙 유지 |
| 5 | 도형 대신 정착민·시설·작물로 읽힘 | 전체 아트, 성장·문·운반·작업 표시, atlas | 모든 기존 종류 대응, 겹침/선택 가독성, 정지 시 연출 정지, 이전 저장 호환 |
| 6 | 실행부터 저장·재실행까지 완결된 흐름 | 설정 저장, 종료 분기, 오류 안내, 개발 패널 정리 | 아래 자동/정적 검사 완료, 수동 조작 확인 상태 별도 기록 |

의존성: 저장은 현재 화면에서도 먼저 완료 가능. 월드 렌더/입력 분리 뒤 최종 HUD와 도구를 연결한다. 아트는 기준 규격 합의 뒤 준비 가능하지만 최종 통합은 렌더러 완성 뒤 한다. 단계마다 기존 경로에서 기능을 하나씩 옮기고, 공용 버튼/필드에 의존하던 검사는 사용자 행동의 관측 결과 기준으로 변경한다. 기존 기대 결과를 없애서 통과 수를 맞추지 않는다. 중간부터 신/구 화면을 동시에 활성화해 입력이 이중 처리되지 않도록 한다.

일정은 확정하지 않는다. 가장 큰 변동 요인은 Canvas 맵 이관과 아트 방향별 일관성 보정이다. 0단계와 2단계의 작은 구현을 완료한 뒤 실제 작업량으로 남은 일정을 추정한다. 기능 단위가 검증되고 문서가 갱신된 경계에서 커밋을 제안하되 명시 승인 전 실행하지 않는다.

현재는 단일 계획 작업이며 에이전트를 새로 실행하지 않는다. 구현 착수 시 공유 Runner/View/Scene/Editor/검사 manifest의 소유자를 먼저 정한다. 기존 S0/SA/SB 역할이 자동으로 새 범위에 승계되는 것으로 보지 않는다. 병렬 작업을 별도 요청받으면 ParallelWork에 공통 접점·파일 소유권을 기록하고 Unity 검사는 통합 담당자 한 명만 직렬 실행한다.

## 9. 검사 범위와 증거 구분

에이전트 실행 가능(구현 후):

- EditMode: 기존 파일→새 목록 읽기, 새 저장 왕복, 이름/슬롯ID 분리, 손상/미지원/잠긴 파일, 임시 파일 무시, 실패 시 원본 유지. 입력 수락과 작업 규칙의 기존 검사 유지.
- PlayMode: 메뉴/모달/문자 입력 중 단축키와 맵 차단, Pause 중 설정 즉시 반영, 저장 실패 후 선택/시간 유지, 복원 후 UI 재연결, 화면→칸 변환, 작업표 끔 처리.
- 렌더 검사: 고정 시나리오를 스크립트로 구성해 각 해상도의 기본/선택/건설/작업표/저장/오류 화면 PNG 생성. 잘림·겹침·글리프·atlas 경계·나무 가림을 이미지로 검토.
- 에셋 검사: 누락 Sprite/Material/Font, import 규격, pivot, 색상/알파, 참조 누락, 개발 전용 원화의 빌드 포함 여부.
- Windows 빌드와 실제 Player: 저장→변경→불러오기→짧은 작업 이어가기, 정상 종료 후 새 프로세스에서 같은 슬롯 읽기. 테스트 전용 저장 루트를 사용한다.
- 성능 관찰: 대표 화면의 UI 재생성·할당, 카메라 이동과 저장 지연을 측정한다. 현재 3명 규모 확인을 대규모 정착지 성능 보장으로 표현하지 않는다.

사람 확인(후속 구현 완료 때만 요청): 클릭/드래그/휠 감각, 글자 크기, 원하는 작업을 찾는 흐름, 아트 식별과 선택 가독성. 이는 **자급 유지 플레이테스트가 아니라 UI·저장 조작 확인**이다. 실제 실행 파일 경로와 3~6단계 확인 순서는 빌드 완료 후 전달한다.

Computer Use·브라우저/데스크톱 UI 자동화는 사용하지 않는다. Unity 테스트의 이벤트/명령 호출과 스크립트 캡처는 사람의 마우스·키보드 사용 증거가 아니다. 사용 중인 에디터를 종료하거나 잠금 파일을 삭제하지 않는다.

## 10. 이번 계획 작업의 종료 상태

완료: 현재 소스/패키지/기록 확인, 범위 변경과 사용자 아트 선택 반영, 도구·구조·저장/UI/아트 흐름·완료 기준 작성.

미구현: 새 저장 목록·시작 메뉴·월드 렌더러·카메라·HUD·아트. 미검증: 새 화면과 에셋의 실제 품질, 새 저장 형식 호환, 새 입력 흐름과 성능. 기존 저장 기능의 실행 증거와 이번 신규 계획을 구분한다.

사용자에게 남긴 선택은 없음. 상세 설계는 추천안이며 변경 가능하다. 다음 구현 요청 시 0단계의 실제 샘플과 저장 fixture 준비부터 진행한다. 문서 수정만으로 기능을 완료 처리하거나 커밋하지 않는다.
