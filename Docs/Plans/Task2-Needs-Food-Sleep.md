# 작업 2 상세 계획: 정착민이 먹고 쉬는 생활

> 현재 변경 기준: [상호작용 단일 점유·R 소집 계획](Interaction-Occupancy-Draft.md). 아래 초기 생활 계획의 X/Stop·R/Release, 음식 복수 예약, 바닥 수면 고정 규칙은 폐기하고 새 점유 계획/계약을 적용한다. 기존 생활 수치의 근거는 유지한다.
작성: 2026-11-15. 작업1은 사용자 정상 확인 보고를 받았다. 작업2는 계획 정리 후 사용자가 구현 목표를 재개하여 계약·소유권에 따라 구현·자동 검증을 완료했고 새 사람 확인은 대기다. 실제 결과는 Status를 따른다. 커밋은 하지 않는다.

## 목표와 결정 상태

정착민 3명이 허기·피로를 인지하고, 사용 가능한 식사·침대를 찾아 이동하고, 먹거나 잔 뒤 다음 필요한 행동을 스스로 선택한다. 플레이어는 부족과 접근 불가 이유를 화면에서 이해할 수 있어야 한다. 지금 직접 하실 일은 없다.

기존 확정 방향: 포만도·휴식도 0~100, 포만도30 이하 식사, 휴식도20 이하 수면/90 이상 기상, 둘 다 부족하면 식사 우선, 식사 없으면 식재료4개 생식, 침대 없으면 느린 바닥 수면, 생활 종료 후 현재 상황으로 재선택.

아래 감소량·회복량·시간·하루 길이·예약 정책·수동 명령 우선순위·시험 배치는 구현 목표 재개에 따라 이번 시험 기준으로 채택한다. [공통 계약](../Contracts/Living.md)을 따른다. 미리 준비한 물자와 침대로 생활을 검증하며 식량 자급은 작업5/8 범위다.

포함: 자동 욕구·식사·수면, 이동 연결, 자원/침대 예약과 해제, 부족·접근 불가 표시, 재시작·배속·월드 독립성, Windows 데모 검증.
제외: 채집·운반·조리·농사·건설, 침대 소유권 배정, 일과표·기분·관계·질병·기아 사망, 전투·FoW, 저장. 식사 대상 타일에서 먹으므로 인벤토리·운반 기능을 먼저 만들 필요는 없다.

## 시험 수치 추천

| 항목 | 추천값 | 의미 |
|---|---|---|
| 욕구 표현 | 0~100, 내부 0~10000 정수(0.01 단위) | 부동소수점 누적 오차 없이 임계값 검사 |
| 시험 하루 | 1200 Tick | 기존1×10Tick/초에서120초, 3×에서40초. 최종 게임 하루 길이 아님 |
| 포만도 감소 | 모든 상태에서 Tick당0.10 | 시험 하루120 감소, 식사60 회복이면 대략 하루2식 목표. 실제 빈도는 이동·행동시간 포함 측정 |
| 깨어 있을 때 휴식도 감소 | Tick당0.05 | 이동·대기·식사 중 동일. 수면 중 이 감소는 적용하지 않음 |
| 일반 식사 | 식사1개, 20Tick, 완료 시 포만도+60 | 100 상한. 시작/예약만으로 수량을 줄이지 않음 |
| 비상 생식 | 식재료4개, 40Tick, 완료 시 포만도+60 | 일부만 예약/소비하지 않음. 식사보다 느림 |
| 침대 수면 | 순회복 Tick당+0.50 | 휴식20→90에140Tick, 단 중간 허기 개입이 없는 조건 |
| 바닥 수면 | 순회복 Tick당+0.25 | 같은 조건280Tick. 침대보다 느리지만 막히지 않음 |
| 이동 | 일반5Tick/칸 유지 | 포만도0에서는 다음 칸부터10Tick/칸 추천. 이미 진행 중인 칸의 소요시간은 바꾸지 않음 |
| 부족 재평가 | 관련 상태 변경 또는 최대10Tick마다 | 실패 대상 매 프레임 탐색과 영구 대기 방지 |

포만도·휴식도는 매 Tick [0,100]으로 제한한다. 포만도0은 경고와 위 이동 저하를 적용하되 이동을 완전히 막거나 죽이지 않는다. 생산 작업의 효율 저하는 작업3 이후 별도 수치화한다. 휴식도0은 경고·수면 필요 상태이며 별도 이동 저하나 실신은 이번에 추가하지 않는다.

식사 중에도 포만도가 감소한다. 예: 식사 행동 시작 시30, 20Tick 뒤 소비와 회복까지 처리하면28+60=88이다. 식사 중 포만도가30 아래라는 이유로 행동을 새로 시작하지 않는다. 수면 중 포만도도 감소하며 식사 필요가 생기면 아래 우선순위 규칙을 따른다.

## 식사 규칙

1. 포만도30 이하이고 현재 식사 행동이 없으면 먹을 수 있는 대상을 찾는다. 도달 가능하고 예약 가능한 식사1개를 우선하며, 없으면 식재료4개를 찾는다. 접근 불가/모두 예약됨인 식사도 사용 불가능으로 보고 생식 후보를 허용한다.
2. 같은 종류 후보는 최단 경로 길이→자원 ID 순으로 선택한다. 직선 거리만으로 선택하지 않는다. 선택한 뒤 더 가까운 물자가 생겼다는 이유로 예약을 바꾸지 않는다.
3. 선택과 동시에 필요한 수량을 예약한다. 총 수량과 다른 정착민의 예약을 고려한 가용 수량을 구분한다. 같은 스택을 여러 명이 예약할 수 있지만 예약량 합계는 총량 이하이어야 한다.
4. 기존 이동 엔진으로 자원 타일에 도착한 뒤 식사 행동을 시작한다. 도착 전 소비·회복 금지. 자원 타일은 통행 가능하며 다른 정착민과 겹침은 계속 허용한다.
5. 정해진 행동 Tick을 채운 순간 소유 예약·대상 존재·도달 위치·수량을 재검사한다. 필요한 수량 차감, 포만도 회복, 예약 해제를 한 번의 상태 변경으로 처리한다. 조건 실패면 소비/회복 없이 취소한다.
6. 식사 종료 후 욕구를 다시 판단한다. 휴식도20 이하라면 수면, 아니면 대기한다. 이전 수동 이동 목적지로 자동 복귀하지 않는다. 노동 재선택은 노동 기능이 들어온 뒤 같은 경계에 연결한다.

중단된 식사 진행은 폐기하되 아직 소비하지 않았으므로 물자는 그대로다. 자원을 집어 들지 않는 현재 범위에서 별도 물자 반환이나 임시 스택 생성은 없다. 이미 완료된 식사를 Stop/Reset 처리 중 다시 환불하거나 소비하지 않는다. Reset은 전체 시나리오 복원이며 게임 내 취소와 구분한다.

## 수면과 침대 규칙

- 휴식도20 이하에서 도달 가능한 빈 침대를 예약하고 이동한다. 후보 순서는 경로 길이→침대 ID다. 침대는 사전 배치하며 건설 비용을 차감하지 않는다.
- 침대1개는 예약/수면 소유자1명만 허용한다. 이동 중 예약을 유지하고 도착 후 같은 소유권으로 점유한다. 일반 보행자의 타일 통과는 허용하므로 침대 점유와 타일 충돌은 다른 규칙이다.
- 사용 가능한 침대가 없으면 현재 서 있는 통행 가능 타일에서 바닥 수면한다. 침대가 예약 중이거나 접근 불가인 경우도 포함한다. 바닥 수면자는 서로 같은 타일에 있어도 되며 침대처럼 독점 예약하지 않는다.
- 수면 중 휴식도가90 이상이 되면 즉시 수면을 끝내고 침대 예약/점유를 해제한다. 100까지 계속 자지 않는다.
- 수면 중 포만도30 이하가 되고 먹을 수 있는 대상이 있으면 식사 예약을 확보한 뒤 침대 예약을 해제하고 식사하러 간다. 식량을 못 구하면 수면을 유지하면서 식량 경고를 표시한다. 매 Tick 깼다가 다시 자는 반복을 금지한다.
- 바닥에서 자던 중 침대가 비어도 현재 수면을 계속한다. 더 좋은 침대로 옮겨 다니는 행동은 제외한다. 깨어난 다음 필요할 때 침대를 다시 선택한다.
- 침대가 사라지거나 통행이 끊기면 예약을 해제하고 다른 침대를 찾거나 바닥에서 잔다. 동적 삭제·재배치는 테스트용 시나리오 변경이며 사용자 건설 UI는 만들지 않는다.

## 소집과 플레이어 명령 우선순위 (2026-11-15 변경)

사용자 지시로 기존 생활 중 Stop 거부 규칙을 폐기한다. Stop 버튼/X는 정착민을 소집하고 즉시 현재 행동·이동·미적용 명령·식량 예약·침대 점유를 해제한다. 일시정지 중에도 Tick이나 욕구 수치를 진행시키지 않고 적용한다. 식사 완료 전이면 소비/회복 없이 취소하며 이미 완료된 소비는 환불하지 않는다.

소집 중에는 플레이어 우클릭 이동과 Stop이 자동 생활보다 우선한다. 포만도·휴식도가0이어도 자동 식사/수면은 시작하지 않는다. 시간 진행 중 욕구 감소와 기존 기아 이동 속도는 유지한다. 소집된 정착민은 플레이어 명령이 없으면 대기한다. Stop 재입력은 소집을 유지하고 이동을 중단한다.

Release 버튼/R로 소집 해제한다. 기존 수동 이동은 취소하고 다음Tick 현재 욕구로 자동 생활을 다시 선택한다. 이전 식사 진행·예약·이동 목적지는 되살리지 않는다. Reset은 소집 상태도 초기화한다. 선택 해제·배속 변경·Pause만으로는 소집이 해제되지 않는다.

비소집 상태의 자동 식사/수면 규칙은 유지한다. 생활 중 직접 우클릭 이동을 요청하면 Stop/X로 먼저 소집하라는 안내를 표시한다. 이번에는 전투·무기·공격 기능을 추가하지 않는다.

## 이동 연계·막힘·예약 수명

이동 구현은 재사용하고 생활 상태는 별도로 둔다. 예: 생활 GoToFood인데 이동 상태는 Moving 또는 Blocked일 수 있다. 사용자용 상태는 이유를 합쳐 '식사하러 이동', '식사 장소 접근 불가'처럼 표시한다.

- 경로가 있는 대상만 예약하되 이동 중 통행이 바뀔 수 있으므로 기존 revision 재탐색을 이용한다. 우회 가능하면 같은 예약 유지. 완전히 막히면 그 Tick에 예약을 해제하고 다른 후보를 선택한다.
- 대상 소진/삭제, 경로 불가, 행동 완료/취소, World 초기화에서 예약 해제 경로를 모두 정의한다. 해제는 중복 호출되어도 총량을 증가시키지 않는다.
- 부족한 동안 매 Tick 새 경로를 계산하지 않는다. 통행·자원 가용량·침대 가용성 변경, 자기 위치 변경 또는10Tick 재시도 시점에 재평가한다. 동일 우선순위에서 목적지를 이유 없이 바꾸지 않는다.
- 경쟁 정착민의 신규 식사 요청은 포만도 낮은 순→ID 순, 신규 침대 요청은 휴식도 낮은 순→ID 순으로 처리한다. 기존 유효 예약은 빼앗지 않는다. 마지막 식사 경쟁의 승자는 이 순서로 결정되며 실패한 정착민은 음수 재고를 만들지 않는다.
- World마다 자원량·침대 상태·예약·욕구·행동 진행을 독립 소유한다. 예약 정보는 원본 Scenario/Seed나 Unity 객체에 저장하지 않는다.

보존식: 각 자원 종류의 초기량 + 명시된 외부 추가량 − 실제 소비량 − 명시된 외부 제거량 = 현재 총량. 예약량은 소비량이 아니다. 총량≥예약량≥0, 가용량=총량−예약량. 바닥 수면/침대 취소는 식량 총량을 바꾸지 않는다.

## Tick 처리 순서와 행동 시간

구현 전 계약에서 기존 이동 Tick 순서를 아래 의미로 확장한다.

1. 외부 통행/대상 변경 적용, 잘못된 예약 무효화.
2. Tick 시작 상태 기준 욕구 갱신: 포만도 감소, 깨어 있으면 휴식 감소/자고 있으면 순회복.
3. 이전 Tick부터 진행 중인 식사 시간 증가·완료 시 소비, 수면 종료 판단. 완료된 행동은 다시 완료시키지 않는다.
4. 현재 욕구와 유효 예약으로 생활 우선순위를 판단하고 신규 예약 경쟁을 결정한다. 필요한 수면 중 허기 전환도 이 단계다.
5. 수동 명령 허용 여부와 생활 명령을 조정한 뒤 기존 이동을 진행한다. 도착하면 식사/수면 상태로 전환하되 새 행동의 진행/회복은 다음 Tick부터 센다.

양의 거리 L칸이면 Tick1에 선택·예약·이동 시작, Tick5L에 도착, 그 다음20Tick에 일반 식사를 완료한다(비기아 정상 속도). 같은 타일 대상은 Tick1에 행동 시작하고 Tick21 완료. 이미 Eating/진행0 상태인 시험은20Tick 후 완료다. 수면 역시 새로 시작한 Tick에 회복하지 않는다. 이 경계를 테스트 초기 조건마다 명시한다.

포만도0에서의10Tick/칸은 다음 칸 진입 진행을 시작할 때 고정한다. 진행 중 포만도0이 되더라도 이미 시작한 칸의 소요시간은 바꾸지 않는다. 한 칸 완료 후 새 상태를 반영한다. 1/3배속은 게임 시간 전달만 바꾸므로 같은 Tick에서 욕구·예약·소비·행동 상태가 일치해야 한다. Pause는 욕구·회복·행동 시간을 멈추고 Step은 이 순서를 정확히 한 번 수행한다.

## 데이터와 화면 확장

검증된 이동 기준의 Resources는 불변 ResourceSeed다. 작업 폴더의 미검증 생활 초안과 이 기준을 구분한다. 원본 seed는 유지하고 World별 ResourceState에 수량을 둔다. 자원0개는 대상 탐색에서 제외하고 화면에서 숨긴다. 이번에는 ID를 재사용하지 않는다. 사전 배치 BedSeed와 World별 BedState를 추가하며 침대·자원·정착민 ID 충돌, 잘못된 위치/초기 욕구/수량을 검증한다.

ColonistState에는 욕구·생활 상태·대상ID·진행·예약 참조를 추가하고, 실제 이동은 기존 위치/경로를 사용한다. Simulation은 Unity를 참조하지 않는다. Runtime은 시간·사용자 명령 전달, Presentation은 조회와 표시만 담당한다. 범용 작업 스케줄러·인벤토리·건설 기능까지 확대하지 않는다.

화면에는 정착민별 포만도/휴식도, 현재 행동과 대상, 진행도, 실패 이유를 표시한다. 자원은 총량/예약/가용량, 침대는 빈 상태/예약자/수면자를 구분한다. 경고는 '식량 없음', '식량 예약 중', '식량 접근 불가', '침대 없음/사용 중/접근 불가→바닥 수면', '포만도0'으로 구분한다. 새로운 정보 때문에 기존 좌표·자원 수량·선택 표시가 가려지지 않아야 한다.

추천 기본 데모는 기존8×8·정착민3·식사18·목재40을 유지하고 침대2개를 (5,5),(6,5)에 사전 배치한다. 초기 포만도35, 휴식도25는 빠른 관찰용 값이다. 식재료 생식/식사1개/침대1개/빈 맵 등은 별도 테스트 fixture로 구성한다. 식재료는 기본 데모에 무료로 추가하지 않는다. 시간 조작·Reset·선택 방식은 유지하고 생활용 별도 버튼은 추가하지 않는다.
