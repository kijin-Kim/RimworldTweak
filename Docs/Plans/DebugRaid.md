# 일반 습격 즉시 진입과 피격 후 표적 재선정

현재 구현 기준은 250×250 정착지의 모던 HUD다. Windows Player에 `--development-ui`를 주고 새 정착지를 연 뒤 F3에서 **일반 습격 발생**을 누른다. 교전 중 이름 있는 슬롯으로 저장하고 다시 불러올 수 있다. 아래 설계에서 언급한 구형 조리대와 예고 단계는 이전 저장의 호환 동작이다. [최신 통합 검증](../Status.md)

개발자 모드에서 ‘일반 습격 발생’을 누르면 현재 정착지에 적이 즉시 나타나고, **각 적이 자기 위치에서 가장 가까운 정착민을 표적으로 잡는다.** 다른 정착민이 가까이 지나가도 원래 표적을 추적한다. 적이 피해를 받고 살아남으면 일정 확률로 현재 위치를 기준으로 가까운 정착민을 다시 계산한다.

## 1. 핵심 설계

**확정 사항.** 개발자 모드에서만 일반 습격을 수동 발동한다. 예고 없이 즉시 교전에 들어가며 자연 발생은 없다. 첫 표적과 피격 후 재선정 대상은 정착민이다. 접근로 선택, 길이 막혔을 때의 전술이나 철수, 벽·시설 상호작용은 후속 결정으로 남긴다.

**구현을 위한 제안.** 처음에는 기존 동쪽 진입 칸 두 곳에 근접 적 한 명씩을 배치한다. 거리는 가로·세로 칸 차이의 합을 사용하고 동률이면 ID가 작은 정착민을 고른다. 후보는 현재 월드에 있고 전투 불능이 아닌 모든 정착민이다. 소집 여부나 부상 자체는 제외 조건이 아니다. 이렇게 하면 ‘누구를 쫓을지’는 이동 경로를 정하기 전에도 판정할 수 있다. 선정한 ID를 유지하면서 그 정착민의 현재 위치로 기존 이동·근접 규칙을 실행한다.

피격 재계산 확률은 한 곳에서 조정한다. 초깃값은 **30% 시험안**이며 사용자 확정값은 아니다. 0~99의 정수 추첨값이 설정값보다 작으면 재계산한다. 기존 전투는 한 틱에 같은 대상에게 들어간 피해를 합산하므로 **피해를 받은 적 한 명당 그 틱에 한 번** 판정하는 안을 사용한다. 확률 0%와 100%에서도 추첨 대상에 해당하면 난수 한 번을 소비한다. 반대로 표적 무효화에 따른 강제 재선정이나 치명 피해는 난수를 소비하지 않는다. 피해량과 공격자 수에 따른 추가 가중치는 없다.

## 2. 동작 흐름

1. 일반 UI에는 발동 명령이 없다. 개발자 모드를 켜고 한 번 누르면 현재 틱에서 새 회차·적 2명·각자의 표적이 함께 생긴다. 조리대 선택이나 월드 전환은 필요 없다. 일시정지 상태에서도 적과 표적이 정해지며 이동·공격·시간 경과는 다음 시뮬레이션 틱부터다. 메뉴를 닫아도 교전은 계속된다.
2. 예를 들어 적과 A의 거리가 2칸, B가 4칸이면 A를 쫓는다. B가 1칸까지 접근해도 표적은 A다. 적이 살아남는 피해를 받았을 때 추첨이 실패하면 A, 성공하면 그 시점에 가장 가까운 B를 쫓는다. 공격자가 누구인지는 이 계산에 사용하지 않는다. 재계산 결과가 여전히 A일 수도 있다.
3. 틱의 모든 피해와 전투 불능·제거·종료 판정을 반영한 다음, 계속 교전할 적의 표적을 정리한다. 원래 표적이 쓰러졌거나 사라졌으면 추첨 없이 새 유효 표적을 찾는다. 이때 피격까지 겹쳐도 두 번 선정하지 않는다. 유효한 표적이 있는 생존 적만 실제 체력 감소가 있었을 때 추첨한다. 피격하지 않은 적·치명 피해로 제거된 적·끝난 교전에는 추첨이 없다.
4. 표적이 바뀌면 이전 대상의 근접 공격 준비를 지우고 남은 공격 대기는 유지한다. 같은 표적이거나 추첨이 실패했다면 피격 때문에 준비를 초기화하지 않는다. 변경된 표적을 향한 이동과 피해는 다음 틱부터 처리한다. 그 틱에 이미 성립한 이전 표적의 타격은 한 번만 반영한다. 다음 틱에는 이전 표적의 재탐색 대기를 해제하고 새 표적으로 향할 다음 칸을 계산한다. 다음 칸이 같으면 기존 이동 진행을 유지하고 다르면 초기화한다. 길을 찾는 과정이 표적 ID를 덮어쓰지 않게 한다.

## 3. 구체적인 구현 작업

| 순서 | 변경 단위 | 필요한 이유 |
|---|---|---|
| 1 | 개발자 모드 전용 ‘일반 습격 발생’을 현재 월드에 연결한다. 기존 예고 단계를 건너뛰고 적과 표적을 한 번에 생성한다. 중복 실행, 활동 가능한 정착민 없음, 유효하지 않은 출현 칸은 월드 변경 없이 거부한다. | 현재 시작 명령은 조리대 ID·전원 체력 100을 요구하며 예고 100틱 뒤 출현한다. 기존 v2 회차의 동작은 구분해 둔다. |
| 2 | 적마다 기존 공격 표적 ID를 추적에 재사용한다. 출현·기존 표적 무효화·피격 추첨 성공 시에만 후보를 비교한다. 이동은 선정된 표적의 인접 칸을 향해 기존 경로 계산을 사용한다. | 현재 AdvanceRaider는 이동 경로를 찾으면서 여러 정착민을 비교하고, 경로가 없으면 조리대를 고른다. 일반 습격에서 이 경로가 매 틱 표적을 바꾸지 않도록 한다. |
| 3 | 해당 틱의 실제 피해를 받은 생존 적을 식별해 정해진 적 ID 순서로 추첨한다. 월드가 소유한 재현 가능한 난수 상태와 해당 회차의 확률을 저장·복원한다. | 피해를 적용하는 도중 재선정하면 뒤에 처리될 정착민의 전투 불능을 놓칠 수 있다. 전역 난수나 표시 프레임에 의존하면 로드 후 표적이 달라질 수 있다. |
| 4 | 시설 목표가 없는 새 일반 습격과 조리대 목표가 있는 기존 v2 회차를 구분해 읽는다. 화면의 발생·종료 안내에서 새 회차에 조리대 조건을 표시하지 않는다. | 현재 저장 검증은 진행 중 회차에 조리대 참조를 요구한다. 적 전멸·아군 전원 불능·기존 교전 제한과 전투 후 치료는 기존 기능을 활용한다. |

## 4. 완료 조건과 검증 방법

| 기능 | 검사 입력 | 통과 조건 |
|---|---|---|
| 즉시 진입 | 조리대 없는 정착지에서 정지하고 디버그 버튼을 연속 두 번 누른다. | 첫 호출 직후 교전 중·적 2명·각자 표적 있음. 두 번째 호출 뒤 적 2명 그대로. 틱·아군 위치/체력·운반 중 물자 보존. 자연 진행·모드 전환만 하면 새 습격 0회. |
| 최초 선택·유지 | 거리 2/4인 A/B, 동거리인 두 대상, 전투 불능자와 부상자를 각각 배치한다. B가 더 가까워져도 피해 없이 틱을 진행한다. | 적별 거리 최소, 동률 ID 순. 쓰러진 대상 제외. B가 가까워진 것만으로 A에서 바뀌지 않는다. |
| 피격 추첨 | A를 쫓다가 B가 가까워진 상태에서 피해를 준다. 확률 0%, 100%, 30% 경계에서 29와 30을 각각 입력한다. | 0%는 A, 100%는 B. 30%일 때 29는 재계산, 30은 유지. 공격자가 멀리 있고 가까운 사람이 따로 있으면 가까운 사람을 고른다. 무작위 반복 횟수로 합격을 판정하지 않는다. |
| 같은 틱 경계 | 적 두 명 중 한 명만 피격, 같은 적 연속 피해, 합산 치명 피해, 원래 표적의 동시 전투 불능, 동일 표적 재선정을 각각 검사한다. | 살아남은 피격 적만 한 번 추첨. 사망·종료 시 추첨 0회. 무효 표적은 확률 0%여도 교체. 동일 표적의 유효한 공격 준비와 남은 대기 보존. |
| 저장·복원 | 다음 피격 직전 실제 JSON 저장 후 원본과 복원본에 같은 명령을 넣고 같은 틱까지 진행한다. 새 일반 회차·구버전 조리대 회차를 각각 읽는다. | 첫 적격 피격으로 난수를 이미 소비한 뒤 저장한다. 연속 두 추첨의 성패가 다른 고정 시드를 사용해 다음 난수 상태·표적 ID·체력·준비·대기·최종 결과가 양쪽에서 같은지 확인한다. 복원 그 자체는 신규 출현이나 추첨을 일으키지 않는다. |

**피해 단위와 틱 경계 검사.** 규칙 검사에서는 같은 틱에 한 적에게 비치명 피해 5+5를 넣어 체력 50→40, 추첨 1회를 확인한다. 실제 사격 통합에서는 1발로 50→25일 때 1회, 같은 틱 2발로 50→0일 때 0회를 확인한다. 별도 사례로 새 표적과 기존 표적이 서로 다른 두 정착민을 배치해, 이미 성립한 공격은 첫 대상에게만 들어가고 새 표적에 대한 준비는 다음 틱부터 시작하는지 확인한다.

**저장 호환 검사.** 변경 전에 실제로 생성된 v2 JSON(대기·예고·교전·종료)을 보관해 게임의 파일 읽기 경로로 불러온다. 예고·교전 중인 과거 회차는 다음 틱에도 당시 규칙을 따른다. 현재 파일 읽기와 월드 검증 양쪽이 버전을 확인하므로 두 경로에서 구형과 새 형식을 구별한다. 새 일반 회차의 종류·확률(0~100)·난수 상태가 누락되거나 손상되면 구형으로 추정하지 않고 거부하며 현재 월드와 기존 파일을 보존한다. [파일 읽기](../../Assets/Game/Runtime/SaveFileService.cs) · [월드 검증](../../Assets/Game/Simulation/SaveValidation.cs)

에이전트는 규칙 검사(EditMode) 뒤 버튼·지도·시간 연결(PlayMode), Windows 빌드와 실행 파일 검사를 순서대로 진행한다. 실제 실행 파일에서는 현재 월드에서 즉시 출현 → 모드 닫기 → 소집·공격 → 교전 종료를 확인한다. 규칙 검사의 0%·100%와 별도로 실제 사격 피해가 재선정 처리로 들어가는 경우를 검사한다. 사람은 구현 후 일시정지 상태의 출현, 재개 후 적의 추적과 전투 결과가 화면에서 이해되는지 확인한다.

### 최종 요약

일반 습격의 즉시 진입과 피격 후 표적 재선정을 구현했다. 실제 실행 결과와 직접 확인 상태는 [일반 습격 검증](../Verification/2026-11-19-normal-raid.md)에 기록한다. 접근로에 따른 새로운 전술을 정하지 않고도 시험할 수 있도록 대표 검사는 열린 맵을 사용한다. 전투와 저장·검증 담당의 교차 평가 결과를 반영했다.
