# 림월드식 정착지 UI 구현 인계

첫 화면부터 지도를 넓게 보여 주고, 정착민·물자·시간은 가장자리에서 읽게 한다. 하단의 **건축가 → 카테고리 → 도구**에서 지도에 일을 지정하고, 지도에서 고른 대상은 **좌하단 요약 → 상세 탭 또는 명령 타일**에서 조작한다. 이 배치로 지도에서 고른 것과 다음에 누를 버튼이 가까워진다. 이 문서는 2026-11-17 조사에 따른 재현 제안이다. 아래 좌표·색·배치 우선순위는 구현을 시작할 기본값이다.

먼저 [원본 사진과 화면별 분석](../Reviews/RimWorld-UI-Reference.md)의 공식 화면 A를 열어 상단·좌하단·우하단을 비교한다. 기존 조작, 저장과 접근성의 판정에는 [기능별 수락 기준](SaveLoad-UX-Art-Acceptance.md)을 함께 적용한다. 기존 기능을 실행하는 대상은 [DemoBootstrap](../../Assets/Game/Demo/DemoBootstrap.cs)이 만드는 `SettlementShell`이다. `SettlementView`는 과거 데모 및 회귀 경로다.

최신 적용은 [모던 HUD 대조 검토](../Reviews/Modern-Hud-RimWorld-Audit.md)와 [모던 다크 HUD 계획](Modern-Hud-Pawn-Eyes.md)을 따른다. 아래 표의 색과 건축가 크기는 당시 초기 기준이며, 최신 건축가는 현재 도구에 맞춘 작은 영역과 별도 활성 도구 표시를 사용한다. 조리 계획서는 새 행에 편집 초점을 옮기고 스크롤 중에도 선택한 계획서 이름을 보여준다.

### 1. 핵심 설계

**카메라를 화면 전체에 고정하고 uGUI를 위에 얹는다.** 현재 `SettlementShell.RefreshLayout`은 상단 108과 하단 최대 320 논리 단위의 패널을 배치하고, `Map.SetViewport`에서 카메라를 그 사이로 제한한다. 목표 배치에서는 카메라의 정규화 사각형을 `(0,0,1,1)`로 두고, 실제 UI의 히트 영역에서만 맵 입력을 막는다. 패널을 열고 닫아도 지도 크기·줌·중심이 튀지 않는다. 가림의 부담은 접을 수 있는 요약과 작은 히트 영역으로 줄인다. 기존 `CanvasScaler`, uGUI `Text`·`InputField`, 한글 폰트, `VisualCatalog`를 활용하면 입력과 저장 목록의 검증 경로를 유지하면서 배치를 옮길 수 있다.

```text
┌ 물자 아이콘+수량 ─────── 정착민 초상/이름 ──────────────────────┐
│                                                               │
│                        탑다운 정착지 지도                       │
│                                                               │
│ [선택 상세 / 건축가 / 작업표]                   작업 문제 목록  │
│ [선택 요약] [대상 명령 타일]      [짧은 결과]     경과·Ⅱ ▶ ▶▶  │
├ 건축가 ─────── 작업 배분 ───────────────────────────────── 메뉴 ┤
└───────────────────────────────────────────────────────────────┘
```

표의 좌표는 1920×1080·100%에서 쓰는 좌상단 기준 논리 단위다. 너비·높이는 `CanvasScaler` 적용 뒤의 캔버스 값으로 고정점에 상대 배치한다. 색과 단위는 림월드 사진에서 복사한 값과 구분되는 프로젝트 제안이다.

| 구역 / 규격 | 배치와 기본 상태 | 좁은 화면·충돌 처리 |
|---|---|---|
| 하단 주 메뉴 | 전체 폭, 높이 40, 하단 0. `건축가`, `작업 배분`은 왼쪽 각 144, `메뉴`는 오른쪽 120. 빈 구간은 바의 시각 배경 | 빈 구간의 배경은 포인터를 받지 않으며, 버튼은 각자 입력을 소비한다. 해당 탭을 다시 누르면 닫힘 |
| 자원 목록 | 왼쪽 8, 위 8, 폭 136. 3줄×26. 아이콘 20과 수량, 텍스트는 종류명/범위 툴팁 | 라벨/배경으로 불필요한 히트 영역을 만들지 않는다. 항목이 늘어나는 경우 실제 스크롤 영역만 차단 |
| 정착민 초상 | 상단 가운데, 위 8. 칸 폭 62, 간격 8, 높이 72. 초상 48, 이름 15. 현재 3명 | 물자 폭과 우측 여유를 제외한 상단 구역 안에서 가운데 배치. 가로 공간을 넘는 증원은 그 구역에서 스크롤. 이름이 길면 말줄임과 전체 이름 툴팁 |
| 선택 요약 | 왼쪽 8, 하단 메뉴 위 4, 폭 380, 높이 최대 144. 이름·현재 행동과 대상별 핵심 수치. 선택 없음이면 숨김. 맵 유효 칸 위에서 간단한 커서 칸 정보만 표시 가능 | 폭을 캔버스의 34% 이내로 제한. 헤더와 명령은 접근 가능하게 유지하고 상세 본문을 별도 스크롤 |
| 선택 상세 | 요약 위 4, 폭 최대 540, 높이 최대 360 및 사용 가능한 높이 이하. 대상별 상세 탭 1개만 펼침 | 초상·자원과 겹칠 때 위쪽 높이 제한 및 내부 세로 스크롤. 상세 닫기는 요약·선택을 유지 |
| 선택 명령 | 요약 오른쪽 8, 하단 메뉴 위 4. 타일 66×66, 간격 6, 아이콘·짧은 캡션·단축키 | 우측 시간 영역을 침범하기 전에 2줄로 줄바꿈. 줄 폭이 부족하면 마지막 타일에서 명령 목록을 여는 방식으로 접근 유지 |
| 건축가 | 하단 메뉴 위 4, 왼쪽 8에 카테고리 폭 192, 2열. 오른쪽에 도구 타일 72×72와 비용/상태 설명 | 좌하단 선택 카드와 같은 공간을 교대 사용. 도구 선택 중 설명을 본문에 남김. 넓은 카테고리가 생기면 먼저 스크롤 적용 |
| 작업 배분 | 하단 메뉴 위 4, 왼쪽 8. 최대 880×320. 정착민 열 최소 122, 작업 열 최소 92, 셀 높이 38 | 우측 정보와 겹치는 폭만큼 좁히고 내용이 넘으면 스크롤. 표의 헤더와 셀 폭을 같은 기준으로 계산 |
| 시간·배율 | 오른쪽 8, 하단 메뉴 위 4, 폭 176. 경과와 현재 상태 위/아래로 정지·1배속·3배속 3버튼. 버튼 높이 30 이상 | 시간 그룹과 문제 목록을 떨어뜨려 겹치지 않게 함. 사용 가능한 조작만 표시 |
| 작업 문제 목록·결과 | 우측 폭 220, 시간 그룹 위 12, 문제 목록 최대 높이 180. 결과 텍스트는 하단 중앙의 사용 가능한 공간에 짧게 띄움 | 문제는 스크롤. 목록이 비면 히트 영역도 사라짐. 도구 이유·모달 오류는 각각 해당 UI 안에서 보여 주며 중앙 결과에 중복하지 않음 |
| 시작·정지·기타 모달 | 시작은 제목과 선택 목록을 스크롤 가능한 독립 화면에 둠. 진행 중 정지 메뉴는 오른쪽 하단의 좁은 패널로 표시하되 전체 입력 차단. 파일 선택·설정·확인·오류는 중앙 폭 최대 720, 높이 화면−40 이내 | 제목과 확인·취소/뒤로 가기는 고정. 저장 이름 입력과 슬롯 목록 본문을 스크롤. 전체 화면 차단막은 클릭을 소비 |

본문은 기존 Noto Sans CJK KR 16–18, 창 제목 22–26, 초상 이름 14–16으로 시작한다. 패널은 `#151B1F`, 경계선 `#53666B`, 본문 `#E8EBE4`, 선택 `#B0CF85`, 위험 `#C96B60`을 기준으로 한다. 9-slice 패널과 얇은 선을 사용하고, 밝은 맵 위의 이름·수량에는 얇은 그림자나 외곽선을 둔다. 호버·포커스는 테두리, 선택은 테두리+활성 형태, 비활성은 강조 감소+사유, 위험은 아이콘/문구도 함께 사용한다. 아이콘은 중심 실루엣을 크게 잡고 24–32에서도 용도를 구별한다. 대상 표시용 `pawn.front`를 초상 첫 샘플로 쓰고, `ui.panel`, `icon.draft`, `icon.sleep`, `icon.work`부터 [아트 인계](../Art/Handoff.md)에 연결한다.

지도 내부는 **지형 → 구역 바닥 → 시설·물자·정착민 → 선택/예고·이름/수량 → 화면 UI**의 순서로 읽히게 한다. Y에 따른 오브젝트 정렬과 바닥 접점을 `WorldMapView.Refresh`에 유지한다. 저장과 경작은 다른 채도와 테두리/구역 이름으로 읽히게 하고, 설계의 반투명 그림과 실제 완성 시설은 구분한다. 미리보기는 선택 테두리와 다른 선 모양을 사용하고 유효/불가 이유를 덧붙인다. 카메라를 멀리 뺐을 때에도 이름·수량에 최소 읽기 크기를 유지한다. 경로선과 이름이 겹치면 칸 가장자리나 오프셋으로 비켜 그리고, 시설의 그림이 커져도 클릭 칸은 논리 좌표에서 판정한다. 포커스 대상이 열려 있는 패널에 가려지면 패널을 정리하는 전환을 우선하고, 맵 가장자리에서 가능한 범위 내로 카메라를 이동한다.

### 2. 동작 흐름

| 현재 상태와 입력 | 화면과 게임 결과 |
|---|---|
| 도구 없음 → 초상 또는 맵 대상 좌클릭 | 해당 ID를 고른다. 건축가/작업표가 열려 있으면 닫고 좌하단에 요약을 보인다. 맵 브래킷·초상 테두리·요약이 같은 ID를 가리킨다. 초상 더블클릭과 위치 보기는 카메라만 옮긴다. 맵 빈 칸은 기존 선택 해제. 활성 도구 중 초상을 누르면 먼저 도구를 취소하고 정착민을 선택 |
| 같은 칸에 시설·물자·정착민이 겹침 | 기본은 정착민, 그다음 시설→설계도→침대→물자→채집물→경작 구역→저장 구역→작물의 종류 순·동종 ID 오름차순. 요약의 ‘같은 칸 대상’ 버튼으로 전 후보에 접근. 프레임마다 삭제된 후보를 걸러 내고 선택한 ID가 사라지면 해제. 현재 소스의 `ObjectsAt` 및 첫 대상/다음 대상 버튼을 출발점으로 사용 |
| 건축가 → 구조/가구/생산 → 시설 선택 → 맵 클릭 | 구조는 벽·문, 가구는 침대, 생산은 조리대. 현재 비용과 유효·불가 이유를 표시. 도구가 맵 위에 있는 동안 고스트와 칸을 그린다. 유효한 배치는 설계 1건을 만들고 도구를 유지해 연속 배치한다. 우클릭/Esc로 종료한 뒤 설계를 선택하면 반입·시공 정보를 볼 수 있다 |
| 건축가 → 구역 → 저장/경작 → 드래그 | 양끝 포함, 역방향도 동일, 같은 칸에서 누르고 놓으면 1칸. 끝이 UI/맵 밖이면 확정하지 않고 도구는 유지. 성공 후 도구와 건축가를 닫고 기존 선택으로 돌아감. 건축가 → 명령 → 채집은 유효 채집물 클릭 때 지정하며 사용자가 취소할 때까지 도구 유지 |
| 도구가 열린 채 우클릭/Esc | 도구와 미리보기만 해제. 건축가는 열린 상태. 같은 입력으로 이동·선택 해제를 실행하는 경우는 0건 |
| 도구 없음 → 맵 우클릭 | 소집 유효 대상이면 이동 요청 1회. 미소집이면 소집 필요 안내. 기존 작업·점유는 보존. 선택 없음이면 무동작 |
| 작업 배분 탭 또는 선택 상세 열기 | 기존 선택과 사용자 시간 상태 유지. 작업 배분을 열 때 건축가와 도구는 닫으며, 화면에 작업표만 표시. 다른 UI 액션이 진행을 막는지는 실제 파일/모달 차단 여부에서 판정 |
| Esc 처리 | 파일 처리 중 입력을 차단. IME 조합 Esc/Enter는 조합이 먼저. 이후 최상위 메뉴 단계 → 도구 → 상세 탭/열린 하단 탭 → 선택 → 게임 메뉴 중 한 단계. 확인 취소 후 직전 메뉴로, 게임 메뉴 닫으면 직전 정지·배속으로 |
| 정지 상태에서 소집·지정·종류/작업 설정 | Tick 증가 0, 명령 반영·선택 수치 갱신. 자동 작업은 Tick 재개 후 진행. `1`·`3`은 각각 현재 `SetSpeed`와 동일하게 해당 배속으로 재개하며 Space는 정지 전환 |
| 저장·교체 | 시작의 `이어하기`·`새 정착지`·`불러오기`·`화면 설정`·`종료`와 게임 메뉴의 기존 진입을 그대로 연결. 진행 중 다른 슬롯 선택은 교체 확인, 덮어쓰기는 대상 슬롯 확인. 취소·로드 실패는 기존 세계/선택/시간/카메라를 보존. 성공 또는 새 정착지에서 선택·도구·열린 탭과 오래된 클릭/표시를 정리하고 새 월드의 기본 카메라로 진입 |

입력은 **파일 처리 → 최상위 모달/텍스트 필드 → 실제 UI 히트 → 활성 도구 → 맵 선택/이동** 순이다. `WorldMapInput.IsPointerOverUI`가 `GraphicRaycaster`를 검사하므로 전체 화면 부모의 장식 `Image`·`Text`는 `raycastTarget=false`로 두고 실제 조작·스크롤·모달 차단 면만 켠다. 맵의 좌표 반환과 UI 차단은 서로 다른 검사다. 화면에 월드가 있어도 UI 위 입력의 맵 명령 건수는 0이어야 한다. 휠은 히트한 스크롤 또는 커서 기준 맵 줌 중 하나, WASD와 중간 버튼 드래그는 기존 카메라 경계에서 처리한다. 모달·도구 전환·포커스 상실·월드 교체 시 기존 캡처를 취소하고 눌린 키/버튼의 release를 삼킨다. `WorldMapView`의 카메라 clamp와 줌 공식을 출발점으로 사용하고, 전체 뷰포트 확정 뒤 최초 `Bind` 때 화면비를 바탕으로 기본/최대 줌을 계산한다. 레이아웃만 갱신할 때는 사용자가 맞춘 줌을 다시 초기화하지 않는다.

### 3. 구체적인 구현 작업

이후 구현자가 순서대로 실행할 CLI는 다음과 같다. [검증 계획](../Testing.md)과 [작업 운영 절차](../Workflow.md)에 따라 같은 프로젝트의 Unity 실행은 직렬로 진행한다.

Capture는 표의 나머지 10조합에서도 실행한다. 숨김 Player PNG가 단색이면 레이아웃 수치 검사는 별도로 기록하고 렌더는 실패로 남긴다. 실제 Windows 그래픽 세션에서 게임 자체의 캡처 경로나 사람 촬영으로 유효한 이미지를 확보한다. 기본·선택·건축가·작업표에서 지도와 UI의 대비를, 조리대·슬롯/확인에서는 전체 텍스트·버튼 가림 여부를 각각 확인한다.

사람 확인은 후속 빌드 `C:\Users\kijin\.codex\worktrees\rimworld-feature-b\RimworldTweak\Builds\Windows\RimworldTweak.exe`를 대상으로 한다. 구현자가 별도 작업 공간을 사용하면 해당 빌드의 절대 경로를 결과에 명시한다.

1. 새 정착지를 열어 초상을 클릭하고 더블클릭한다. 단일 클릭은 같은 대상의 요약과 맵 테두리, 더블클릭은 위치 이동을 표시한다.
2. 건축가에서 시설을 골라 빈 칸과 막힌 칸에 포인터를 올린다. 두 상태에 표식과 문구가 나오며 유효한 칸에 놓으면 설계가 한 건 생긴다. 구역 드래그를 UI 위에서 놓으면 구역이 생기지 않는다.
3. 정지 후 작업표에서 숫자와 끔을 바꾼다. Tick은 정지한 채 버튼 표시가 바뀌고, 해당 작업을 끄면 점유가 해제된다.
4. 저장 메뉴에서 한국어 이름을 입력한 뒤 취소하고 복귀한다. 타이핑 중 맵/시간은 반응하지 않으며 복귀 뒤 기존 정지 상태가 유지된다.
5. 작은 해상도·큰 배율로 반복해 목록을 끝까지 스크롤한다. 답변은 ‘모두 정상’ 또는 ‘1280×720·150%, 조리 주문의 삭제 버튼에 접근할 수 없음’처럼 관찰한 결과를 적는다.

### 최종 요약

구현은 전체 카메라와 얇은 HUD에서 시작해, 건축가와 대상 요약을 같은 좌하단 공간에 연결하고, 현재 슬롯·정지·작업 명령을 새 위치로 이관하는 순서다. 화면 전환 전후 같은 지도를 가리키고, 한 번의 입력은 해당 단계의 명령 한 번만 실행해야 한다. 이 인계에서 실행한 것은 원본 이미지·설치본·대상 소스의 조사다. 이 배치의 Unity 구현과 Player·렌더·사람 검증은 후속 작업이다.
