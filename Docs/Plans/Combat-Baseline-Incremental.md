# 림월드식 기본 전투부터 확장하는 계획

작성일: 2026-11-17. 사용자 지시에 따라 기본 전투를 첫 단계로 두고, 확인한 결과를 바탕으로 확장 하나씩을 선택한다. 이번 요청은 계획 수정이며 구현·커밋 승인이 아니다. 현재 UI 구현 범위를 바꾸지 않는다.

후속 요청 반영: [기본 전투의 기능 분리·의존성·병렬 배치](Combat-Baseline-Parallel.md)를 실제 작업 분해 기준으로 사용한다. 아래 B1~B5는 유지할 플레이 경험의 수락 묶음이며 직선 개발 순서나 파일 소유권이 아니다. 건강·부상·방어구·구조·치료·회복을 별도 기능으로 나누고, 같은 상태를 바꾸는 기능은 한 담당이 관리한다.

## 1. 핵심 설계

첫 결과물은 '정착민을 소집해 엄폐와 무기를 활용하여 작은 교전을 해결하고, 부상자를 돌본 뒤 생활로 돌아가는 전투'다. 유지할 림월드식 경험을 먼저 완성해 이후 변경의 비교 기준으로 삼는다. 림월드 전체 복제나 공식·수치·AI의 동일 재현은 목표가 아니다.

이전 C0~C9 계획은 전체 확장을 가정한 의존성 참고로 내려놓는다. 유한 탄약 → 제압 → Fog of War → 공격 → 원정의 고정 순서와 각 확장의 도입 여부는 확정하지 않는다. 특히 방향 엄폐와 기본 방어 교전을 제압·탄약·Fog of War 뒤로 미루지 않는다.

| 첫 단계에서 유지할 경험 | 기본 전투에 넣을 범위 | 이유 |
|---|---|---|
| 개별 정착민 지휘 | 기존 소집·일시정지·이동·정지와 표적 지정, 자동 사격/사격 보류 | 생활 인물을 직접 지휘하고 중요한 판단에 집중 |
| 사격 준비와 무기별 간격 | 조준 → 발사 → 회복. 준비 중 취소와 이동 명령의 관계 표시 | 공격과 재배치에 시간 비용을 부여 |
| 지형·시설을 활용한 배치 | 완전 사선 차단, 낮은 엄폐, 방향에 따른 보호 | 평상시 건설과 위치 선택이 전투 결과에 영향 |
| 무기·사수 역할 차이 | 소수 원거리 무기의 사거리·조준·공격 간격 차이, 사수 능력의 명중 영향, 최소 근접 대응 | 상위 무기 하나보다 배치와 역할을 판단 |
| 장비와 부상, 생활 복귀 | 단순 방어구 보호, 최소 부상·무력화·사망, 구조·치료와 작업 복귀 | 같은 정착민의 생존과 전투 이후 운영을 연결 |
| 적과 교전 종료 | 고정 구성 적의 접근·엄폐 활용·공격·철수와 종료 판정 | 플레이 가능한 한 전투를 완결 |

일반 총기는 첫 단계에서 탄약 물자를 소비하지 않고 조준·회복 시간으로 사격 간격을 제한한다. 사격 후 회복을 재장전이라고 부르지 않는다. 전장은 시험 맵 전체 공개로 시작한다. 제압, 수동 숨기/노출 모드, 지속 Fog of War, 유한 탄약과 재보급, 목표형 공격 원정은 기본 전투의 완료 조건에 포함하지 않는다.

확률은 노출 교전의 명중 등 기본 규칙으로 검토하되, 완전 차단과 취소는 확실한 결과로 검사한다. 기본판의 복잡한 명중 공식을 그대로 이식하지 않으며 초기 수치와 난수 통제 방식은 해당 작업 착수 전에 정한다. 무피해의 반복 재현 범위는 전체 게임에 대한 확정 약속으로 만들지 않는다.

## 2. 첫 단계의 플레이 흐름

정착민이 생활·작업 중인 작은 정착지에서 고정 전투를 시작한다. 플레이어는 시간을 멈추고 소집한 뒤 벽/낮은 엄폐 뒤에 배치한다. 사거리와 사선에 따라 표적을 지정하거나 자동 사격하게 하고, 불리하면 사격을 멈춰 뒤로 이동한다. 적이 무력화되거나 철수하면 교전이 끝난다. 부상자를 구조·치료하고 소집을 풀면 가능한 생활·작업으로 복귀한다.

첫 비교는 같은 적과 무기로 개방 지형 / 엄폐 / 측면 노출을 비교한다. '배치와 무기 선택만으로 무엇을 할 수 있고 어디서 한계가 생기는가'를 확인한다. 이 단계에서 탄약 부족이나 정보 부족으로 인한 실패는 만들지 않는다.

## 3. 기본 전투의 수락 묶음

첫 단계를 한 번에 크게 구현하지 않고 독립 기능으로 작성한 뒤 B1~B5의 플레이 경험으로 확인한다. 실제 선행·담당·공유 파일·검증 문턱은 [병렬 계획](Combat-Baseline-Parallel.md)을 따른다. 아래 최소 범위는 제안이며 B1~B4의 개별 통과는 기본 전투 전체 완료와 구분한다.

| 묶음 | 기능 결과물 | 담당 기능과 주요 연결 | 확인할 결과 |
|---|---|---|---|
| B1. 직접 지휘하는 교전 | 소총 1종으로 아군·적이 서로 공격하고 벽 뒤로 이동 | K/AT/SP/EQ/HP/AR/IN을 S0가 기존 명령·Tick에 연결. 초기 판정 시험과 실제 피해 연결 구분 | 사격 보류·표적 변경·이동/정지로 조준을 제어. 벽 뒤 직접 피해 없음. 무력화자는 공격·작업 중단 |
| B2. 지형과 엄폐 | 낮은 엄폐와 방향에 따라 유불리가 달라짐 | SP는 K 뒤 독립 작성. S0가 지도/표시에 연결. B1 전체 완료를 작성 선행으로 요구하지 않음 | 정면 엄폐와 측면 노출 차이가 결과·표시에서 일치. 완전 차단과 확률적 엄폐를 구분 |
| B3. 무기와 역할 | 성격이 다른 원거리 무기 2종, 최소 근접 공격 1종을 시험 | EQ/SP/AT/HP 조합. 무기 설정과 사수 능력·접촉/점유 규칙. 이동 중 사격이나 복잡한 근접 기술은 제외 | 같은 무기가 모든 거리에서 우월하지 않음. 가까운 적 대응과 재배치가 가능하고 공격/이동 충돌이 없음 |
| B4. 피해 이후의 대응 | 단순 방어구·부상 영향, 구조·치료·작업 복귀 | AR/HP/IN/RS/MD/RC를 별도 기능으로 작성. S0가 기존 이동·점유/예약과 연결. 세부 장기·감염·수술·다층 관통 제외 | 방어구 효과와 부상 영향이 보이고, 구조/치료 중단으로 대상·예약이 남지 않음. 처치와 시간 회복을 구분하고 운영 복귀 |
| B5. 작은 방어전 통합 | 시작 → 배치 → 교전 → 종료 → 복구를 한 판으로 연결 | AI/BT와 전체 기능·UI·저장 연결. 고정 적 구성·철수·보호 목표·신규 부상 이력·결과 표시 | 적 전멸/철수와 아군 손실을 구분. 같은 전투를 다른 배치로 반복하고, 종료 후 다음 전투도 정상 진행 |

여기서 WorldState·ConstructionRules는 기존 코드 접점이고 전투 상태·무기 설정·부상/임무 규칙은 새로 설계할 내용이다. 적에게 정착민 생활 시스템 전체를 복사하거나, 미래 분대/원정을 위해 범용 구조를 미리 만들지 않는다. 사격 판정·표적 조회를 한곳에 모으는 현재 기능의 경계만 둔다. 관측 기억·시야 프레임워크를 기본 전투의 선행 조건으로 추가하지 않는다.

UI·저장·취소 처리는 각 작업에 포함한다. 조준 중·무력화·구조/치료 중 상태를 저장에서 누락하지 않는다. 옛 저장 호환과 Load/Reset 뒤 표적·선택·예약 정리도 함께 확인한다. 운반 중 물자와 전투 장비를 혼동하지 않는다. 세부 처리 순서와 저장 필드는 실제 추가하는 기능만 대상으로 정한다.

## 4. 검증과 다음 확장 선택

### 기본 전투 완료 기준

- 자동 규칙 검사: 소집/명령 권한, 사선 차단, 엄폐 방향, 공격 취소, 표적 상실, 같은 Tick 처리 순서, 무력화자의 행동 정리, 구조/치료 예약, 신규 부상 이력과 전투 종료를 확인한다.
- 자동 통합 검사: 기존 생활/운반/건설 중 전투 전환, 해제 후 복귀, 저장 후 연속 진행과 Reset/두 번째 전투를 확인한다. 확률 결과는 고정 입력·난수 조건과 반복 분포를 구분한다.
- 실제 화면 확인: 누가 조준/공격/무력화 상태인지, 왜 사격 불가인지, 어떤 방향에서 보호받는지 읽을 수 있는지 확인한다.
- 사람 플레이: 일시정지로 배치를 바꾸고 무기·엄폐·후퇴를 사용해 한 전투를 해결한 뒤, 피해 원인과 다음에 바꿀 배치를 설명할 수 있는지 확인한다. 자동 통과만으로 조작감과 재미를 완료 처리하지 않는다.

현재는 계획 수정이므로 위 검사는 모두 미실행이다. 실행 파일과 직접 조작 순서는 실제 빌드가 생긴 뒤 제공한다. 기본 전투의 성공 여부를 무피해 확장 설계 전체의 검증으로 해석하지 않는다.

### 확장은 하나씩 선택

기본 전투 확인 → 불편/부족한 선택 기록 → 다음 기능 하나 선택 → 그 기능의 최소 규칙·선행·검증만 구체화 → 구현과 비교 → 유지/조정/보류 판단 → 다음 기능 선택.

다음 표는 번호 없는 후보 목록이다. 모두 구현할 의무도, 표의 순서대로 진행할 의무도 없다. 기존 제안은 버리지 않고 선택할 때 다시 검토한다.

| 실제 플레이에서 확인할 필요 | 확장 후보 | 선택한 경우 필요한 최소 선행 |
|---|---|---|
| 적을 제거하기 전에는 아군 이동을 보호하기 어려움 | 제압 | 기본 사격·엄폐·행동 취소. 유한 탄약은 필수가 아니며 사격 간격·회복·노출 비용으로 먼저 시험 가능. 무제한 봉쇄가 생기면 탄약 또는 다른 비용을 별도로 비교 |
| 전투 지속과 철수 시점에 자원 선택이 필요함 | 휴대 탄약·재장전 | 기본 무기·발사·취소·저장. 생산/수송망 없이 지급 탄약으로 시작 |
| 탄약 보충 위치와 경로를 지키는 선택이 필요함 | 현장 재보급 | 유한 탄약 + 실제 이동·물자·예약. Fog of War는 필수 아님. 나중에 도입하면 위험 표시의 정보 범위를 연결 |
| 적 발견 시점과 숨겨진 접근로 판단을 경험하고 싶음 | Fog of War·정찰 | 공간 차단·표적 조회·적 판단·UI를 진영 정보와 연결. 제압·탄약은 필수 아님 |
| 같은 전투를 공격자 입장에서 시험하고 싶음 | 작은 목표형 공격 | 기본 전투 + 목표·회수·철수 조건. 우선 공개 맵/무한 일반 탄약으로도 시험 가능. 보급·Fog of War 전체 완료를 요구하지 않음 |
| 공격 시험을 정착지 운영의 선택으로 연결하고 싶음 | 정착지 출발·귀환 | 선택된 공격 임무 + 인원/물자 이전·저장 + 본거지 시간 정책. 세계지도는 별도 선택 |

후속 기능은 기본 전투와 같은 비교 시나리오로 효과와 조작 부담을 확인한다. 모든 기능을 켜고 나서 판단하지 않는다. 비교용 이전 규칙은 테스트/시나리오 설정으로 남길 수 있지만 영구적인 사용자 옵션 시스템을 만들기로 확정하지 않는다.

기존 완전작전 지향은 유지하되 첫 기준선에서 확인한 피해 원인을 바탕으로 해결할 기능을 고른다. 제압·탄약·Fog of War 등으로 무피해를 얼마나 재현할지 지금 한꺼번에 확정하지 않는다.

## 최종 요약

당장 구체화할 대상은 유지할 림월드식 기본 전투다. [기능별 병렬 계획](Combat-Baseline-Parallel.md)으로 독립 작성·직렬 통합하고 B1~B5의 경험을 확인한 후 새 기능 하나를 선택한다. 이전 전체 확장 의존성 계획은 후보 검토 참고로만 사용하며 다음 기능 착수·구현·커밋을 자동 승인하지 않는다.
