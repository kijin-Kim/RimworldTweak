# 8방향 이동과 건설 현장 점유

2026-11-19 구현 승인. 이 문서는 4방향 이동을 교체하는 기능 규칙과 합격 장면을 정의한다. 실행 결과는 [현재 상태](../Status.md)에서 확인한다.

## 1. 플레이 요구사항

| 상황 | 제안하는 규칙 |
|---|---|
| 열린 땅 | 정착민과 습격자가 8방향으로 이동한다. 직선 5틱, 대각선 7틱. 굶주린 정착민은 10틱·14틱. 한 걸음을 시작할 때 시간을 고정한다. |
| 벽 모서리 | 대각선 도착 칸과 양옆 직교 칸이 모두 통행 가능해야 한다. 한쪽에만 벽이 있어도 직접 대각 진입을 막는다. 청사진과 다른 폰은 보행을 막지 않는다. |
| 자동 작업과 전투 | 이동 비용으로 접근 경로를 고른다. 건설·수리·타인 치료·습격자 근접 공격의 도착 위치는 기존 직교 인접 칸이다. 음식·침대·환자 인계 등 각 작업의 도착 규칙과 기존 사거리·표적 선정 규칙을 따로 유지한다. |
| 건설 칸에 폰이 섬 | 벽·문·침대·조리대 본체 한 칸에 정착민이나 습격자가 있으면 착공·공정 증가·완공을 보류한다. 쓰러진 정착민도 현재 위치로 센다. 사용 칸이나 옆 작업자는 대상에서 제외한다. 설계도·반입재·진행도를 보존하며 마지막 폰이 떠난 뒤 다음 유효 건설 틱부터 재개한다. |
| 점유와 운반 | 점유는 실제 시뮬레이션 위치로 판단한다. 다음 칸 예약이나 화면 보간으로 막지 않는다. 현장에 반입된 목재는 바닥 물자와 구별한다. 기존 바닥 물자 대기는 통행 차단 건물에만 적용한다. 자재 반입과 설계도 배치 가능 여부는 기존 규칙을 따른다. |

원작 1.7.5013 설치본에서 확인한 근거는 방향별 이동 시간(대각 약 1.414배), 대각 양옆 검사, 작업별 도착 조건과 건설 방해물 검사다. 5/7틱, 네 건물의 동일한 폰 점유 처리, 직교 작업 위치는 우리 프로젝트의 선택이다. 지형별 속도·폰 밀어내기·자동 표적 변경은 별도 기능이다.

## 2. 설계 선택

| 결정 | 대안과 선택 이유 |
|---|---|
| 후보 비용은 다익스트라, 먼 단일 경로는 A* | 첫 Windows 시제품에서 250폭 모서리 조회가 0.65→3.01ms, 세 명 명령이 2.56→9.70ms로 늘어 재검토선을 넘었다. 다익스트라로 한 출발점의 후보 탐색을 공유하고, 한 축이라도 24칸 이상 떨어진 경로 요청은 직선·대각 최소 남은 시간을 추정하는 A*로 찾는다. 두 방식 모두 합법적인 최소비용 경로를 고른다. 습격자는 본인과 표적 위치·통행 버전이 같을 때 접근 경로를 재사용한다. |
| 걷는 방향과 행동 가능 위치 분리 | 공용 Directions에 네 방향을 추가하면 수리 후보가 선택된 뒤 직교 거리 검사에서 탈락할 수 있다. 걷기만 8방향으로 하고 대상별 도착 칸·사거리·표적 우선순위는 독립적으로 판정한다. |
| 건설만 잠시 정지 | 폰의 통행을 금지하면 청사진만으로 길이 끊긴다. 현장 작업을 보류하면 통행과 작업을 함께 지원하고 소집·취소 시 기존 점유 정리 절차를 쓸 수 있다. |

## 3. 동작 흐름과 구현 순서

1. 합법적인 한 걸음과 기본 비용(5/7)을 공통화한다. 일반 맵의 배열 탐색과 큰 사용자 시나리오의 희소 탐색에 적용한다. 같은 출발점·통행 버전에서는 탐색을 재사용하고 더 싼 비용으로 갱신한다. 같은 비용은 고정 방향 순서와 발견 순번으로 결정한다.
2. 직접 명령·생활·생산·구조·습격 추적과 철수에서 경로 길이 비교를 점검한다. 기존 선택 순서에서 거리 비교 자리만 기본 이동 비용 합으로 바꾼다. 정착민·습격자의 실제 걸음과 정착민 화면 보간에 방향별 시간을 적용한다. 현재 습격자 그림은 논리 칸 중심에 표시되므로 적의 화면 보간은 이번 범위에서 제외한다.
3. 기존 건설 Clearance의 폰 판정과 바닥 물자 판정을 분리한다. 자동·우선 작업·작업 중·완공·표시가 같은 조건을 사용한다. 공정 틱에서 먼저 점유를 검사하고 완공으로 통행 지도가 변하면 그 뒤의 이동은 새 지도에서만 허용한다.
4. 아래 저장 호환 절차를 완료한 뒤 UI·성능·저장 회귀를 통합 검증한다. 구현 전에는 변경 전 Player에서 이동 중인 저장 표본과 성능 측정 자료를 먼저 확보한다.

### 경로와 행동 선택

기본 비용은 직선 5, 대각 7로 통일한다. 굶주림은 개인별 실제 소요 시간을 두 배로 늘린다. 작업 후 미래의 허기까지 예측하지 않는다. [현재 후보 비교](../../Assets/Game/Simulation/WorkPolicy.cs)에서 개인 우선순위·돌봄 우선·돌봄끼리 요청순을 먼저 보존하고, 기존 거리 비교 뒤의 요청순·대상 ID·단계 비교도 유지한다. 음식 종류 우선, 운반 출발지와 반입처의 도달 조건 등 작업 고유 규칙도 그대로 둔다.

탐색은 목적지를 처음 발견한 뒤에도 더 싼 경로가 생기면 비용과 부모 칸을 갱신하고, 최소비용이 확정된 칸까지 결과를 재사용한다. 같은 비용이면 직교 동·북·서·남, 이어 북동·북서·남서·남동의 고정 순서와 최초 발견 순번을 쓴다. 기본/희소 탐색이 같은 경로를 반환해야 한다. 걸음 수는 경로 원소 수, 후보 점수는 누적 비용으로 구분한다. 특히 [작업 후보](../../Assets/Game/Simulation/FeatureWorkContracts.cs)와 [파종 착수 시 재검사](../../Assets/Game/Simulation/WorldState.Production.cs) 양쪽의 단위를 함께 바꾼다. 후보 조사에서는 비용만 얻고 채택한 밭 칸의 경로를 나중에 만드는 기존 최적화도 유지한다.

### 건설 한 틱의 순서

건설 공정 → 정착민 이동 → 습격자 이동 순서다. 공정 판정 때 현장이 차 있으면 그 틱에 0만큼 진행한다. 그 뒤 폰이 떠나면 다음 공정 틱에 재개한다. 반대로 마지막 공정이 빈 현장에서 먼저 끝났다면 그 틱에 이동할 폰도 새 벽을 통과할 수 없다. 완공·철거·파괴·수리로 통행이 바뀔 때 대각 옆 칸도 다시 검사한다. 기존 직접 명령의 중지·실패·재개 및 통행 변경 시 걸음 진행 초기화 정책을 따른다.

착공 전 대기에서는 작업자가 현장을 선점하지 않는다. 작업 중 잠시 막히면 현재 담당자의 권리를 유지하며 소집·취소·정상 재배정으로 해제할 수 있다. 현장에 필요한 자재가 모두 반입된 뒤 대기하는 동안 반입량·공정은 일정하다. 자재 부족 단계는 기존 반입을 허용한다. 배치가 허용되는 빈 지형에 폰만 서 있는 경우 설계도를 놓을 수 있다. 완공 시점에 목재와 청사진을 한 번만 소비한다.

대기 중 선택한 설계도에는 ‘현장 비우기 대기’와 기존 진행값이 표시되어야 한다. 다른 일꾼이 같은 현장을 조회해도 소유자 있음 표시가 대기 이유를 덮지 않아야 한다. 담당자는 타격 동작을 멈추고 유효한 다음 공정부터 다시 작업한다. [현재 현장 진단](../../Assets/Game/Simulation/WorldState.Features.cs) · [작업 동작 표시](../../Assets/Game/Simulation/WorldState.WorkFeedback.cs)

이 규칙은 새 건물 시공에 적용한다. 무너진 벽 수리는 기존처럼 마지막 틱에 실제 점유와 정착민·습격자가 다음에 밟기로 한 칸까지 확인한다. 사람을 밀어내거나 지나가는 동안 퇴거 명령을 내리지 않는다. [기존 수리 판정](../../Assets/Game/Simulation/WorldState.Recovery.cs)

### 저장 호환

추천안은 새 저장의 schemaVersion을 3으로 올리고 새 실행 파일에서 기존 schema 2와 기존 schema 1 정착지 변환 경로를 계속 읽는 방식이다. rulesVersion 2·3·4는 습격·장비 조합을 이미 구분하므로 이동 구분에 재사용하지 않는다. schema 2에 선택 필드를 더하는 대안은 예전 실행 파일이 새 이동 규칙의 필드를 무시할 수 있다. 실제 적용에는 본문 검증, 파일 헤더의 지원 버전 분기, 이름 있는 슬롯과 기존 단일 슬롯 입구, 메모리 내 구버전 변환을 함께 갱신한다. 지원하지 않는 버전과 잘못된 진행 수치는 복원 전 거부한다. [파일 읽기와 이전 저장 변환](../../Assets/Game/Runtime/SaveFileService.cs) · [버전별 데이터 검사](../../Assets/Game/Simulation/SaveValidation.cs)

구 저장 정착민의 합법적인 남은 직교 경로 전체와 현재 걸음 진행·업무·점유를 보존한다. 새 최적 경로의 첫 칸이 다르다는 것만으로 운반·수면 이동을 취소하지 않는다. 새 명령이나 통행 변경부터 새 규칙으로 탐색한다. 습격자는 전체 경로를 저장하지 않으므로 합법적이고 이미 진행 중인 첫걸음만 마친 후 새 경로로 추적·철수한다. 도중 표적 무효·통행 변경은 다시 판단한다. 구 저장을 연 직후 다시 저장해도 이 진행을 잃지 않아야 한다. 새 저장은 합법적인 직교·대각 전 구간과 해당 진행을 보존하고, 무효 경로는 기존 후보 월드의 복구·취소 정책을 따르되 벽 통과나 이중 반환은 허용하지 않는다. 복원 실패 시 실행 월드와 원본 파일은 그대로 보존한다. [정착민 경로 복원](../../Assets/Game/Simulation/WorldState.Save.cs) · [습격자 복원](../../Assets/Game/Simulation/WorldState.CombatSave.cs)

## 4. 완료 조건과 검증

복원 검사에서는 오류 종류별 기대값을 고정한다. 새 정착민 직접 이동 경로가 중간에 막혔으면 후보 월드에서 합법 경로를 다시 찾고, 없으면 목적지를 유지한 채 대기한다. 무효 경로를 가진 자동 작업은 기존 해제 경로로 예약·화물을 한 번만 정리한다. 구 저장의 직교 경로에 대각선이 들어가면 합법적인 구 경로로 인정하지 않는다. 습격자의 저장된 다음 칸이 범위 밖이거나 새 저장의 대각선이 벽 모서리를 통과하면 후보를 거부한다. 진행 중인 직교 걸음의 총시간은 정착민 5·10, 대각은 7·14이며 습격자는 각각 5·7이다. 방향과 맞지 않는 시간이나 범위 밖 진행값도 거부한다. 구 습격자의 첫걸음 보존과 같이 복원 직후 잠깐 필요한 상태는, 같은 틱에 다시 저장·복원해도 동작이 같아야 한다.

| 장면 | 자동 검사와 합격 기준 |
|---|---|
| 빈 지도와 모서리 | (0,0)→(3,3)은 3걸음·21틱, 굶주림 고정 시 42틱. 2×2에서 옆 한 칸이 벽이면 직교 2걸음·10틱, 양옆이 벽이면 접근 불가. 큰 사용자 지도와 일반 지도에서 같은 국소 배치 결과가 일치한다. |
| 작업 선택 | 직교 세 걸음(15)과 대각 세 걸음(21)의 동순위 후보 중 15를 선택한다. 건설·치료·습격자가 대각으로 접근해도 실제 동작은 기존 도착 조건에서만 시작한다. |
| 건설 대기와 재개 | 네 건물 각각 공정 중, 완공 1틱 전, 착공 전에 점유한다. 두 폰 중 한 명만 떠나면 대기하고 마지막 폰이 떠나면 재개한다. 대기 중 진행도·반입량 일정, 완공 건물 1개와 목재 차감 1회. 소집·작업 취소·재배정 후에도 장부 일치. |
| 벽 완공과 이동 | 현재 서 있는 칸에 벽을 완공하지 않는다. 대각 옆 칸에 벽이 완공되면 해당 대각선을 밟지 않는다. 우회 가능하면 도착하고 완전히 막힌 직접 이동은 철거 후 재개한다. |
| 저장 호환 | 구 저장의 직선 5틱 중 4틱은 1틱 뒤 원래 칸에 도착한다. 구 정착민의 남은 합법 경로·작업을 보존하고 구 습격자는 그 걸음 뒤 새 규칙을 쓴다. 새 버전끼리는 대각선 7틱 중 4틱, 굶주린 정착민 14틱 중 9틱, 현장 점유 대기 중 각각 저장하고 무저장 대조군과 위치·도착 틱·작업·장부를 비교한다. |
| 표시·성능 | PlayMode에서 정지·1배·3배와 복원 직후 중간 위치·클릭 선택·작업 이유를 검사한다. 250×250 Windows Player에서 장거리, 접근 불가, 세 명 동시 이동과 작업 후보 조회를 변경 전후 같은 장면에서 측정한다. |

**단계별 종료 판정**

합법적인 게임 상태에서 만든 저장은 반드시 다시 열려야 한다. 습격자가 다음 칸을 정한 뒤 같은 틱의 통행 변경으로 그 걸음이 무효가 되면, 새 형식으로 캡처하기 전까지 예약 걸음과 진행을 정리한다. 이 경계에서 저장한 파일도 무저장 대조군과 비교한다.

1. **경로와 걷기** — 작은 지도에서 별도 기준 계산과 최소비용을 비교한다. 서로 다른 순서로 여러 목표를 질의해도 새로 탐색한 비용·경로와 일치해야 한다. 250폭과 251폭에서 같은 국소 지도, 제자리·경계·차단·도달 불가, 이동 중 굶주림 전환, 정지·재지정·반복 명령을 검사한다.
2. **게임 행동** — 같은 밭에 파종 후보만 나타나는 상태로 끝내지 않고 실제 파종·수확까지 진행한다. 음식·운반·구조·우선 건설·습격 추적·철수에서 각 대상 도착 조건을 확인한다. 작업 비교 시 돌봄 요청순이 보존되어야 한다. 현장 점유자는 정착민·습격자 각각을 검사하고, 두 명이 겹친 경우와 쓰러진 환자도 포함한다. 조리대 사용 칸에만 폰이 있을 때는 본체 공정이 증가해야 한다. 설계도를 놓은 뒤 바닥 물자를 떨어뜨려 벽·조리대만 물자 대기하는지도 확인한다.
3. **재현과 복원** — 고정된 이전 정착지 v1, 습격·장비 조합별 schema 2 표본과 새 schema 3을 단일 파일·이름 있는 슬롯 등 지원 진입점으로 읽는다. 합법적인 구 경로의 첫 칸이 새 최적 경로와 다른 운반 사례를 포함한다. 새 저장의 불가능한 대각·잘못된 시간·미지원 버전에서 정해진 복구 또는 거부와 원본 보존을 확인한다. 별도 Player 프로세스로 다시 열어 대조하고 임시 테스트 슬롯만 사용한다.
4. **측정과 화면** — 동일 PC·빌드 종류·해상도·배속·초기 시나리오에서 변경 전후 각각 1회 준비 실행 후 새 월드로 5회 반복한다. 32·250폭에서 모서리·고립 목표·세 폰 명령·밭 작업 선택(250폭은 1,024칸)의 처리시간 중앙값과 최댓값을 기록하고, 할당량은 개발 빌드끼리 비교한다. 일반 습격 추적도 같은 적 수·틱 구간으로 비교한다. 시험용 재검토선은 중앙값이 이전보다 2배 초과이면서 1ms 이상 증가하는 경우다. 넘으면 원인을 좁혀 재측정하고 해소 또는 수용 판단 전에는 성능 확인을 닫지 않는다. 실제 장애물 배치로 기준 비용을 산출하고 기존 4방향 칸 수를 단언하는 검사만 의도에 맞게 수정한다. [기존 성능 시나리오](../../Assets/Game/Demo/SettlementPlayerCheck.WorkFeedback.cs) · [기존 측정 기록](../Verification/2026-11-18-settlement-work-feedback.md)

각 단계에서 관련 EditMode를 확인한 뒤 최종 입력을 동결하고 통합 담당자가 전체 EditMode → PlayMode → Windows 빌드 → Player 실행·렌더 검사를 직렬로 수행한다. 새 검사 이름은 기존 manifest에 등록한다. 실행 명령과 결과 파일 확인 절차는 [검증 계획](../Testing.md)을 따른다. 사람 확인은 빌드 후 실제 경로와 장면을 안내해 ① 빈 땅에 대각 이동 지시 ② 한쪽 벽을 두고 같은 이동 지시 ③ 시공 중 다른 폰을 현장에 세웠다가 이동시키는 순서로 한다. 걸음의 부드러움·모서리 우회·현장 대기 이유를 구별할 수 있는지 별도 기록한다.

## 5. 검토와 다음 단계

세 담당이 초안과 현재 코드를 독립적으로 검토했다. 아래 보완은 문서에 반영한 결과이며 기능 검사와 성능 측정은 구현 뒤 수행한다.

| 검토 | 발견한 모순·실행 위험 | 반영 |
|---|---|---|
| 이동·작업 | 후보 점수를 비용으로 바꾸고 착수 검사를 칸 수로 두면 파종이 탈락한다. 습격자에는 정착민과 같은 화면 보간이 없다. | 비교 단위·돌봄 예외·파종 착수 검사, 두 탐색의 동일 결과, 습격자 논리 이동과 정착민 보간 범위를 명시했다. |
| 건설·점유 | 현재 조회 순서로는 담당자가 있는 공사의 대기 이유가 ‘예약됨’으로 덮인다. 파괴된 벽 수리는 예약된 다음 칸도 검사한다. | 시공 틱과 이동 틱의 선후, 자재 반입과 시공 대기, 실제 선택 패널의 대기 표시, 수리 전용 점유 규칙을 구분했다. |
| 저장·검증 | 기존 버전 번호를 덮으면 습격·장비 구분이 깨진다. 새 최단 경로를 강제하면 구 저장의 작업이 취소된다. 기존 Player 성능 장면은 4방향 칸 수를 요구한다. | 저장 형식 판독과 게임 규칙 버전을 분리하고 구 경로 보존과 새 저장 왕복을 각각 시험한다. 기준 장면을 이전 빌드에서 먼저 측정하고 바뀐 기대값과 성능 회귀를 별도로 평가한다. |
