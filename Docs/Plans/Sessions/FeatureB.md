## 3차 연결 검사: I1 → I2

별도 QA 세션을 추가하지 않고 SB가 맡는다. 범위는 다섯 기능의 통합과 기존 기능 회귀이며 장기 자급/전투/데모로 확대하지 않는다. 신규 제품 코드를 쓰지 않고 결함의 소유자에게 수정 요청한다.

| 단위 | 시험 구성 | 완료를 증명할 관측 |
|---|---|---|
| I1 실제 연결 | 자재로 침대/조리대 건설, 작물 재배/수확, 운반/조리/섭취, 개인 우선순위 적용 | 건설된 시설ID 실제 사용, 수확물 반입 추적, 생산 식사의 소비 추적, 종류별 생성/소비/각 보관 위치 합계 보존 |
| I2 중단·복원 | 운반/반입/시공/성장/조리 각각 정지·R·취소·통로 차단·출력 포화, S1/S2 연결 후 저장/복원 | 명령/UI는 즉시·시간은 불변, 권한/운반 정리 한 번, 원인 해소 후 정해진 시간 내 재개, 복원 후 같은 후속 명령에서 생산/소비 일치 |

SA가 저장 작성 중일 때 I1과 저장 전 I2를 작성한다. 저장 복원 사례는 데이터 목록과 기대 결과부터 준비하고 S1/S2 통합 후 실제로 실행한다. 테스트용 완성 조리대/재료만으로 I1을 통과시키지 않는다. 재개 상한 Tick은 시나리오의 경로 길이/작업 시간에서 계산해 S0과 고정하고 무한 대기로 검사하지 않는다.

기존 회귀는 이동/배속/Reset, 식사·수면, R/단일 점유/오래된ActionId/낙하, 바닥 수면자의 빈 침대 재선택, 물류/필터, 정지 즉시 반영, 저장 구역 도구 해제를 유지한다. 기존 공통 검사를 바꿔야 하면 S0에 요청한다. SA 제품 결함은 입력·실제·기대·실패 검사 이름으로 전달하며 직접 수정하지 않는다. SB 소유 재배/정책 결함은 S0이 검사 동결을 해제한 뒤 수정한다.

## 인계·검사 요청

변경 파일·기준/계약 버전·공개 읽기 상태·연결 요청·저장 항목·검사 이름/결과·미검증을 단위별로 제출한다. 실제 Unity 실행은 S0만 한다. 검사 대상 동결 중 제품/검사 파일을 수정하지 않는다. UI 이벤트 호출 검사와 사람의 실제 조작 확인을 구분한다.

현재 기록: F1~F2 구현과 S0의 통합 자동검증을 완료했다. 실제 사람 조작은 확인 대기다. J1~J2/I1~I2는 미착수이며 이번에 확장하지 않는다. 다음 행동은 S0의 최종 통합 입력 재동기화와 사용자 확인이다. 인계는 [작업 카드](../SettlementFiveFeatures.md) 및 [최종 검증 기록](../../Verification/2026-11-15-construction-farming.md)을 사용한다. 커밋은 하지 않았다.
