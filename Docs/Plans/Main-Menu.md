# 독립된 메인 화면 시안과 구현 계획

일반 실행은 독립된 타이틀 화면에서 시작한다. 새 게임을 누르거나 저장을 복원할 때 플레이 화면으로 넘어간다. 아래는 검토 후 채택한 설계이며 실행 검증 결과는 [현재 상태](../Status.md)를 따른다.

## 1. 핵심 설계

변경 전 [빌드 스크립트](../../Assets/Game/Editor/DemoBuild.cs)는 SimulationSandbox 하나를 시작 씬으로 등록했다. 종전 [일반 실행](../../Assets/Game/Demo/DemoBootstrap.cs)은 [SettlementShell.Initialize](../../Assets/Game/Presentation/SettlementShell.cs)에서 지도와 입력을 만들고 현재 월드에 연결한 뒤 ShowMainMenu를 호출했다. 이 순서에서는 메뉴를 보는 동안에도 정착지가 이미 생성되어 있었다.

타이틀 씬이 메뉴·저장 목록·화면 설정을 열고, 플레이 씬은 정착지와 HUD를 담당하도록 권장한다. 타이틀에서는 시뮬레이션 실행기 없이 저장 목록과 설정을 읽을 수 있도록 기존 저장소를 사용한다. 공통 글꼴·버튼 외형과 최근 저장 선택 규칙을 공유한다.

## 2. 시안과 동작

차콜색 단색 배경 중앙에 기존 메뉴 제목 ‘정착지’를 임시로 둔다. 아래에 ‘새 게임’, ‘불러오기’, ‘이어하기’를 한 줄씩, ‘화면 설정’과 ‘종료’를 마지막 한 줄에 둔다. 기존 한글 글꼴, 아이보리 글자, 올리브 강조색과 9분할 버튼을 쓴다. 저장이 없으면 이어하기를 비활성화하고 이유를 한 줄 표시한다.

새 게임은 기존 250×250 정착지로 진입한다. 불러오기를 누르면 타이틀에서 목록이 열린다. 취소하면 타이틀로 돌아오고, 정상 슬롯은 복원을 마친 뒤 플레이 화면을 표시한다. 실패하면 타이틀의 목록에 원인을 표시한다. 이어하기는 기존 최근 슬롯과 후보 확인 규칙을 따른다.

## 3. 구현 순서

1. 전용 타이틀 씬을 일반 실행의 첫 씬으로 등록하고 빌드 스크립트에 두 씬을 포함한다. 기존 진단 실행 인자는 해당 검사 경로로 전달한다.
2. 타이틀의 새 게임·선택 슬롯 진입을 플레이 초기화에 연결한다. 전환 중 중복 입력을 막고 실패 시 부분 생성된 플레이 상태를 정리한다.
3. 플레이 중 메인 메뉴 복귀는 기존 저장·취소 확인을 거친다. 복귀가 확정되면 플레이 씬을 해제한다. 저장 실패나 취소 시에는 기존 플레이 상태를 보존한다.

## 4. 검증 계획

세 담당의 검토를 반영했다. 시작 씬 순서와 실제 Windows 빌드 목록을 모두 바꾼다. 타이틀에서 저장 목록을 조회할 때 복원용 시뮬레이션도 생성하지 않도록 파일 구조·요약 검증과 선택 후 전체 복원을 구분한다. 최근 기록 누락 시 후보 확인을 보존한다. 플레이 씬의 저장 복원이 실패하면 HUD를 만들기 전에 타이틀 목록으로 복귀한다. 실제 일반 시작 경로에 관찰자를 붙여 검사하며 기존 진단의 직접 생성 경로를 첫 실행의 증거로 사용하지 않는다.

완료 기준은 두 씬이 등록된 Player에서 ① 타이틀·목록·설정에 실행기·지도·HUD 0개 ② 새 게임 250×250·3명과 중복 실행 방지 ③ 정상 저장의 Tick·슬롯 복원과 손상 파일 안내 ④ 게임에서 타이틀 복귀 후 이전 세션 해제와 재진입 ⑤ 두 해상도의 타이틀·목록 렌더와 입력 가능한 버튼 배치 ⑥ 기존 자동 검사·Windows 빌드·기존 진단 성공이다.

PlayMode에서 일반 시작, 목록 열기·취소, 설정 왕복 동안 실행기·지도·HUD가 생성되지 않는지 확인한다. 새 게임에 한 번 진입하는지, 정상 저장의 진행이 복원되는지, 손상 저장에서 오류와 목록이 남는지, 메인 복귀 후 다시 시작할 때 이전 세션이 남지 않는지 검사한다. 기존 자동 검사와 진단 인자 경로를 확인한 뒤 Windows Player 일반 실행에서 1920×1080 UI 100% 및 1280×720 UI 150%로 버튼과 상태 문구를 렌더 검증한다. 실제 입력감과 스타일은 사람 확인 항목이다.
