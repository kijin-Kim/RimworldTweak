# 모던 다크 HUD와 폰 눈

## 구현 계획

1. 자원·초상·도구·상세·저장 화면에 차콜 패널, 아이보리 글자, 얇은 경계와 작은 둥근 모서리를 공통 적용한다. 기존 지도 조작과 패널 배치를 기준으로 삼는다.
2. 선택 탭과 조리 계획서 행, 초상 및 일시정지·배속 버튼의 활성 상태를 올리브로 표시한다. 호버·키보드 포커스·누름 색은 지속 선택 표시와 독립적으로 처리한다. 조리 행은 반복 방식에 맞는 수량을 표시한다.
3. 기존 512px 얼굴 원화에 정면 두 점, 오른쪽 옆모습 한 점을 추가한다. 왼쪽은 기존 반전을 사용한다. 기존 얼굴 알파와 다른 부위는 그대로 유지한다.

## 완료조건

- 1920×1080/UI 100%와 1280×720/UI 150% Player에서 초상·조리 3행과 상세·건축가·작업표·모달의 배치 오류 0. 조리 행의 기존 작업자·수량·재료·거리·운반 입력과 탭·배속이 기존 게임 상태를 제어한다.
- 조리 행·활성 탭의 선택 표시는 포커스 이동에도 유지된다. 비활성 버튼은 Unity의 입력 경로에서 동작하지 않는다. 지도 클릭을 가로채는 장식은 추가하지 않는다.
- 앞·옆 얼굴 이외 37개 원화와 앞·옆 얼굴 알파가 종전과 일치한다. 세 헤어와 앞·뒤·양쪽 방향의 점눈을 확대·기본 줌·48px 초상에서 살핀다.
- Unity 자동 검사와 Windows 빌드를 통과하고 실제 Player 진단 렌더를 남긴다. 실제 조작과 스타일 수락은 마지막에 사용자 확인 항목으로 정리한다.

## 검토 반영

세 에이전트가 원화, UI 적용, 검증을 각각 읽기 전용으로 검토했다. 패널 색은 카탈로그의 9분할 이미지까지 연결한다. 이벤트 포커스와 선택 색을 분리하고 비활성 상태는 실제 Selectable 입력으로 검사한다. 눈은 헤어 아래 얼굴 그림에 넣어 기존 월드·초상 합성을 재사용한다. 모듈식 외형이 누락될 때 쓰는 예비 완성 그림은 기존 복구용 자산으로 유지한다.

## 적용과 검증 결과

- 차콜 패널과 버튼의 모서리를 기존 9분할 스프라이트로 그린다. 탭·조리 행·초상에 올리브색을 쓰고, 조리 행에 목표 재고·남은 횟수·계속 생산을 표시한다. 시안의 팔레트를 기존 패널 배치에 적용했다.
- 512px 얼굴 원화는 정면 두 개, 옆면 한 개의 11×17px 타원을 사용한다. 앞·옆 PNG만 변경됐고 두 그림의 알파와 나머지 37장 해시가 동일했다. 세 헤어에서 눈 중심의 헤어 알파가 0이었고, Player 확대 화면에서 정면 두 점이 눈으로 읽히는지 확인했다.
- 카탈로그 두 번 재생성 결과가 일치했다. EditMode 200/200, PlayMode 120/120, Windows 빌드 성공. 실제 Selectable 이벤트에서 저장 없는 이어하기의 클릭·Submit이 차단되고, 다른 버튼으로 포커스를 옮겨도 조리 행의 선택색이 유지됐다.
- 1920×1080/UI 100%와 1280×720/UI 150%에서 각각 HUD 32개 장면의 배치 이슈가 0건이었다. 기준 장면 5개도 통과했다. 근거는 `TestResults/map-work-20261118T150734906-capture`, `TestResults/map-work-20261118T150748494-capture`, `TestResults/20261118T150717530Z-ux-settlementart`다. 실제 게임 창의 자동 캡처는 단색이라 Player 카메라와 UI를 합성한 렌더를 확인했다.
