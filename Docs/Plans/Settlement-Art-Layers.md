1. **정면 원형.** 세 시안은 배경까지 합쳐진 비교 그림이다. 승인된 그림과 동일한 시점·선·색을 지시해 기본 폰 하나를 기준으로 잡고, 동일 크기 캔버스에 몸통·셔츠·열린 재킷·머리 바탕·짧은 헤어를 각각 투명 PNG로 제작한다. 목 중심, 머리 폭, 바닥 접점, 밑단 위치를 가이드에 표시한다. 생성할 때마다 가이드를 겹쳐 보고 어긋난 부위만 다시 그린다. 빈 옷 안쪽에 배경색이나 셔츠가 그려져 있으면 재작업한다.
2. **세 방향.** 정면을 기준으로 뒤·오른쪽을 만들고 왼쪽은 옆모습 반전으로 시작한다. 뒤에서 재킷의 열린 앞섶이 보이거나 앞머리가 얼굴 반대편에 남지 않게 한다. 비대칭 헤어·장비의 좌우 구별이 실제 디자인에 필요해질 때만 왼쪽 원화를 추가한다. 중립 색상으로 일괄 착색할 때는 피부·옷감·테두리가 같이 물들지 않는지 본다.
3. **환경 기준 장면.** 흙은 테두리 없는 불투명 정사각 타일을 반복 배치해 이음새를 본다. 나무·침대는 투명 PNG로 각각 제작한다. 기존 월드 크기(나무 1.32, 침대 1.08, 기본 폰 0.95 유닛 정사각 캔버스)를 시작값으로 삼되, 새 그림의 실제 줄기 밑면·침대 바닥·폰 하단에서 접점을 다시 잡는다. 침대 그림 크기와 점유 칸은 별도로 다룬다.
4. **변형 생산.** 기본 장면이 읽히면 헤어와 체형을 늘린다. 세 방향 기준 헤어 3종은 9장, 셔츠와 재킷 각 1종의 세 체형 대응은 18장이 제작 예상량이다. 얼굴과 헤어는 체형 사이에 공유하고, 옷은 목 중심과 깃 폭을 유지하면서 어깨·허리선을 다시 그린다. 셔츠만 입은 경우와 겉옷을 더한 경우를 조합으로 확인한다.
5. **바닥 무기와 확장.** 소총·칼은 각각 투명 PNG 한 장을 만들어 개발용 기준 장면의 흙 위에 표시한다. 첫 단계의 완료물은 바닥 크기에서 구별되는 그림이다. 실제 장착·운반·전투가 기획되면 해당 아이템 정의가 그림 키를 참조한다. 다음 제작 후보는 이미 게임에 나오는 조리대, 목재, 식재료, 식사, 성장 단계별 작물이다.

제작 담당은 원본과 게임용 출력을 구별해 키, 원본 경로·출처·사용 조건, 방향/체형, 캔버스 치수, 표시 크기, 접점, 사용처를 기록한다. 기존 자체 원화와 이번 자체 생성물을 사용하고 로컬 레퍼런스는 시각 비교에 쓴다. 투명 여백까지 같은 규격을 유지한다. 에셋에 맞춰 자동으로 잘라 각 부위를 개별 확대하면 조립 시 목·깃이 어긋난다.

## 2. 구조 변경 순서

| 순서 | 기존 코드와 변경 제안 | 인계·완료 기준 |
|---|---|---|
| 카탈로그와 임포트 | 일반 사물은 기존 `VisualCatalog`의 키·스프라이트·월드 크기·접점을 사용한다. `BuildArtAssets.Build`가 목록을 다시 작성하므로 생성 입력에도 신규 부위와 출처를 등록한다. 최초에는 폰 전용 조합 정의에서 체형·옷·헤어·방향별 기존 그림 키를 참조한다. | 재임포트와 카탈로그 재생성 뒤에도 키·출처·접점이 유지된다. 필수 부위/방향 누락은 제작 검사에서 식별하고, 선택하지 않은 겉옷은 정상으로 처리한다. |
| 폰 한 명의 월드 표시 | `WorldMapView`의 폰 ID와 월드 위치는 유지한다. 발밑에 자세용 부모를 두고 그 아래 부위를 한 묶음으로 그린다. 방향·반전·작업 중 회전과 눌림·바닥 수면·침대 수면 크기는 이 묶음에 적용한다. 이름·선택·게이지·운반물은 기존 위치 계산을 따른다. | 같은 발 위치에서 방향을 바꿔도 부위가 밀리지 않고, 나무나 다른 폰이 옷과 몸 사이에 끼어 그려지지 않는다. 매 갱신마다 부위 오브젝트를 새로 만들지 않는다. |
| 초상과 기존 호출부 | 정착민 바는 현재 `pawn.front` 한 장을 쓰므로 월드와 같은 외형 조합을 정면 UI 이미지로 보여준다. 기존 ID별 색은 초상 테두리 등 식별 표시와 실제 옷·피부색을 구분한다. 일반 명령 아이콘 등 기존 단일 키 사용처는 유지한다. | 월드와 초상이 같은 사람으로 읽히고, 선택·소집 상태 및 기존 명령 아이콘이 보인다. |
| 저장과 향후 변경 | 첫 장면은 고정 시연 외형을 사용한다. 플레이용으로 서로 다른 외형을 부여할 때는 기존 ID에 대해 명시적으로 고정한 기본 조합을 반환해 세이브마다 같은 모습을 재현한다. 사용자가 외형을 바꾸거나 장비가 소유물을 나타내는 기능이 도입될 때 안정적인 종류 ID와 구버전 기본값을 정하고 저장한다. | 카탈로그 배열 순서나 새 헤어 추가로 기존 폰이 바뀌지 않는다. 장비 기능 도입 시 착용 상태는 장비 데이터 한 곳이 소유하고 화면은 그 값을 읽는다. |

## 3. 통합과 완료조건

제작 담당은 원화와 부위 목록, 표시 담당은 폰 조립·월드·초상, 통합 담당은 카탈로그 생성기·저장 호환 경계와 Unity 실행을 맡는다. 먼저 한 체형·한 의상·세 방향으로 연결 규격을 공유한다. 통합 검사 중에는 원화·코드 입력을 고정하고 한 담당자가 import → EditMode → PlayMode → Windows Player 순으로 실행한다.

- **에셋 검사.** 흙 타일은 한 칸을 채우고, 나머지 원화는 알파가 보존돼야 한다. 방향·체형 대응표를 순회해 키 누락·중복·치수 불일치·참조 유실을 검사한다. 색인/규격 통과와 작은 크기에서의 식별성은 별도 결과로 남긴다.
- **동작 검사.** 이동, 네 방향 작업, 일시정지와 재개, 운반, 바닥·침대 수면, 저장 후 재실행에서 발 접점·외형·게이지의 기대 결과를 확인한다. 나무 뒤 선택과 두 폰의 교차 시 그려지는 순서도 본다.
- **기본 줌 기준 장면.** 같은 카메라·배치로 흙, 나무, 빈 침대와 사용 중인 침대, 폰, 바닥 무기 두 개를 비교한다. 일반 플레이와 분리된 개발용 무기는 저장·물자 수량·작업 선택에 영향을 주지 않아야 한다. 기본 줌과 축소 화면, 조리대 앞 작업, 동일 복장의 세 체형을 촬영한다. 진단 렌더와 실제 게임 창 캡처의 출처를 구분한다.
- **최종 미술 판단.** 이후 사용자가 기본 줌에서 세 체형, 소총과 칼, 나무 밑의 폰을 구분하고 작업 방향·진행을 읽을 수 있는지 본다. 첫 장면을 기준으로 선 굵기와 상대 크기를 조정한 뒤 나머지 에셋을 확대 제작한다.

| 담당 | 소스·시안에서 확인한 제약 | 합의안에 적용한 조치 |
|---|---|---|
| 원화·반입 | 세 시안 모두 1536×1024 RGB다. 기존 생성기는 PNG 하나를 단일 FullRect 스프라이트로 반입하며 최대 크기는 512다. | 시트를 통째로 반입하거나 가려진 부위를 잘라 쓰지 않는다. 맨머리, 셔츠의 가려질 부분도 온전히 제작한다. 긴 머리가 옷깃 앞뒤에 함께 걸칠 때만 앞·뒤 조각을 나눈다. 흙은 최소 3×3 반복으로 본다. 생성기를 두 번 실행해 키·에셋 참조가 동일한지 검사한 뒤 저장된 카탈로그로 Player를 빌드한다. |
| 월드 표시 | 폰 본체 정렬과 운반물 정렬 차이는 5이며 이동 중 두 폰의 값은 더 가까워질 수 있다. 기존 작업 애니메이션은 한 SpriteRenderer의 위치·회전·세로 배율에 직접 작용한다. | 발 위치 → 자세 → 좌우 반전 → 부위 순서로 묶고 폰당 SortingGroup 하나에서만 부위 순서를 적용한다. 상태 전환 때 기준 자세를 복구한다. 기존 ID별 표시 객체를 재사용하고, 벗은 겉옷은 끄며 월드 교체 때 폐기한다. 기존 PlayMode·Player 검사에서 단일 자식 스프라이트를 전제로 한 조회를 수정한다. 작업·좌우 반전 전후 같은 발의 화면 오차 목표는 동일 카메라에서 1픽셀 이내다. |
