# 림월드식 UI 구현과 완료 조건

기준은 [UI 인계](RimWorld-UI-Handoff.md)와 [기능 수락 기준](SaveLoad-UX-Art-Acceptance.md)이다. 전체 화면 카메라, 실제 UI 히트 검사, 기존 슬롯과 작업 명령은 소스에서 확인했다. 인계 문서의 화면 배치와 전환은 아래 단위로 적용한다. M1은 사용자 요청에 따라 추후 항목으로 둔다.

### 1. 화면 전환과 건축가

- 착수 당시에는 건설과 구역·채집이 별도 탭이었고 선택 정보와 작업표가 함께 표시됐다. 하단 건축가에서 구조·가구·생산·구역·명령을 선택하게 하고, 열린 작업표나 건축가가 선택 카드 자리를 사용한다.
- 건설 성공은 설계 하나를 선택하고 건축가를 닫는다. 구역 성공은 이전 선택을 복구한다. 채집은 도구를 유지한다. Esc와 우클릭은 도구만 취소하며, 초상 선택은 도구와 전역 패널을 접는다.
- 완료 조건은 다섯 카테고리의 기존 명령 접근, 위 전환 결과, 카메라 위치·줌·Tick 보존이다. 합성 입력과 실제 UI 연결 검사를 사용한다.

### 2. 가장자리 HUD와 대상 카드

- 자원은 좌상단, 초상은 상단 가운데, 시간과 스크롤 가능한 작업 문제는 우하단, 메뉴는 하단 오른쪽에 배치한다. 아래 바의 빈 배경에서 맵 입력을 받는다.
- 좌하단 대상 요약·상세·명령을 구분한다. 동적 겹침 순환, 위치 보기, 실제 대상별 수치와 명령, 건설 고스트 및 자원 구성 내역을 검증한다.
- 목표는 기존 게임 명령이 전부 접근 가능하고 두 대표 화면에서 요소 간 충돌 없이 읽고 조작할 수 있는 것이다.

### 3. 모달과 통합 검증

- 정지 메뉴 우하단, 파일·설정·확인·오류 중앙 배치, 본문 스크롤과 고정 확인·뒤로 가기를 확인한다. 모달 동안 맵·시간이 차단되고 실패/취소가 진행을 보존해야 한다.
- EditMode·PlayMode·Windows 빌드와 재실행 복원을 직렬 실행한다. 12조합 × 8필수 화면 배치 결과와 대표 화면 PNG를 확인한다. PNG의 실제 출력 경로와 사람 조작 결과는 각각 기록한다.

- 작업표는 헤더와 값의 열이 정렬되지만 현재 같은 폭을 사용한다. 이름 열 최소 122, 작업 열 최소 92, 좁은 폭에서 실제 가로 스크롤이 필요한지 확인하고 폭 계산과 접근을 맞춘다.
