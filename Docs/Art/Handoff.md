# 아트 작업 인계: 다음 세션 시작 문서

갱신: 2026-11-17. 조사·제작 계획을 기준으로 한 인계 문서다. 현재는 원화 4종과 연결 코드 초안이 있으며 Unity 반입 결과·실제 렌더·사람 확인은 미검증이다. 제작 파일·출처는 [구현 기록](Implementation-2026-11-17.md), 실제 진행은 [Status](../Status.md)를 따른다.

## 1. 먼저 알아야 할 결론

사용자는 **RimWorld 아트를 임시 그림으로 쓰고 나중에 교체하는 방향**을 제시했다. 최초 인계 당시에는 로컬 원본 조사와 제작 방법 보고까지 수행했다. 임시/최종 그림이 같은 표시 기준을 사용하도록 하고, **정착민·나무·침대·지면·선택 패널 5종을 같은 화면에서 검토한 뒤 전체 제작**으로 확장한다. 파일 제작을 게임 적용이나 시각 검증 완료로 취급하지 않는다.

최신 요구사항·완료·검사 기준은 [수락 기준](../Plans/SaveLoad-UX-Art-Acceptance.md)을 먼저 확인한다. 작물 중간 전환 1200 Tick은 샘플에서 조정 가능한 제안값이며, 첫 문 그림은 정적 표시로 두고 개폐 연출은 유보한다. 아래 조사 당시의 미정 표현보다 최신 수락 기준이 우선한다.

이번 요청은 다른 세션에서 볼 수 있도록 문서를 정리하는 작업이다. 이 문서가 신규 제작·게임 반입·도구 설치·구매·커밋·원격 게시의 실행 지시를 대신하지 않는다. 다음 세션은 최신 사용자 요청과 현재 소스를 확인하고 해당 요청 범위에서 진행한다.

### 읽는 순서와 문서 역할

1. [현재 상태](../Status.md): 실제 완료·미완료·검증 상태.
2. 이 문서: 인계 요약, 주의사항, 다음 행동.
3. [저장·UI·아트 전체 계획](../Plans/SaveLoad-UX-Art.md): 기능 범위, 렌더링 이관, 단계별 완료 기준.
4. [아트 상세 보고](2026-11-17-art-production-brief.md): 기능별 목록, 제작 규격의 이유, 생성 지시문, 도구별 사용 방법.
5. [로컬 원본 목록](local-art-inventory.json): 개별 파일의 정확한 경로·해상도·미리보기 상태.

공통 설명 방식은 최신 AGENTS 지침, 문서 운영은 [Workflow](../Workflow.md)를 따른다. 이 인계 문서에 공통 지침을 다시 복제하지 않는다.

| 구분 | 내용 |

| 현재 기능 범위 | 저장·불러오기 경험, UI·조작, 현재 생활·생산 기능에 필요한 아트 |
| 제외 | 전투·적·무기·치료·Fog of War, 새 생산/생활 규칙, 음향 전체 제작, 저장 썸네일. 자급 플레이테스트는 이번 선행 조건이 아님 |
| 추천 제작 방식 | 기준 5종 검토 → 물자·작물·시설·방향 변형 확대. 원화 생성과 규격 도형 제작을 구분 |
| 잠정 규격 | 1칸=1 Unity unit, 128 PPU, 지면 128×128, 높은 대상 128×192 또는 256×256, Bilinear 후보 |
| 샘플에서 정할 것 | 정확한 시점·팔레트·선 두께·광원, 최종 크기와 여백, pivot, 축소 범위, 성장 표시 전환점, 최종 에셋 수 |
| 미확정 | 원본의 별도 게임 사용 조건, 실제 반입 방식, Krita 설치/사용 가능 여부, 최종 스타일 채택 |

PPU는 이미지 몇 픽셀을 게임 공간 1단위로 표시할지 정하는 값이다. 위 수치를 이미 구현·합의된 규격으로 취급하지 않는다. 32/48px 비교는 설명용 검사 예시이며 최종 카메라 확대 범위를 확정한 것이 아니다.

## 3. 필요한 아트와 제작 순서

| 검증 가능한 묶음 | 필요한 표현 | 확인할 결과 |
|---|---|---|
| 기준 장면 | 정착민·나무·침대·지면·선택 패널 | 한 화면에서 시점·비율·지면 대비·가림을 판단할 수 있음 |
| 정착민 식별 | 앞/뒤/옆, 3명 색상 구분, 초상, 운반·수면 표시 | 방향이 바뀌어도 같은 사람으로 읽히고 이름·선택 표시가 유지됨 |
| 건설·시설 | 벽·문·침대·조리대, 설계/진행/철거 표시 | 기존 배치·사용 위치가 유지되고 벽 연결이 끊기지 않음 |
| 채집·재배·물자 | 나무·채집 식물, 작물 3성장 표현, 목재·식재료·식사 | 작은 크기에서 종류와 성장 상태를 구분하고 수량은 별도로 표시 |
| 바닥·구역 | 흙/풀 계열 후보, 경작/저장 표시 | 반복 경계가 두드러지지 않고 대상 선택을 방해하지 않음 |
| UI·작업 상태 | 패널·버튼·명령/상태 아이콘, 선택·소집·부족 표시 | 텍스트를 읽을 수 있고 실제 상태와 표시가 일치함 |

종류 수는 PNG 개수와 다르다. 벽 4방향 연결은 16경우를 표현해야 하지만 16개 독립 그림이 반드시 필요한 것은 아니다. UI 아이콘 20~30개는 후보 규모이며 중복 명령의 재사용을 고려해 실제 화면 확정 뒤 집계한다.

## 4. 도구 선택과 사용 방법

| 도구 | 역할과 선택 이유 | 실행 시 주의 |
|---|---|---|
| Codex 내장 이미지 생성 | 자연물·정착민·시설의 원화. 기준 그림을 참조하여 한 대상씩 수정/확장하기 편함 | 다음 세션에서 도구 제공 여부 재확인. 같은 시점·선·빛 등 유지 조건과 변경 조건을 나눠 지시. 투명 배경·정확한 크기를 요청했어도 실제 결과 검사 필요 |
| 코드 도형/벡터 | UI·선택 테두리·단순 패널·벽 접합처럼 치수와 반복 규격이 중요한 부분 | 자연물 원화를 전부 도형으로 대체하려는 계획이 아님. 텍스트는 이미지에 넣지 않고 UI로 표시 |
| Python/CLI | 원본 검색, 해상도·알파·여백·이름·참조·출처 검사 | PSD 단순 합성 출력을 정상 원본으로 단정하지 않음. 검사 성공은 미술 품질 보장이 아님 |
| Krita, 필요 시 | 사람이 레이어·외곽선·방향별 연결을 보정할 후보 | 표준 설치 경로 2곳에서는 찾지 못했으며 PC 전체 미설치를 확정한 것은 아님. PSD 완전 호환 미보장. 에이전트 GUI 자동화 금지 |
| Unity Editor C# 스크립트 | importer의 크기/접점, 종류별 그림 연결, 비교 장면·PNG 캡처 | 실제 제품의 겹침·선택·배치 검증에 사용. 테스트용 화면과 실제 사용자 조작 증거를 구분 |

현재 비픽셀 탑다운·소량 샘플에는 추가 생성 서비스나 픽셀 전용 도구를 선행 도입하지 않는 안이다. 기준 샘플에서 반복되는 한계가 드러날 때 도구 변경을 재검토한다. 상세 프롬프트 예시는 [보고서 4절과 6절](2026-11-17-art-production-brief.md)에 있다.

## 5. 반드시 보존할 표시·게임 규칙

- **같은 시점으로 배치한다.** 침대만 옆면이면 눕는 방향과 바닥 접점이 모호해질 수 있다. 동일 배치에서 시점 하나씩 바꿔 비교한다. 광원·선·팔레트도 기준 샘플에 기록한다.
- **실제 표시 크기로 판단한다.** 작물은 색뿐 아니라 잎 덩어리·높이로 성장 상태를 구분한다. 지면은 낮은 대비로 두고 사람·시설·선택 표시가 먼저 읽히게 한다.
- **바닥 접점과 논리 위치를 분리해 관리한다.** 이미지 중심 고정만으로 교체하면 높이가 달라질 때 발/시설 바닥이 이동한다. 불투명 영역의 접점과 크기를 확인하고 모든 이미지에 같은 정규화 pivot을 일괄 적용하지 않는다.
- **수량·이름·진행·선택을 원화에 넣지 않는다.** 상태를 별도 표시하면 수량이나 작업이 변해도 그림을 다시 만들 필요가 없다.
- **그림으로 통행·점유·사용 위치를 계산하지 않는다.** 이전 조사 시 `BuildingState`는 단일 위치를 사용하고 방향/문 개폐 상태가 없었다. `ConstructionRules.BlocksMovement`는 벽/조리대를 차단하며 `ServiceCell`은 Y-1이다. 착수 시 현재 소스를 다시 확인한다. 문 개폐 그림을 추가한다고 잠금이나 통행 규칙을 새로 만들지 않는다.
- **성장 그림이 새 게임 상태를 만들지 않는다.** 이전 조사에서 `CropStage`는 Empty/Growing/Mature, 성장 시간은 2,400 Tick이다. 3단계 그림은 기존 성장값의 표시 세분화안이며 중간 전환점은 미정이다.
- **저장 데이터에 그림을 묶지 않는다.** 종류→그림·크기·접점을 연결하는 `VisualCatalog`는 제안 이름이며 구현 완료가 아니다. 저장에는 기존 ID·종류·게임 상태를 유지하여 아트 교체 후에도 이전 저장을 읽게 한다.
- **반복·겹침·시간 상태를 검사한다.** 지면 3×3 반복, 벽 연결, 나무 뒤 선택 정착민, 운반물과 이름 겹침, Pause 중 이동/작업 연출 정지를 확인한다. UI 호버 등은 시뮬레이션 정지와 구분한다.

## 6. 발견한 자료와 현재 한계

원본 위치:

```text
C:\Users\kijin\Downloads\Ludeon public art assets\Game art source\Game art source - RimWorld
C:\Program Files (x86)\Steam\steamapps\common\RimWorld\Assets.zip
```

개별 경로는 [목록 JSON](local-art-inventory.json)에 있다. 조사 당시 설치 아카이브는 6,132항목, 그중 Textures 아래 3,418항목이었다. 대표 20개 다운로드 원본의 존재·크기를 읽고 합성 미리보기를 확인했다. **17개는 형태 확인, 침대·목재·식재료 PSD 3개는 색상 이상으로 추가 보정 필요**다. 원본 그림의 의도된 색이라고 해석하지 않는다.

설치본 `.dds.split`을 일반 DDS처럼 읽은 결과는 깨져 채택하지 않았다. 현재 참고 PNG는 다운로드 원본 기반이다. 새 세션이 같은 실패 경로를 반복하지 않도록 다운로드 원본과 목록부터 확인한다. 폴더 이름의 public은 별도 게임 사용 허가 확인을 대신하지 않는다. 원본 사용 조건·외부 배포 가능 여부는 아직 확정하지 않았다.

이 경로는 이 컴퓨터의 로컬 경로다. 다른 PC나 작업 공간에는 없을 수 있다. 특히 이 작업 공간의 문서와 미리보기는 아직 커밋하지 않았으므로 다른 worktree에 자동으로 존재한다고 가정하지 않는다. 누락 시 원본 경로/작업 공간을 확인하며 무단 게시·반입으로 해결하지 않는다.

## 8. 다음 세션의 실행 순서와 완료 기준

1. **현재 상태 재확인:** 최신 사용자 요청, Status, 전체 계획, 현재 소스, 로컬 원본 실존 여부 확인. 현재 작업 공간에 변경이 많으므로 관련 없는 변경을 되돌리지 않는다.
2. **기준 장면 준비:** 제작/구현 요청 범위에서 5종의 표시 규격과 샘플을 준비한다. 기존 도형·임시 그림·최종 원화를 구분하여 기록한다. 샘플 검토 전 전체 아트를 대량 생성하지 않는다.
3. **교체 가능한 연결:** 실제 구현 시 화면 표시와 게임 상태를 분리하여 종류별 그림 연결을 구성한다. 전체 계획의 월드 렌더러/입력 이관과 조율하고, 별도 UI나 게임 규칙을 임의로 추가하지 않는다.
