# 다음 단계 아트 조사와 제작 보고

다른 세션의 시작점: [아트 작업 인계](Handoff.md). 이 보고서는 조사 근거와 상세 제작 이유·예시를 보존한다.

작성: 2026-11-17. 범위: 저장·불러오기, UI·조작, 탑다운 2D 아트. 제품 구현·아트 채택·배포 승인이 아닌 조사와 제작안이다.

## 결론

현재 필요한 것은 정착민, 시설 4종, 자연물·작물, 물자 3종, 바닥, 작업·선택 표시, UI다. 전투·무기·적·치료·음향·저장 썸네일은 현재 범위 밖이다. 로컬 RimWorld 원본 묶음에서 대응 자료를 찾았다. 이미지 교체를 전제로 진행하되, 원본의 큰 외형·방향·상태를 우리 게임 규칙으로 가져오지 않는다. 먼저 정착민·나무·침대·지면·선택 패널의 5개 기준 샘플을 같은 화면에서 비교하고 전체 제작으로 확장한다.

사용자는 RimWorld 아트를 임시로 사용하고 추후 교체하려는 의도를 밝혔다. 이번에는 검색·분석·보고만 수행했다. 게임에 원본 아트를 반입하지 않았으며 사용 조건 확인과 실제 반입 여부는 별개다. 기존 문서의 독자 아트 제작은 최종 목표로 유지한다. 보고서 내 로컬 참고 이미지도 외부 게시용으로 승인된 것이 아니다.

## 3. 실제 만들 때 지킬 기준

### 화면 규격 — 추천안, Unity 샘플 후 확정

- 1칸=1 Unity unit, 128 PPU. 지면 128×128, 높이 있는 대상은 128×192 또는 256×256 후보. 캔버스가 커지면 표시 크기도 커질 수 있으므로 캔버스·불투명 영역·화면 크기를 각각 기록한다.
- 탑다운 기반의 약한 앞면 표현. 동일한 시점·광원(왼쪽 위 후보)·팔레트·외곽선. 지면은 저대비, 정착민과 시설은 명확한 실루엣. UI 상태 강조색은 장식 색과 구분한다.
- 바닥 접점(pivot)을 발/건물 밑면에 맞춘다. 모든 이미지의 정규화 pivot을 무조건 같은 값으로 두지 않는다. 머리·몸·운반물의 상대 위치도 별도 기록한다.
- 정착민 앞/뒤/옆은 기준 한 캐릭터를 참조하여 순차 제작. 측면 반전은 비대칭 도구에 적용하지 않는다. 초기에 8방향 걷기 프레임 전체를 만들지 않는다.
- 지면은 경계 반복 확인. 벽은 이웃 연결 규칙으로 조합하고 틈·끝부분을 확인한다. 자연물의 불규칙한 윤곽을 벽 접합부 제작에 그대로 적용하지 않는다.
- 물자 수량·작업 진행·이름·선택·위험은 별도 레이어. 이미지에 숫자·문구를 그리면 상태가 바뀔 때 그림까지 다시 만들어야 한다.
- Bilinear는 비픽셀 스타일의 후보. 실제 작은 크기에서 흐려지는지 확인하고 확정한다. 투명 가장자리, atlas padding, mipmap 적용 여부는 축소 화면으로 판단한다.

### 기존 게임과 충돌하지 않을 조건

`BuildingState`는 종류와 단일 위치를 보유하며 방향·문 개폐 상태 필드가 없다. `ConstructionRules.BlocksMovement`는 벽/조리대만 차단하고 `ServiceCell`은 Y-1이다. 따라서 조리대 그림의 가로 폭을 점유 칸으로 사용하거나 그림을 돌려 사용 위치를 변경하면 안 된다. 이번 아트 계획에서 문 열림/닫힘은 표시 연출 후보이며 새로운 잠금/통행 규칙이 아니다.

`CropStage`는 Empty/Growing/Mature이고 성장 시간은 2,400 Tick이다. 새싹/성장/성숙 3그림은 Growing 안의 중간 표시를 추가하는 방식으로 연결한다. 중간 전환 수치는 샘플 단계에서 정하며 게임 상태 enum이나 수확 조건을 바꾸지 않는다.

`VisualCatalog`는 예정 구조다. 종류→그림·크기·pivot·변형을 연결하고 저장에는 기존 ID·종류·상태만 둔다. 도형→임시 그림→최종 그림으로 교체할 때 기존 저장 파일과 동일한 칸 선택·점유·서비스 위치를 유지하는 것이 완료 기준이다.

## 4. 생성 방법과 예시 지시문

기준 샘플은 **정착민·나무·침대·지면·선택 패널 5개**다. 이 묶음으로 사람과 시설의 비율, 가림, 지면 대비, UI와 맵의 시각적 충돌을 함께 판단할 수 있다. 이후 물자/작물/시설 변형 순서로 확대한다.

1. 기준 보드에 시점·팔레트·외곽선·바닥 접점·최소 화면 크기를 기록한다. RimWorld 참고 자료에서 관찰한 원리를 적되 독자 외형의 기준 샘플을 만든다.
2. 제공된 이미지 생성 도구로 자연물·캐릭터·시설을 개별 투명 배경 에셋으로 생성한다. UI 패널·선택 테두리·벽 접합처럼 규격이 중요한 것은 코드 도형/벡터를 우선한다.
3. 한 번에 전체 시트를 요구하지 않고 기준 한 장→같은 대상의 방향/상태→다른 종류 순서로 만든다. 자연어로 크기를 요청했다고 실제 규격을 만족했다고 보지 않는다.
4. PNG 규격·알파·여백·접점·팔레트·출처를 검사한다. PSD 레이어 보정은 사용자/아티스트 또는 지원하는 파일 처리 방식으로 수행하며 GUI 자동화를 사용하지 않는다.
5. Unity 샘플 화면에 5종을 같이 넣어 축소/기본/확대, 겹침·선택·야외/구역 표시를 비교한다. 원본 크기에서만 예쁜 그림은 채택하지 않는다.
6. 기준을 통과한 뒤 전체 제작과 importer/atlas 연결을 한다. 도구가 반복해서 방향·접점을 놓치면 단순 자체 도형을 유지하고 보정 범위를 줄인다.

정착민 생성 지시문 예시:

> 독자적인 정착지 시뮬레이션용 비픽셀 2D 캐릭터 한 명. 탑다운 게임에서 앞쪽을 보는 뷰. 작업복을 입은 작은 머리와 몸, 작은 화면에서도 읽히는 실루엣. 첨부한 자체 기준 샘플과 동일한 시점, 외곽선과 광원. 투명 배경, 전신이 캔버스 안에 들어오고 발밑 접점이 명확함. 이름, 선택 표시, 소품 배경, 글자 없음. 출력 후 128 PPU와 실제 표시 크기는 별도 검증한다.

침대 생성 지시문 예시:

> 같은 자체 기준 스타일의 단일 목제 침대. 베개·덮개·프레임이 작은 크기에서 구별됨. 약한 앞면이 보이는 탑다운, 광원 왼쪽 위. 투명 배경, 바닥 접점을 식별할 수 있고 외형 전체가 잘리지 않음. 캐릭터, 사용 중 표시, 바닥 타일, 숫자 없음. 우리 게임의 단일 논리 위치를 바꾸지 않는 표시용 외형이며 최종 화면 비율은 샘플에서 조정한다.

지면 생성 지시문 예시:

> 같은 팔레트의 낮은 대비 흙 타일. 위에서 본 질감, 개별 돌·풀에 과도한 강조 없음. 반복 배치 시 모서리와 경계가 두드러지지 않는 패턴. 캐릭터·그림자·시설·구역 경계 없음. 지면은 불투명 출력. 생성 후 3×3 반복 화면으로 이음새를 검증한다.

이번 완료: 계획/소스 대응, 로컬 원본 찾기, 대표 20개 파일·해상도 조사, 17개 형태 확인/3개 PSD 보정 필요 식별, 제작 기준·지시문·시각 보고·보고 지침 추가. 문서 링크 및 보고서 스크립트 정적 검사 수행.

이번 미실행: 새 게임 아트 생성, RimWorld 아트의 게임 반입, Unity import/테스트/빌드, 최종 게임 화면 캡처, 사람 조작. 보고서의 참조 이미지·설명 그림은 실제 신규 게임 화면이 아니다. 인터랙티브 자료는 코드/데이터 검사만 하며 브라우저 UI 자동화를 수행하지 않는다.

검사 기록: `inspect_local_art.py`로 대표 20개 파일·해상도 읽기 완료. 접촉 시트를 직접 열어 17개 형태 확인/3개 합성 이상을 구분했다. `build_art_explorer.py`로 정상 확인한 6개 참고 이미지를 포함했고, `verify_art_report.cjs`의 DOM 대용 객체 검사에서 6대상×3배율의 그림/설명 갱신, 접점 고정, 그림 범위를 확인했다. 이것은 브라우저 렌더 검사가 아니다. 보고서 로컬 링크·원본 20경로 실존 및 변경 문서 `git diff --check` 통과. 인터랙티브 문서의 실제 표시·사람 조작은 미검증이다.

다음 구현 요청 시 기준 샘플 5개부터 제작한다. 에이전트는 원본·알파·규격·연결 검사와 Unity 스크립트 렌더 캡처를 수행할 수 있다. 사람은 대상 식별, 선택·확대·축소 감각과 스타일 선호를 확인한다. 현재 사용자에게 실행이나 구매를 요청하지 않는다. 커밋·외부 게시 없음.

## 6. 후속 설명: 고려 사항과 도구 사용 이유

2026-11-17 사용자 후속 요청에 따른 제작 제안. 새 게임 아트를 만든 결과가 아니다.

### 이유와 사례

- 시점: 정착민과 나무는 위에서 내려다보는데 침대만 옆면이면, 침대의 바닥 방향과 누울 위치가 모호해진다. 같은 배치에서 침대 시점만 바꾼 설명 그림으로 비교한다. 시점·광원·외곽선·팔레트를 기준 샘플로 고정하되 한 번에 여러 변수를 바꿔 원인을 흐리지 않는다.
- 식별: 성장 중과 성숙 작물이 같은 외형이면 매번 선택 정보를 읽어야 한다. 색만 바꾸는 대신 줄기 높이·잎 덩어리도 구분하고 실제 표시 크기로 축소하여 비교한다. 32/48px는 보고서의 검사 예시 크기이며 최종 줌 규격으로 확정한 것은 아니다.
- 교체: 새 그림의 캔버스 높이가 바뀔 때 중심만 맞추면 발/시설 바닥이 이동한다. 불투명 영역의 바닥 접점과 표시 크기를 따로 맞추고 기존 논리 위치·사용 위치는 유지한다. 수량·선택·진행 표시를 이미지 밖으로 분리하여 한 그림을 여러 상태에서 재사용한다.
- 반복·겹침: 흙 한 장이 좋아 보여도 반복하면 경계선이 드러나고, 나무 한 장이 좋아 보여도 사람을 가릴 수 있다. 3×3 반복, 벽 연결 경우, 나무 뒤 선택 정착민을 실제 Unity 화면에서 확인한다. 이번 설명 자료는 그 검증을 대신하지 않는다.

### 도구별 역할과 실행 방식

| 도구 | 왜 사용하는가 | 어떻게 사용하는가 / 한계 |
|---|---|---|
| Codex 내장 이미지 생성 | 자연물·캐릭터·시설의 원화와 스타일 후보를 대화로 수정하기 편함 | 기준 5종부터 한 대상씩 생성. 자체 기준 샘플을 참조해 방향·성장 변형을 순차 제작. 불변 조건과 변경할 조건을 나누어 지시. 투명 배경 요청 후 실제 알파·가장자리·크기는 검사. 일관성·정확한 규격을 자동 보장하지 않음 |
| Codex의 코드 도형/벡터 제작 | 선택 테두리·UI 아이콘·벽 연결처럼 선 두께와 치수가 정확해야 하는 표현에 적합 | 같은 좌표·선·여백 규칙으로 생성. 패널 모서리는 유지하고 가운데만 늘리는 9-slice 적용. 텍스트는 별도 UI. 복잡한 자연물의 원화에는 사용하지 않음 |
| Python/파일 CLI | 파일 발견·해상도·알파·이름·출처·참조 누락 등을 반복 검사하기 좋음 | 검사표와 결과 목록 작성. 일반 창작 이미지 편집은 이미지 생성 도구로 수행하고 픽셀 단위 수작업은 아래 보정 경로 사용. PSD 단순 합성 결과가 정상이라고 가정하지 않음 |
| Krita — 필요 시 사람 보정 후보 | 레이어를 보며 외곽선·연결 부위·투명 가장자리를 직접 조정 가능 | 사용자/아티스트가 문제 PSD를 열어 레이어와 색을 확인하고 PNG로 출력. 표준 설치 경로 2곳에서는 실행 파일을 찾지 못했으므로 현재 설치·사용 가능을 확정하지 않음. PSD 완전 호환이나 문제 해결을 보장하지 않으며 에이전트 GUI 조작은 하지 않음 |
| Unity Editor C# 스크립트 | 실제 게임에서의 크기·정렬·선택·배치가 최종 품질 기준 | importer의 PPU/pivot, 종류별 Sprite 연결, 필요 atlas, 비교 장면과 PNG 캡처를 자동화. 별도 게임 규칙을 이미지에서 계산하지 않음. 실행 시 기존 편집기 잠금과 직렬 검사 원칙 준수 |

사용 흐름: 기준 샘플 5종 → 원화 생성/규격 도형 제작 → 파일 검사·필요 보정 → Unity 동일 장면 배치 → 축소/겹침/반복/교체 확인 → 통과한 규격으로 나머지 제작. 초기 권장 128 PPU는 샘플에서 확정한다. 여러 생성 서비스를 동시에 도입하거나 픽셀 전용 편집기를 선행 도입하지 않는다. 현재 비픽셀 탑다운과 소량 기준 샘플에는 기존 제공 도구부터 검증하는 편이 설정 부담이 적다.

실제 생성 지시에는 대상, 사용 장면, 유지할 기준(시점·광원·선·팔레트), 변경할 부분, 투명/불투명 배경, 제외할 요소, 출력 후 검사 크기를 포함한다. 예: “자체 승인된 나무 샘플과 동일한 시점·선·빛을 유지하고 채집 식물 한 개만 생성. 낮고 넓은 잎 덩어리로 나무와 구분. 투명 배경. 바닥 타일·선택 테두리·숫자 없음. 출력 후 실제 축소 크기에서 확인.”

도구 근거: [Krita PSD 지원과 한계](https://docs.krita.org/en/general_concepts/file_formats/file_psd.html), [Unity 6.3 9-slice](https://docs.unity.com/en-us/engine/6000.3/manual/unity2d/sprite/9-slice/9-slicing), [OpenAI 이미지 생성](https://developers.openai.com/api/docs/guides/image-generation). 내장 도구의 현재 제공 여부는 세션 도구 목록에서도 확인했다.

설명 자료 검증: `prepare_production_cases.py`로 로컬 참고 5종과 참조/ID 검사 통과. `verify_production_cases.cjs`로 주제 3개·축소 5크기·교체 2높이·상태 복원의 코드 경로 검사 통과. 리터럴 HTML과 한글 레이블 검사도 통과했다. 브라우저 렌더·사람 조작·Unity 실행은 별도 미검증이다.
