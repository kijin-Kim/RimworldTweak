# 첫 습격 기획 검토 · 2026-11-19

[첫 습격 시나리오](../Plans/FirstRaidScenario.md) 초안을 작성한 뒤 플레이, 규칙·저장, 검증 담당 세 에이전트가 각자 읽기 전용으로 검토했다. 주 담당자가 각 의견과 대표 배치의 DLL 실행 결과를 다른 담당자에게 전달했다. 세 명 모두 아래 수정에 동의했다.

| 관점 | 초안에서 발견한 문제 | 합의한 수정 |
|---|---|---|
| 플레이 | ‘동쪽으로 간다’만으로 승리를 반복하기 어렵다. 겹친 적은 그리는 순서와 클릭 순서가 다를 수 있다. 시험 전환은 현재 월드를 교체한다. | 서로 다른 방어 칸과 두 번의 표적 지정 시점을 고정했다. 맨 위 적을 클릭하고 그 적이 사라지면 같은 칸의 남은 적을 지정하게 했다. 월드 교체는 전환 전에 안내한다. |
| 전투 규칙·저장 | 시작 버튼과 실제 명령이 철거 예정·진입 차단을 다르게 다룬다. 새 표적 지정과 같은 표적 재지정은 준비도에 미치는 효과가 다르다. 복원된 공격 표적과 현재 UI 선택도 수명이 다르다. | 읽기 전용 시작 판정을 공유한다. 정지 중 바뀌는 상태, 우클릭이 닫는 모드, 복원 직후와 사수 재선택 때의 강조 기준을 R1·R3·R7에 넣었다. |
| 검증 | 기존 Player의 승리에는 직접 선택·시간 진행 호출이 섞였다. 기존 PlayMode는 첫 지정 뒤 초기화한다. | 배포 DLL의 100·110·130틱 관찰값을 규칙 근거로 삼는다. 화면 명령과 정상 시간 진행을 사용한 Windows 승리, 렌더, 사람의 직접 확인은 향후 각각 검증한다. |

적 선택창을 추가하는 대안 대신 기존 표식의 표시·클릭 순서를 맞추기로 했다. 표시는 월드의 보호 목표·표적 ID에서 읽고, 시험 진입은 기존 저장과 전환 안내를 사용한다. 별도 자동 저장 슬롯과 표시 전용 저장 필드는 이 시나리오에 필요하지 않다는 결론이다.
