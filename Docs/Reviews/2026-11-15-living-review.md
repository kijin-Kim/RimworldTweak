# 생활 기능 병렬 구현과 검토

> 상태: 사용자의 구현 목표 재개 후 교차 검토. 실제 검사 증거는 별도 검증 기록을 따른다.
2026-11-15. 공통 계약은 [Living.md](../Contracts/Living.md). Simulation/Presentation/Tests는 파일 소유권을 분리해 병렬 작성, root는 Runtime·Player smoke·통합·문서 담당. 검토 합의와 실제 테스트 결과를 구분한다.

## 선택 근거

불변 seed와 World 실행 상태를 분리하고 식량은 예약 시가 아니라 행동 완료 시 소비한다. 운반·인벤토리를 도입하지 않아 중간 취소에서 가상의 반환 물자를 만들 필요가 없다. 침대 소유권은 일반 타일 충돌과 구분한다.

기존 이동 검사는 생활을 끈 Sandbox fixture로 의미를 유지한다. 실제 데모의 Runtime 기본은 생활이 켜진 LivingScenario로 전환하며 기존 검사 통과만으로 자동 생활을 검증했다고 주장하지 않는다. 별도 생활검사와 실제Player 2400Tick·배속·상태별Reset 검사를 추가한다.

생활 우선수위에 의해 수동이동/Stop이 거부될 수 있으므로 LifeBusy 이유를 명시한다. 식량이 없을 때 매Tick 수면을 깨우지 않으며, 경로/자원 변화 또는 제한된 주기로 재평가하여 예약 고착과 반복 탐색을 줄인다.

## 재개 후 교차 검토와 반영

Simulation·Tests 검토자가 독립적으로 회복 중 침대 삭제 결함을 확인했다. 휴식도가20을 넘으면 기존 시작 조건만으로는 대체 수면이 시작되지 않았다. root가 그 Tick에 중단된 수면 의도를 보존하고 결정 단계에서 다른 침대/바닥을 선택하도록 수정했다. 새 수면의 회복은 다음 Tick부터 적용한다. 테스트 담당자는 회복 후 삭제 경계를 보완한다.

검사 담당자가 Pause 욕구 불변, 우회/최단 후보, 생식 대안, 침대 경쟁, 배속 경로·예약 소유자 비교, 화면 부족 이유 등의 누락을 보고하여 보완한다. root는 Player 배속 비교가 실제로 진행한 상태인지 확인하도록 양쪽300Tick을 명시적으로 요구한다. SetSpeed는 기존 계약대로 정지를 해제한다. Presentation 검토자가 이를 잘못 가정한 Pause 테스트를 찾아 수정 요청했고, 수면 진행이 60/0처럼 보이는 표시도 지적하여 수면 시간과 기상 기준을 분리한다. 첫51개 통과만으로 완료 판정하지 않는다.
