# 일반 습격 표적 선정 계획 교차 검토

2026-11-19. [구현 계획](../Plans/DebugRaid.md) 초안 작성 후 두 에이전트가 코드와 계획을 독립적으로 읽었다. 전투 담당은 틱 순서·공격·이동, 저장 담당은 저장 파일과 추첨 재현을 검토했다. 주 담당자가 서로의 제안을 전달했고 두 사람 모두 통합안에 동의했다. 문서 편집은 주 담당자만 수행했다.

| 관점 | 발견한 문제 | 반영한 기준 |
|---|---|---|
| 전투 | 적 HP 50, 사격 25이므로 두 발 동시 명중은 치명적이다. 이 경우만 검사하면 합산 피해를 받고 살아남은 경우의 추첨 횟수를 알 수 없다. | 5+5는 규칙 검사에서 추첨 1회, 실제 사격 1발은 1회, 두 발 동시 제거는 0회로 나눴다. |
| 표적 변경 | 이전 표적의 재탐색 대기·이동 도중 진행·이미 성립한 근접 공격을 잘못 넘기면 새 표적에게 즉시 피해를 주거나 이동이 지연될 수 있다. | 기존 타격을 한 번 반영하고 새 표적의 이동·공격은 다음 틱부터 진행한다. 다음 칸이 바뀌는 경우만 이동 진행을 초기화한다. |
| 저장 | 현재 파일 읽기와 월드 검증이 각각 버전을 확인한다. 새 코드로 다시 쓴 파일만 읽으면 실제 구버전 호환을 입증할 수 없다. | 변경 전 파일을 게임의 정상 읽기 경로에 넣는다. 새 회차의 필수 값 손상은 명시적으로 거부한다. |
| 난수 | 첫 추첨 전 저장만 검사하면 불러올 때 난수 진행이 처음으로 되돌아가는 오류가 가려진다. | 적격 피격당 1회 소비, 무피격·치명 피해·강제 재선정은 0회. 0%·100%도 같은 소비 규칙을 적용하고 이미 소비한 뒤의 파일로 다음 상태와 결과를 대조한다. |

확률 기본값은 사용자 결정 전 시험안으로 둔다. 접근로 정책, 공병·시설 공격은 추가하지 않았다. 이번 검토의 결과는 요구사항과 검사 설계이며 게임 실행 증거는 구현 후 수집한다.
