# 조리·작업계획 교차 검토

2026-11-15. S0 통합, SA 조리, SB 작업계획. 각 기능은 별도 worktree의 소유 파일에만 작성했고 World/Runner/View/검사 실행은 S0가 맡았다. Unity 입력 동결 중 기능 담당은 읽기 검토만 수행했다.

| 제안자 | 확인한 문제 | 채택한 변경/근거 |
|---|---|---|
| SA | 주문 삭제·재생성 뒤 목록 삽입순과 시설ID순이 달라짐 | 회차 재평가를 stove ID순으로 고정, 신규 시작과 목표 하향 회귀 추가 |
| SA/SB | 기존 출력 스택에 추가한 식사의 CreatedTick 미갱신 | 산출 Tick 갱신, 빈 출력 재사용 뒤 같은 Tick 운반 금지 검사 |
| SA | 접근 불가 첫 조리대가 목표를 선점 | 신규 회차 전에 담당 설정·실제 경로·재료 접근 검사, 두 조리대 경쟁 검사 |
| SB | NoWorker 집계는 단위검사만 있고 실제 UI 미연결 | World 읽기 진단과 화면 연결, 실제 조리대 끔→켬/재료 부족 전환 검사 |
| SB | 끔→켬 뒤 이전 Disabled 안내가 남음 | 설정 재활성 때 오래된 안내 제거, Tick 없이 UI 검사 |
| SB | 조리대 선택 중 물류 보기를 매Refresh 다시 닫음 | 대상이 바뀔 때만 자동 열기, 닫힘 유지/수동 재열기 검사 |
| S0 | 렌더에서 조리대 이름 중복·작업 중인 소유자를 보류처럼 표시 | 중복 이름 제거, 정상 담당 작업과 보류 상태 문구 구분 |

출력의 기존 잔량까지 한 Tick 지연하는 방식을 채택했다. 스택 단위 독점에 맞으며 산출만 분리한 새 스택/추가 권한을 도입하지 않는다. 파일 저장과 조리 외 신규 작업은 구현하지 않았다. 검토 합의 자체를 성공 증거로 취급하지 않고 [실제 검사 기록](../Verification/2026-11-15-cooking-work-policy.md)으로 판정한다.
