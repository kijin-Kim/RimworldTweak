# 작업 1 병렬 구현 검토

2026-11-15. [공통 계약](../Contracts/MovementTime.md)을 작성한 뒤 파일 소유권에 따라 병렬 구현했다. 검토 의견은 실제 검증 증거와 별개다.

- movement_sim: 순수 C# 상태·BFS·명령·Tick·통행 변경.
- movement_view: 같은 World의 위치 표시, 선택·경로·목적지·입력·단축키.
- movement_tests: 기존 의미 보존과 이동·시간·입력 회귀 검사.
- root: Runtime 시간 전달, asmdef·Player smoke, 통합 및 단일 Unity 실행.

## 설계 판단

불변 초기 seed와 실행 상태를 분리해 Reset과 월드 격리를 유지한다. 작은 맵의 동일 비용 경로는 이웃 순서를 고정한 BFS로 재현한다. 대각 이동·다중 선택·정착민 충돌·보간은 이번 승인 범위에서 제외한다.

명령을 받는 순간에는 ID/범위를 검사하고 다음 Tick에서 경로를 검증한다. 정지 중 명령을 예약하면서도 위치와 진행이 바뀌지 않게 한다. 실패 명령은 기존 유효 명령을 보존한다. 통행은 이동보다 먼저 적용해 닫힌 타일에 들어가지 않는다.

배속은 Runtime이 공급하는 게임 시간에만 적용한다. 이동 칸당 Tick은 바꾸지 않는다. 초기값은 5 Tick/칸이며 Step/배속 결과를 같은 게임 시간에서 비교한다. 실제 프레임 지연으로 현실 시계의 정확한 순간을 보장한다고 주장하지 않는다.

## 통합 검토 기록

- root가 Simulation 1차 코드를 검토해 명령·통행 적용 순서, 외부 readonly 상태, 월드별 경로와 대기열, Tick overflow 사전검사를 확인했다.
- LastCommandError는 월드의 마지막 명령 처리 결과다. 여러 정착민의 명령이 같은 Tick에 처리되면 뒤의 성공/실패가 갱신한다. 정착민별 오류 이력은 이번 범위에 없다.
- 이동·선택 overlay는 기존 WorldMarker 수와 분리하고 Reset 뒤 전체 UI 객체 수가 증가하지 않아야 한다. 이를 화면 담당자와 검사 담당자에게 전달했다.

- Simulation 담당의 읽기 교차 검토에서 Runtime 배속·Reset과 Player smoke의 동기 시간 비교·차단 fixture가 계약과 일치함을 확인했다. 최종 캡처는 겹침 허용 정책을 바꾸지 않고 Tick10으로 골라 세 정착민이 보이게 했다.
- 화면/검사 담당 협의로 CommandFeedbackText getter를 계약에 추가했다. 오류 코드만 검사하지 않고 사용자에게 보이는 거부 문장도 검증한다.
- 첫 EditMode 컴파일은 NUnit Does.Not.Contain(GridPosition) 표현식 타입 오류로 실패했다. root가 Has.No.Member로 고쳐 검사 의미를 유지했다. 실패 결과는 20261115T073120671Z-b61361c6에 보존하고, 재실행 20261115T073152467Z-e3a113f4에서 33개 통과·입력 해시 불변을 확인했다.

- Windows smoke와 PNG 검토에서 경로 점이 목재 수량 중앙을 가리는 문제를 발견했다. 숫자를 가리지 않도록 타일 하단 여백으로 이동하고, 목적지는 별도 테두리가 있으므로 마지막 점을 생략했다. 화면 담당자는 하단 점 범위가 타일 안에 유지됨을 계산해 교차 확인했다. 선택/이동 로직과 실제 Path는 바꾸지 않았다. 최종 소스로 검사를 다시 수행한다.
