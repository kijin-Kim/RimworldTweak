# 모던 HUD의 림월드식 조작 대조

[림월드 공식 화면과 설치본 분석](RimWorld-UI-Reference.md), [모던 HUD 장면](../Verification/Images/modern-hud-building.png), [조리 3행](../Verification/Images/modern-hud-bills.png)을 비교했다. 지도 위 가장자리 정보, 하단 관리 메뉴, 좌하단 선택과 명령 흐름은 참고 방향에 맞는다. 현재 차콜·아이보리·올리브로 자체 디자인을 유지한다.

| 독립 검토 | 확인한 문제 | 보완 및 완료조건 |
|---|---|---|
| 지도와 명령 | 건축가의 빈 면이 지도를 가리고 선택한 타일이 카테고리와 별도로 표시되지 않는다. 이동자 그림과 클릭 칸도 달라질 수 있다. | 패널을 현재 도구 수에 맞춘다. 도구 전환과 취소에서 타일 색이 즉시 바뀐다. 지도 클릭은 화면에 그려진 이동자의 기준 칸을 사용한다. |
| 조리 | 새 계획서가 생성되어도 이전 행이 선택된다. 계속 생산에서 재고 목표 도달과 수량 버튼을 볼 수 있다. | 새 ID를 선택하고 화면에 보인다. 계속 생산·목표 재고·지정 횟수의 표시와 판단을 일치시킨다. |
| 화면 계층 | 작은 화면에서 조리 상세로 스크롤하면 어떤 계획서를 편집 중인지 찾기 어렵다. 저장 경고와 다중 행 버튼도 화면에서 비슷한 강도로 보인다. | 선택한 계획서 이름과 상태를 상세 상단에 유지한다. 경고 묶기와 전체 조작 재배치는 후속 후보로 기록한다. |

사용 가능한 조작을 명확히 하기 위해 우클릭 이동 명령에 소집 조건도 표시한다. 기존 저장·도구 입력·시간 흐름을 회귀 검사하고, 두 해상도의 Player 진단에서 지도 가림과 조리 행·상세를 다시 비교한다.

## 적용과 확인

- 건축가는 1920×1080/UI 100%에서 880×276에서 428×174로 줄였다. 선택한 건설·구역·채집 타일에 테마의 올리브색을 적용했다. 작업표는 별도 크기와 스크롤을 사용한다.
- 새 조리 계획서는 생성된 ID를 선택하고 해당 행으로 스크롤한다. 목록을 내려도 상단에 선택한 계획서 ID와 상태가 표시된다. 계속 생산은 재고 목표에서 멈추지 않으며 수량 버튼이 비활성화된다. 실질적으로 동일한 설정을 받아도 진행과 담당자 예약을 보존한다.
- 폰의 좌클릭은 이동 중 그려지는 위치의 칸을 우선 사용한다. 미소집 상태에서는 대상 우클릭 메뉴의 이동을 비활성화하며, 혼합 그룹은 이동 가능한 인원을 표시한다.
- EditMode 200/200, PlayMode 120/120, Windows 빌드 성공. PlayMode에서는 추가한 계획서에 즉시 수량 적용, 미소집 컨텍스트 명령 비활성, 작업표의 가로·세로 스크롤과 물리 입력 모의 검사를 통과했다. 첫 시도에서 닫힌 상세의 스크롤 참조와 같은 탭 재개 시 작업표 크기 재설정을 발견해 보정했다.
- 최종 Player에서 1920×1080/UI 100%와 1280×720/UI 150%의 32개 화면씩 배치 이슈가 없었다.
