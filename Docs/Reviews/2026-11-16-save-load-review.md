# 저장·불러오기 교차 검토

2026-11-16 KST. S0는 실제 상태 복원/시간/UI 연결, SA는 DTO/검증/파일서비스/패널, SB는 실제 단계 왕복 검사를 맡았다. 모든 Unity 실행은 S0에서 입력을 동결하고 직렬 수행했다.

- SA/SB 공통: 수량 범위만 맞아도 물자가 늘어난 파일을 받아들일 수 있었다. 초기 물자+생산+외부 추가−외부 제거−생활 소비−건설/조리 소비+철거 반환과 현재 물자/운반/현장/투입분을 long 장부로 대조한다. Meal 생산은 Produced에 이미 포함하므로 중복 가산하지 않는다.
- SB: 식사 기간0, 조리 중 채집 단계, 완공 벽/조리대의 통행 차단 누락을 거부해야 한다. S0가 행동 단계·위치·기간·시설 정합성을 확인하고 원본을 바꾸지 않는 거부 검사를 추가했다.
- SA: 저장 전 검사와 불러오기 검사의 강도가 다르면 나중에 읽을 수 없는 파일로 정상 슬롯을 덮을 수 있다. 저장 전과 임시 파일 재읽기 뒤에도 실제 후보 복원을 검증한다.
- 파일 실행 검사: BCL reader가 정상 JSON 뒤 추가 root를 무시했다. 단일 최상위 object 경계/문자열 escape/깊이 검사 후 BCL 역직렬화하며 trailing content 검사는 그대로 유지했다.
- S0: 수면은 고정된 종료 시간이 아니라 휴식 수치로 끝난다. 식사와 같은 진행 상한을 적용해 정상 수면을 거부하던 검증을 수정하고 침대·바닥 수면의 실제 파일 왕복을 검사한다.
- SA/S0: 삭제된 조리 주문도 시설의 같은 Claim 객체를 참조한다. 삭제 기록의 점유 정보까지 시설과 일치해야 한다. 출력 삭제 기록은 실제로 권한을 분리하므로 이 예외를 유지한다.
- SB: 저장 슬롯 입고는 Resource 예약 수량0이어도 공유 Claim을 소유할 수 있다. 음식/집기 단계의 예약과 입고 단계의 슬롯 소유를 구분한다.

검토 합의는 통과 증거가 아니다. 실행별 실패와 보완 결과는 [검증 기록](../Verification/2026-11-16-save-load.md)에 기록한다. 실제 디스크를 가득 채우거나 사용자 저장 파일을 시험에 사용하지 않는다.


최종 Edit165/Play60·Windows 실행을 통과했다. S0가 추가한 I/O 직후 첫 자동 프레임 생략은 SB가 양수 unscaledDeltaTime으로 첫 Update 불변/두 번째 정상 진행을 검사했다. 실제 마우스·키보드 확인은 이 검토의 증거가 아니다.


마지막 UI 교차 보완: 저장 안내의 수명과 일반 게임 명령 오류를 분리했다. Runner의 일반 명령과 Reset은 이전 SaveMessage를 지우며, 불러오기 후 미소집 이동 안내가 다시 표시되는 PlayMode 검사를 통과했다.
