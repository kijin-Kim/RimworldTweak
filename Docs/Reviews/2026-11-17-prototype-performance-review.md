# 프로토타입 우선 성능 지침 토론과 반영 기록

일자: 2026-11-17. 사용자 요청: 여러 에이전트가 토론한 뒤 프로토타입 구현 우선, 측정 후 상세 최적화 원칙을 최종 문서에 반영한다.

## 운영과 공통 기준

[병렬 배정](../ParallelWork.md)에 따라 세 검토자는 파일 읽기와 의견 전달만 수행했다. 제품 코드와 문서는 root만 수정했으며 Unity 실행과 커밋은 하지 않았다. 검토 합의는 성능 개선이나 구현 검증의 증거가 아니다.

검토자: prototype_scope는 구현 부담, structure_scope는 최소 구조, measurement_scope는 측정 전환과 정확성 검사를 담당했다. 기준 자료는 기존 성능 계획, 저장/UI/아트 계획, Status, Architecture, Testing 및 관련 코드다.

## 독립 의견

| 관점 | 핵심 의견 | 우려 |
|---|---|---|
| 구현 부담 | 저장/UI/아트 사용 흐름을 먼저 연결하고 P0/P1 의무 순서를 제거 | 전용 CLI·전 구간 카운터도 기능보다 먼저 만들면 조기 최적화 인프라가 됨 |
| 최소 구조 | 기존 순수 Simulation과 World의 시작 재검사·예약·취소 경계로 충분 | 탐색 인터페이스·서비스·DI·변경 이벤트를 미리 만들면 미래 설계를 선결정 |
| 측정 | 대표 Player에서 큰 비용 범주를 확인한 뒤 필요한 구간만 상세 측정 | 300회 UI 갱신·30회 복원·30분 실행·5회 A/B 등을 모든 기능의 완료 관문으로 쓰면 과도함 |

## 반론 교환과 결론

1. 구현 부담 검토자는 구조 검토자에게 “확장성을 이유로 인터페이스·이벤트·카운터를 지금 추가하면 미래 최적화를 선결정하지 않는가”를 제기했다. 구조 검토자는 동의하며 기존 ReadPath, PrepareWorkContext, ChooseStorage, 시작/취소 함수 경계 유지로 충분하다고 답했다. 새 추상화를 필수로 두지 않는 안을 채택했다.
2. 구조 검토자는 “프로토타입 중 실제 지연이 기능 검증을 막아도 기다려야 하는가”를 반론으로 제기했다. 구현 부담 검토자는 재현 입력·환경·막힌 행동을 남긴 뒤 해당 구간만 측정·최소 수정하고 기능 작업으로 복귀하는 예외에 동의했다.
3. 측정 검토자는 “성능 후순위가 객체 수명 정리와 중복 호출 오류 방치의 이유가 되지 않아야 한다”고 지적했다. 구현 부담 검토자는 명령 한 번 적용, 예약 해제, 자원 보존, Reset/Load 뒤 표시·구독 중복 방지는 지금 검사하되 결과가 맞는 반복 읽기는 미측정 비용으로 구분하자고 답했다. 정확성과 성능 검사를 분리했다.
4. root가 프로토타입 전환·예외 초안을 전달하자 측정 검토자는 목표 사양 미정이 현재 환경 측정을 막지 않아야 하며, 사람 확인 대기는 별도 기록하고, 메모리 상승만으로 누수를 확정하지 말 것을 보완했다. 반복 지연·배속 미달·참조 누적 등 관측과 소유 증거를 요구하도록 반영했다.

## 채택과 제외

| 항목 | 최종 처리와 이유 |
|---|---|
| 프로토타입 → 측정 → 최소 개선 | 채택. 현재 저장/UI/아트 흐름을 우선하며 자급·전투를 새 선행 조건으로 만들지 않음 |
| 기존 책임·함수 경계 유지 | 채택. 현재 기능 정확성과 나중 변경 가능성을 함께 확보 |
| 전용 계측·캐시부터 구현 | 제외. 실측 전에 해법과 인프라를 고정함 |
| 캐시·공유 검색·버퍼·재시도 분산 | 조건부 후보로 보존. 병목이 확인된 경우만 비교·선택 |
| 모든 지연 수정을 프로토타입 후로 연기 | 제외. 현재 기능 확인을 막는 문제는 재현 후 최소 수정 필요 |
| 고정 대규모·반복 횟수의 일괄 검사 | 필수 기준에서 제외. 실제 문제와 관측 변동에 맞춰 나중 결정 |
| 멀티스레딩·ECS·엔진 교체 | 현 범위에서 제외. 외부 게임 사례만으로 도입할 근거 부족 |

## 반영 결과와 확인 범위

[최종 지침](../Plans/RimWorld-Performance-Application.md)을 다시 작성하고 README, Status, Decisions, Architecture, 저장/UI/아트 계획의 연결 문구를 일치시켰다. 제품 변경과 성능 실측은 없으며 다음 단계는 기존 기능 프로토타입 구현이다. 문서 검사는 로컬 링크와 변경 형식·상호 참조로 제한하고, 기능·성능 통과로 표현하지 않는다.

최종 초안 재검토: measurement_scope가 두 최종 문서를 다시 읽고 토론 왜곡, 선행 최적화 의무, 측정 시점 모순이 없음을 확인했다. root의 변경 대상 8개 문서 로컬 링크 148개 검사에서 누락 0건, `git diff --check` 통과, 이전 P0/P1 우선 실행 문구 검색에서 유효 지시 잔류 없음. 신규 문서 내용은 별도 읽기와 링크 검사로 확인했다. Unity 검사와 성능 측정은 실행하지 않았다.
