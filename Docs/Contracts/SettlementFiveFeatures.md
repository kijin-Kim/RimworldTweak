# 건설·재배·조리·작업계획·저장 공통 계약

2026-11-15 G0-D 확정 v2 (`settlement-five-v2`), 제품 기준 `d0069af`. 현재 범위의 동작/책임 계약이다. G0-C에서 기존 채집/운반 공통 접점을 구현했으며 실제 제공 범위는 [검증·인계](../Verification/2026-11-15-g0-c.md)를 따른다. [3세션 계획](../Plans/SettlementFiveFeatures.md)과 함께 사용한다. 기존 [즉시 명령](ImmediatePlayerCommands.md), [단일 점유](InteractionOccupancy.md), [물류 계약](GatherHaulStorage.md)을 유지한다. 전체 로드맵용 C7 전투/정보전 계약은 적용하지 않는다. 실제 서명·수치·조작/공간·저장 정책의 최종 기준은 [G0 준비 확정서](../Plans/G0-Preparation.md)이며 이 문서의 초기 계획 표현보다 우선한다. G0-D 완료는 G0-C 연결 구현/검증 완료를 뜻하지 않는다.

## 책임과 데이터 경계

S0만 계약·World 상태 변경·공통 루프·Runtime/화면 연결을 관리한다. SA는 건설/조리/저장, SB는 재배/작업계획의 전용 규칙·패널·검사를 맡는다. 정책과 후보 조회는 상태를 바꾸지 않으며 실제 점유/소비/산출은 World의 명시된 적용 경로를 거친다. Simulation은 Unity·파일시스템을 참조하지 않는다.

| 접점 | 제공 내용 | 만드는 담당 → 연결하는 담당 |
|---|---|---|
| 작업 후보 | 작업 종류, 대상ID/좌표, 요청순, 가능 여부/불가 이유, 접근거리 | SA/SB → S0 |
| 작업 시작 | PawnID/ActionId, 대상·수량·통행 재검사, 성공/실패와 점유 결과 | 기능 규칙 SA/SB → 실제 적용 S0 |
| 진행/완료/취소 | 현장 진행, 한 번 소비/산출, 반환/낙하, 무효화 이유 | 기능 규칙 SA/SB → 공통 실행/정리 S0 |
| 시설/작물 조회 | ID, 논리 위치/면적, 완공/성장 단계, 사용/통행 가능 여부 | SA/SB → 읽기 조회 S0 |
| 정책 | Pawn별 작업종류의 끄기/우선순위, 후보 정렬·보류 이유 | SB → 실제 자동 선택 S0 |
| 저장 데이터 | 상태값·ID 참조·진행·내부 자재·설정과 버전, 복원 검증 결과 | 기능별 항목 SA/SB → 직렬화 SA, 월드 교체 S0 |

표는 데이터의 의미를 고정한다. 실제 타입/메서드 서명과 오류 코드는 G0 준비 확정서에 고정했다. 구현 시 두 기능 세션은 v2를 확인한다. 서로 다른 스텁/API를 각자 확정하지 않는다. 공통 파일 변경이 필요하면 수정안·이유·영향 검사로 요청한다. 전용 신규 파일도 공유 내부 필드를 직접 수정하면 독립 모듈로 간주하지 않는다.

## 시간·조작·취소

- 일시정지는 이동·성장·시공·조리·욕구 변화와 자동 선택을 멈춘다. 지정/취소/파종 허용/생산 목표/작업 설정은 같은 명령 처리에서 실제 상태와 UI에 반영한다. 명령 반영을 위해 Step을 호출하지 않는다.
- 소집 R은 모든 자동 생활/작업보다 우선한다. 해당 행동·이동 예약·점유를 즉시 정리하고, 소집 해제 후 새 자동 선택은 다음 Tick에 한다. 오래된 ActionId 취소가 새 행동을 건드리면 실패다.
- Pawn 중단과 작업 자체 삭제를 구분한다. 소집/생활 전환은 건설 현장과 조리대의 진행·투입 자재를 유지한다. Pawn의 운반물만 기존 규칙대로 한 번 낙하하고 점유를 해제한다. 설계도/조리 작업 자체 삭제는 별도 반환 규칙을 적용한다.
- 현장의 유효한 진행은 담당 교체로 사라지지 않는다. 시작/도착한 Tick에 진행을 중복 적용하지 않는다. 완료는 유효성 확인 후 소비·산출·상태 전환을 한 번 처리한다.
- 기존 저장 구역 도구의 한 번 생성 후 해제는 유지한다. 새 건설/재배 도구는 G0 조작표에 반복 배치 여부를 정하며 기능 세션이 임의 확장하지 않는다.

## 자재·공정·점유

스택은 한 번에 한 Pawn/ActionId만 점유한다. 반입 예정량은 기존 물자와 별도의 새 수량이 아니다. 출발 스택→운반→현장/작업대→출력의 각 이전은 출발 차감과 도착 증가를 함께 적용한다. 서로 다른 기능이 같은 스택을 이중 차감하면 안 된다.

| 상황 | 보존/소비 규칙 |
|---|---|
| 건설 반입 | 필요한 비용까지만 현장 자재로 이전. 아직 건설 소비로 세지 않음 |
| 건설 완공 | 반입량/진행/위치를 재검사하고 비용 한 번 소비, 시설 한 개 생성 |
| 설계도 취소 | 실제 반입분만 현장에 반환. 운반 중인 담당은 취소 경로로 낙하, 두 번 반환 금지 |
| 시설 철거 | 초기 기획대로 원래 건설 비용 전량 반환. 철거 완료 기록으로 반복 반환 방지 |
| 조리 반입/중단 | 작업대 내부 자재/진행 유지. 담당 소집/생활 전환은 재료 소비·산출을 일으키지 않음 |
| 조리 완료 | 식재료2를 한 번 소비해 식사1을 한 번 산출. 출력 공간 없으면 완료 소비를 보류 |
| 조리 작업 삭제/조리대 철거 | 미완료 투입 자재는 반환하고 진행 폐기. 이미 완료한 생산/소비는 되돌리지 않음. 사용 권한부터 정리하고 한 번만 반환 |
| 수확 | 성숙한 작물 한 번만 수확해 식재료6 산출. 수확 완료 단계 변경과 산출을 함께 적용 |

자원 종류별로 초기+생성/외부추가/변환산출/철거반환−생활소비/변환투입/건설소비/외부제거 = 바닥+보관+운반+현장투입+작업대투입+별도출력이다. 스택으로 생성된 출력은 바닥/보관에 포함하고 다시 더하지 않는다. 시설 비용 장부와 철거 반환을 연결한다. SA/SB가 제공한 내부 물자 항목은 공통 집계와 저장 목록 양쪽에 등록한다.

## 건설·재배·조리의 연결

건설은 벽/문/침대/조리대로 한정한다. 기존 시험 비용은 목재2/4/10/15다. 면적·사용 위치·출력 위치를 같은 정의에서 읽고, 겹침/맵 밖/통행 불가 배치와 Pawn 위 벽 완공을 거부 또는 보류한다. 점유 중 철거는 우선 관련 행동/점유를 안전 정리하고 반환/통행 갱신한다. 철거 지정·실제 철거·취소의 시점과 예외는 G0 준비 확정서에 고정했다.

재배는 한 칸 한 작물, 파종→성장→수확→재파종이다. 파종 중지는 새 파종을 막고 기존 작물의 성장·수확은 유지한다. 기존 생활 시험 하루1200Tick을 기준으로 성장2일=2400Tick을 초기 연결 시험안으로 사용한다. 최종 밸런스가 아니며 생활 수치를 바꾸는 승인이 아니다. 검증을 위해 짧은 성장시간을 쓰면 별도 시험 설정임을 기록한다.

조리는 건설된 조리대 ID와 실제 접근/출력 위치를 사용한다. 생산 목표 초기값12, 사용 가능한 식사와 진행 중 확정 생산량을 함께 세어 새 생산을 시작한다. 이미 운반 중인 식사는 기존 물자 집계에서 한 번만 포함한다. 두 작업대의 동시 시작도 목표량을 이중 확보하지 않도록 시작 시 재검사한다. 목표 하향/생산 끄기는 새 회차 시작을 즉시 막으며 진행 중 회차를 보존/보류한다. UI에 보류 이유와 남은 투입을 표시한다. 회차 유지/보류와 동시 목표 판정은 G0 조작표에 고정했다.

## 작업계획

작업별 끄기 또는1~3, 1이 높다. 종류는 기존 채집·운반과 신규 건설·농사·조리다. 생활/소집 설정까지 끄는 기능은 아니다. 후보는 수행 가능 여부를 먼저 확인하고 개인 우선순위→접근 경로 길이→요청순→대상ID 순으로 결정하는 계획이다. Pawn 처리 순서는 기존 ID순을 유지한다.

끄기로 바뀐 종류의 현재 행동은 안전 취소하고 점유/운반을 정리하며, 현장/작업대의 진행은 유지한다. 수치만 바뀐 경우 현재 유효 행동은 유지하고 다음 선택부터 새 우선순위를 적용한다. 불가 후보는 원인별로 보류하며 관련 가용성 변화 또는 기존 제한된 재시도로 다시 판단한다. 재료 부족/담당자 없음/접근 불가/출력 포화/목표 도달/설정 중지를 구분한다. 기존 특정 작업 간 우선순위가 개인 설정으로 대체되는 범위와 기본 설정은 G0 준비 확정서의 검사표를 따른다.

## 저장/불러오기

최소 수동 저장/불러오기만 포함한다. 고정된 사용자 데이터 경로의 한 슬롯을 사용하며 실제 경로/파일명/오류 UI는 G0 준비 확정서에 기록했다. 자동저장·여러 슬롯·과거 모든 버전 마이그레이션은 제외한다.

저장 목록: 스키마/시나리오 버전, Tick/시간 잔여·배속/일시정지, 다음ID, Pawn 위치·욕구·소집·행동/운반, 자원·소비/생성 집계, 저장 구역/필터, 설계도/현장자재/시설/통행, 작물/구역설정/성장, 조리 목표/회차/재료/진행/출력, 개인 작업 설정. 새 기능 데이터가 목록에서 빠지면 완료가 아니다. UI 선택/미리보기는 복원 후 초기화하며 실제 게임 상태와 구분한다.

명령이 끝난 안정 상태에서 데이터 복사 → 임시 파일 쓰기/검증 → 교체한다. 읽기는 별도 후보 월드 구성·검증 후 교체하고 오류 시 기존 월드를 유지한다. 파일 I/O는 Runtime, 데이터/검증은 Simulation에 둔다. Unity 참조/Transform은 저장하지 않는다.

경로/점유는 게임 ID/행동 ID로 유효성을 검증하고 결정적인 순서로 복구한다. 유효한 진행과 내부 자재는 유지하고, 무효 대상은 공통 취소로 한 번 정리한다. 점유 고착을 피하려고 모든 작업/자재를 무조건 버리는 복원은 허용하지 않는다. 입력 전·후 Tick 진행 없이 UI를 새 월드에 연결하고, 이후 같은 명령/시간에서 생산·소비 결과가 일치하는지 확인한다.

## G0-D 확정 결과와 남은 구현

[G0 준비 확정서](../Plans/G0-Preparation.md)에 작업 공간 구성, 현재 코드 접점, 신규 API 서명/소유권, 시험값, 시설/출력 위치, 모든 조작, 저장 필드/경로/교체·복원 순서를 확정했다. 성장2400Tick, 파종20/수확30, 조리40, 시설별 시공40/60/100/120, 철거30을 첫 시험값으로 사용한다. 기존 이동/생활/운반 시간은 유지한다.

G0-D 당시에는 문서만 작성했다. 후속 G0-C 구현/검사 및 인계 기준은 검증·인계 문서에 기록한다. 건설/재배/조리/작업계획/파일 저장의 제품 구현은 별도 착수 지시 전 시작하지 않는다.

## 건설·재배 연결 구현 범위

[병렬 실행 카드](../Plans/Sessions/ConstructionFarming-Handoff.md)의 Options/ActiveWork/FeatureWorkResult로 읽기 규칙과 실행 변경을 분리한다. 건설/재배의 새 명령은 World와 Runner에 동일 이름으로 연결하며 정지 중 즉시 적용한다. 건설·재배 단계에서는 시설과 남쪽 서비스칸까지만 등록했으며, 후속 조리 연결은 아래 기록을 따른다. 실제 반입/시공/성장/수확/철거 결과는 별도 검증 기록으로 판정한다.

## 조리·작업계획 연결

[실행 카드](../Plans/Sessions/CookingWorkPolicy-Handoff.md)의 API/소유권으로 조리 주문·출력 및 개인 설정을 연결했다. WorkReadContext에는 불변 정책 복사본이 포함되고 S0는 현재 권한/진행을 재검사한 뒤 결과를 적용한다. 실제 검사 증거는 [통합 검증](../Verification/2026-11-15-cooking-work-policy.md)을 따른다. 저장/불러오기 규칙은 여전히 명세이며 이번 구현 범위에 포함하지 않는다.

## 저장·복원 연결 (2026-11-16)

사용자가 조리·작업계획 정상 확인 후 저장 S1/S2를 승인했다. [저장 실행 카드](../Plans/Sessions/SaveLoad-Handoff.md)의 DTO/API·파일 소유권에 따라 실제 JSON 저장/후보 복원/한 번 교체를 연결했다. 필수 필드는 G0 준비 확정서와 SaveData.cs의 명시 스키마를 기준으로 한다. 파일 크기·버전·enum·참조·공유 점유·행동 단계·시설·물자 장부 검증을 통과한 후보만 적용한다. 이전 절의 저장 미구현은 당시 단계의 기록이며 현재 증거는 [저장 검증](../Verification/2026-11-16-save-load.md)을 따른다.
