# 일시정지 중 플레이어 명령과 UI 계약

2026-11-15 사용자 승인. 이전 문서의 '채집 지정·구역 편집은 다음 Tick 적용'보다 이 계약이 우선한다. 커밋·Computer Use·원격 작업은 하지 않는다.

## 명령과 시간의 분리

- 일시정지는 이동·욕구 감소/회복·채집/운반/식사/수면의 진행과 자동 선택을 멈춘다. 선택·소집/해제·행동 취소·지정·필터·구역 생성/삭제는 멈추지 않는다.
- 플레이어 명령은 유효성 검사 → 실제 상태 변경 → 무효 행동/점유 정리 → UI 갱신을 같은 호출에서 완료한다. 명령 적용을 위해 Step(0/1), 시간 누적, 자동 작업 선택을 실행하지 않는다.
- UI는 버튼 처리 직후 또는 다음 화면 갱신까지 최종 실제 상태를 표시한다. 소집됨과 수면 중 표시가 동시에 남거나, 화면만 필터가 바뀌는 중간 상태를 만들지 않는다.
- 수면 중 소집은 수면·침대 점유·수면 목적·이동 예약을 즉시 제거한다. UI의 행동/점유/배지도 함께 바뀐다. 다른 Pawn의 빈 침대 선택은 다음 Tick이다.
- 운반 취소는 기존 규칙대로 한 번만 바닥 낙하하고, 운반량0·점유 해제를 즉시 반영한다. 필터/구역 변경으로 집기 전 행동도 더 이상 수행할 수 없으면 출발 점유를 해제한다. 유효한 대체 저장 공간이 있으면 출발 접근을 유지할 수 있다.
- 소집 해제는 기존 수동 이동을 즉시 취소하지만 자동 행동은 다음 Tick에 선택한다. 명시적 행동 취소도 현재 상태를 즉시 비우고 다음 Tick부터 새 선택을 허용한다. 이전 행동 ID의 명령은 새 행동을 취소하지 않는다.
- 이동 명령은 접수/예정 목적지를 즉시 표시하고 위치 변화는 Tick에 진행한다. 기존 이동 큐 의미는 유지한다. 외부 테스트 전용 자원/침대/통행 변경 API는 이번 플레이어 설정 UI 범위가 아니며 기존 Tick 적용을 유지한다.
- 저장 구역 생성은 유효한 두 번째 클릭에서 즉시 완료하고 도구를 None으로 되돌린다. 추가 구역은 버튼을 다시 눌러야 한다. 잘못된 영역은 생성하지 않고 오류를 표시하며 첫 모서리를 초기화해 다시 시도할 수 있게 도구를 유지한다.
- API 이름 `QueueDesignateGather/QueueCreateStorage/QueueStorageFilter/QueueDeleteStorage/QueueCancelLife`는 호출자 호환을 위해 유지하되 적용 시점은 즉시다. 이 명령들은 PendingCommandCount에 포함하지 않는다.

## 파일 소유권

root가 `WorldState.Work.cs`, `WorldState.Living.cs`, `WorldState.cs`의 명령/취소 경로, `SettlementView.Work.cs`의 도구 종료/표시, 필요한 Inspection 표시, 관련 EditMode/PlayMode 검사와 manifest, Player smoke, Docs를 단독 수정한다. 다른 에이전트에 배정하지 않는다. 검사 실행 중 입력 동결, Unity 실행은 root가 직렬 수행한다.

## 완료 기준

1. 정지 중 수면 소집, 운반 소집/취소, 채집 취소가 Tick 진행 없이 실제 상태와 UI에 반영된다.
2. 필터 변경·구역 생성/삭제·지정 변경은 즉시 반영되고 반복 입력/오래된 취소로 물자가 복제·유실되지 않는다.
3. 입력 전후 Tick·욕구·현장 채집 진행도가 변하지 않는다. 취소된 행동의 로컬 진행도 초기화는 의도된 정리다. 자동 작업·빈 침대 재선택은 다음 Tick이다.
4. 저장 구역 한 번 생성 후 일반 클릭은 추가 구역을 만들지 않으며 버튼 재선택 시에만 두 번째 구역을 만들 수 있다.
5. 기존 이동·생활·점유·물류·UI 회귀, 신규 무시간 상태/표시 검사, Windows 빌드·Player·렌더를 실행한다. 사람의 실제 조작 확인은 별도 기록한다.
