# 다중 세션 기능 통합 공통 계약

> 현재 범위의 우선 계약은 [다섯 기능 공통 계약](SettlementFiveFeatures.md)이다. 아래 C0~C7은 전체 로드맵 참고이며 전투/정보전과 추가 담당 세션은 이번 적용 대상이 아니다.

2026-11-15 계획 버전 v1. 기준 `d0069af`. 기존 확정 규칙을 유지하면서 후속 기능의 접점을 정하는 문서다. 신규 API·상태 구조는 설계 제안이며 구현된 API가 아니다. 담당·파일 소유권·순서는 [전체 세션 계획](../Plans/MultiSessionRoadmap.md)을 따른다. 이 문서의 작성은 구현/작업 폴더 분리/커밋 승인이 아니다.

## 계약 관리와 착수 판정

S0이 이 문서를 단독 관리한다. 기능 담당은 변경 요청만 제출하고 전체 세션이 공유 파일을 직접 고치지 않는다. 변경 요청에는 기존 규칙, 바꿀 이유, 영향 단위, 필요한 회귀 검사를 적는다. S0이 영향 기능 소유자와 접점을 맞추고 버전/기준을 갱신한다. 계약 내용 변경 후 이전 버전을 전제로 한 시험 결과를 새 버전의 통과로 간주하지 않는다.

| 계약 | 유지할 기존 규칙과 제안 접점 | 구현 전 고정할 항목 | 소유자/사용자 |
|---|---|---|---|
| C0 상태·시간·식별 | 월드별 상태 격리, 안정 ID/단조 증가, 동일 Tick의 결정 순서, Simulation→Runtime→Presentation 경계 | 새 개체 종류 등록·시설 조회·작물 성장 Tick 위치, 기능별 설정 데이터 | S0 / 전체 |
| C1 작업·취소 | R 소집/해제와 명령 취소, ActionId 일치 점유만 해제, 자동 행동은 Tick에서만 선택 | 작업 후보 읽기 결과·시작 성공/실패·중단 이유·정리 결과 형식 | S0 / BUILD,FARM,COOK,JOBS,RECOVERY |
| C2 물자·생산 | 스택 단위 독점, 출발/도착 점유 전환, 운반 중 취소 한 번 낙하, 보존량 조회 | 현장/작업대 투입량·완성품·목표량 예약을 표현하는 데이터와 반환/소비 시점 | S0 / BUILD,COOK,SAVE,QA |
| C3 시설·통행 | 맵 밖/막힌 위치 거부, 지형 변경 후 경로 재검증, 논리 상태가 화면보다 우선 | 설계도/완공물 footprint, 문 통과, 점유 중 철거, 조리대 출력 위치·용량 | S0 / BUILD,COOK,이후 VISION |
| C4 재생산 | 기존 Settlement 시험값, 정지 중 진행 없음, 배속별 같은 게임 시간 결과 일치 | 게임 하루 Tick 수와 성장2일 환산, 파종/수확/조리 소요, 출력 포화 판정 | S0 / FARM,COOK,QA |
| C5 작업 정책·진단 | 소집과 긴급 생활 우선, 작업 실행과 정책 분리, 중단 이유 실제 상태 조회 | 끄기/우선순위 변경 시 진행 작업 처리, 거리 측정·요청순/ID 동률, 재시도 조건 | S0 / JOBS 및 작업 제공 세션 |
| C6 저장·복원 | 상태/ID/수량 보존, 경로·점유 재검증, 실패 시 현재 월드 보존 | 포맷 버전·필수 필드·원자 저장/교체, 도중 행동/점유 복원 정책, UI/시간 설정 보존 범위 | S0 / SAVE 및 상태 소유 세션 |
| C7 전투·정보·평가 | GameDesign의 완전작전 정의, 고정 습격 구성, 현재/기억 정보 구분 | 팀·피해/부상/치료 이벤트, 관측 소비 접점, 사선/시야 차단 차이, 습격 보호 목표/종료 | S0 / COMBAT,RECOVERY,VISION,TACTICS,RAIDS |

P0은 C0~C6의 연결 형식과 공통 불변 조건를 정하는 단계다. 기능별 세부 수치는 해당 기능 작성 전에 확정하며, 예를 들어 성장 Tick 환산이 미정이면 F2를 시작하지 않는다. C6의 전체 미래 저장 필드를 P0에서 고정하지 않고 기능이 추가될 때 상태 소유자와 함께 목록을 확장한다. C7은 후반부 준비용이며 G8 이후 실제 전투 구현 전에 별도 상세 계약으로 확정한다. 미정 접점이 남은 기능은 문서/시험 사례 준비만 할 수 있다.

## 작업 연결의 최소 구조

현재 `WorldState.Work.cs`가 작업 선택·진행·취소와 물자 처리를 맡고 `WorldState.cs`가 Tick 순서를 연결한다. `SimulationRunner.cs`는 명령 전달, `SettlementView`의 partial 파일들은 표시와 입력을 공유한다. 이 파일들은 S0 소유다. 새 partial 파일을 각자 만들고 같은 내부 상태를 수정하는 방식은 독립 작업으로 간주하지 않는다.

예정 연결 흐름: 기능 모듈이 수행 가능한 후보와 실패 이유를 읽기 데이터로 제공 → S0의 기존 작업 선택 경로가 후보를 결정 → 시작 시 유효성/점유를 다시 검사 → World의 정해진 시점에서 진행/완료 → 공통 취소 경로가 소유권을 정리 → 화면은 확정 상태를 조회한다. 작업 정책은 후보를 정렬할 뿐 자원을 소비하거나 점유하지 않는다. 후보 조회 자체는 상태 변경이나 점유를 만들지 않는다.

후보에 필요한 의미는 작업 종류·대상 ID/좌표·요청 순서·수행 가능 여부/이유다. 실제 타입/메서드 이름은 P0에서 현 코드에 맞춰 정한다. 필요 이상의 범용 플러그인·이벤트 버스·추상 계층을 미리 만들지 않는다. 계약은 문서뿐 아니라 작은 연결 검사로도 확인한 뒤 기능 작성을 시작한다.

## 소집·취소·정지 중 명령

[즉시 명령 계약](ImmediatePlayerCommands.md)과 [단일 점유 계약](InteractionOccupancy.md)을 유지한다.

- 유효성 검사 → 상태 변경 → 무효 행동/점유 정리 → UI 반영. 정지 중 명령을 적용하려고 Step을 호출하지 않는다.
- R은 모든 자동 생활/노동보다 우선하며 진행 행동·이동 예약·해당 ActionId의 점유를 즉시 정리한다. 소집 해제 후 자동 선택은 다음 Tick이다.
- 명시적 취소와 대상 무효화가 진행/완료와 경합할 때 중복 소비·산출을 막는다. 오래된 ActionId는 새 행동을 취소하지 않는다.
- 자동 행동이 다른 빈 대상이나 새 작업을 선택하는 것은 다음 Tick이다. 정지 중 UI 갱신과 자동 작업 진행을 혼동하지 않는다.
- 개인 작업 끄기 변경은 계획상 해당 진행 작업을 안전 정리하고 다음 Tick부터 제외한다. 우선순위 수치 변경만으로 유효한 진행 작업을 강제 중단하지 않는 안을 권장하며 C5 확정 시 명시한다.
- 기존 저장 구역 생성 성공 후 도구 해제는 유지한다. 다른 새 도구의 반복 배치 여부는 각 기능 조작 계약에 명시하며 임의로 같은 정책을 확장하지 않는다.

## 물자의 위치와 소비 책임

같은 물자는 바닥/보관 스택, Pawn 운반물, 건설 현장 투입물, 조리대 투입물, 완성품 중 정확히 한 위치에서만 센다. 점유는 수량 이전이나 소비가 아니다. 기능 모듈이 독자적으로 기존 스택을 차감하고 공통 운반도 다시 차감하는 경로를 만들지 않는다.

자원 종류별 보존식: 초기량 + 생성/외부추가/변환산출/철거반환 − 생활소비/변환투입/건설소비/외부제거 = 미보관 + 보관 + 운반 + 현장투입 + 작업대투입 + 아직 다른 항목에 포함되지 않은 출력. 이미 스택으로 생성된 출력은 미보관/보관에 포함하고 별도로 더하지 않는다. 건설 소비와 철거 반환은 시설 비용 장부로 연결해 반복 철거·취소가 물자를 생성하지 않게 한다.

건설은 반입 시 현장으로 이전하고 완공 시 비용을 한 번 소비한다. 설계도 취소는 반입분을 반환하며 미반입 비용을 생성하지 않는다. 완공된 시설의 철거 반환은 현장 취소와 별개다. 조리는 반입 시 작업대 내부로 이전하며 담당 Pawn 중단만으로 재료·진행을 삭제하지 않는다. 한 회 완료 시 투입 소비와 산출을 한 번 확정한다. 작업대 철거/작업 자체 삭제 시 투입 반환 정책을 C2/C3에서 고정한다.

원본 스택은 기존처럼 하나의 Pawn/ActionId만 점유한다. 건설·조리의 여러 작업자가 필요하더라도 같은 스택을 동시에 부분 점유하는 새 규칙을 몰래 도입하지 않는다. 두 Pawn이 같은 출력 공간/생산 목표를 확보할 때 초과 생산이 생기지 않도록 시작 시 다시 확인한다.

## 시설·시간·정보 조회

완공/철거는 점유와 기존 개체 ID의 수명을 함께 갱신한다. 벽 완공으로 Pawn을 타일 안에 가두거나 이미 점유한 상호작용 대상을 무효 상태로 남기지 않는다. 사용 중 철거의 거부/취소 후 철거 중 한 정책을 정해 검사한다. 통행 가능과 사선/시야 차단은 다른 속성이며 미래 정보전을 위해 지금 모든 문·벽이 동일하게 차단한다고 가정하지 않는다.

성장/회복/공정 시간은 논리 Tick으로 계산한다. Settlement의 '2일'을 임의 현실 시간으로 해석하지 않는다. 시험 맵8×8에서 기능을 확인하고 통합 목표 약64×64는 이후 실제 경로/갱신 비용과 함께 검증한다. 현재 작은 맵 통과를 큰 맵 성능 보장으로 보고하지 않는다.

모든 UI는 읽기 조회를 사용한다. 나중에 Fog of War가 연결되면 현재 관측·마지막 관측·미탐색을 구분한 조회를 제공해야 한다. 숨은 적의 현재 위치를 화면에서만 가리고 선택·목록·명령에는 그대로 제공하는 구현은 허용하지 않는다. 적 AI도 관측 결과를 소비하도록 C7에서 연결한다.

## 저장과 시험 경계

저장은 명령 처리가 끝난 안정 상태에서 스냅샷을 얻는 안을 기준으로 한다. 실패한 읽기/검증이 현재 월드를 부분 변경해서는 안 된다. 복원 후보 월드를 검증한 뒤 교체한다. Unity 참조/Transform 대신 게임 ID와 순수 데이터를 저장한다. 파일 쓰기는 임시 파일 검증 후 교체하는 방향으로 설계하고 실패 복구를 시험한다.

진행 작업의 재료·진행·운반은 보존하며 경로/점유는 복원 후 권한과 대상 유효성을 검사한다. 점유 재구축 순서와 유효한 작업 재개/무효한 작업 정리 정책은 C6 상세 계약에 명시한다. 경로와 점유를 무조건 삭제하는 것만으로 '정상 복원'으로 판정하지 않는다. 새 기능 상태를 저장 목록에서 빠뜨리면 G7을 통과할 수 없다.

시험용 자재·조리대·피해 입력은 Test Scenario에서만 사용한다. 기능 규칙 검사 통과와 실제 건설/재배/전투 연결 통과를 별도 기록한다. 기능별 인계 문서에 실제/시험용 연결 여부, 입력 해시, 검사 실행 여부, 미검증 경로를 적는다. Unity 실행은 S0 단일 큐이며 사용자 화면 조작과 CLI/버튼 이벤트 검사를 구분한다.
