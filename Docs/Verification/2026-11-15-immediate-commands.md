# 일시정지 명령과 저장 도구 검증

2026-11-15. [공통 계약과 파일 소유권](../Contracts/ImmediatePlayerCommands.md)을 먼저 확정하고 root가 직렬 구현·검증했다. 커밋·원격 연결·push·Computer Use 없음.

## 변경 결과

- 기존 채집 지정·구역 생성/필터/삭제·행동 취소의 Tick 대기를 제거했다. 호출 즉시 실제 상태와 무효 행동/점유를 정리하고 UI가 다시 읽는다. 호환을 위해 Queue 접두 API 이름은 유지한다.
- 정지 중 소집으로 수면 행동·침대 점유·수면 목적·이동 예약이 취소되고 하단 행동/점유와 소집 배지가 함께 갱신된다. 다른 바닥 수면자의 빈 침대 선택은 다음 Tick이다.
- 필터/구역 변경은 입고 중 행동뿐 아니라 유효한 도착 공간이 없는 집기 전 행동도 즉시 취소한다. 운반물은 현재 위치에 한 번만 놓는다. Tick 외 취소로 놓인 물자는 다음 Tick부터 다시 선택 가능하다.
- 저장 구역은 유효한 두 번째 클릭에서 생성하고 도구를 해제한다. 일반 클릭은 추가 구역을 만들지 않으며 버튼을 다시 눌러야 한다. 잘못된 영역은 부분 생성하지 않고 재시도 가능하게 도구를 유지한다.
- UI는 설정 즉시 적용과 이동 대기 수를 구분한다. 자동 행동·이동·욕구/작업 진행은 계속 Tick에만 의존한다. 외부 테스트용 자원·침대 변경 큐는 기존 의미를 유지한다.

## 기능별 자동 검사

| 기능 | 관측 결과 |
|---|---|
| 수면 중 정지 소집/해제 | Tick·욕구·채집 진행 불변, Idle/소집 표시, 침대 비어 있음, 점유 없음, 다음 Tick에만 다른 Pawn이 침대 획득 |
| 구역 생성과 필터/삭제 | 정지 상태에서 실제 구역/필터와 체크 표시 변경, 자동 작업 시작 없음 |
| 저장 도구 한 번 사용 | 생성 후 None/첫 모서리 없음, 일반 클릭 2회로 추가 생성 없음, 버튼 재선택 후 생성 가능 |
| 운반 중 필터 변경 | 운반0·도착 점유 해제·미보관 목재10, 반복 필터 명령으로 자원 개수 증가 없음 |
| 집기 전 공간 무효화 | 필터 해제 및 마지막 구역 삭제 즉시 출발 스택 점유 해제, 수량10 유지 |
| 명시적 운반 취소 | Tick 변화 없이 낙하와 UI 갱신, 같은 행동 ID 재취소 시 중복 생성 없음 |
| 채집/식사 취소 | 지정/권한 즉시 제거, 현장 진행 보존·음식 소비0, 오래된 취소가 새 행동을 침범하지 않음 |

신규 PlayMode6개는 버튼 이벤트/명령 호출 직후 상태와 표시를 검사한다. 검사 환경을 준비할 때만 Step을 사용하며 정지 중 명령 검증 구간에서는 Step 없이 Tick·모든 Pawn의 욕구·현장 진행도를 비교한다. 자동 동작이 재개되는지 확인하는 별도 구간만 한 Tick 진행한다. 실제 키보드/마우스 입력을 자동화한 검사는 아니다.

## 남은 확인

[실제 조작 안내](../ReadableUiDemo.md)의 일시정지 추가 확인 3가지는 사용자 확인 대기다. 구현과 자동 검증을 사람의 가독성/실제 조작 확인과 구분한다. 기존 Player 종료 시 ComputeBuffer/D3D12 4096B 경고는 남아 있으며 이번 변경의 빌드 오류·경고는 0이다. 장시간 GPU 프로파일링과 다른 OS/해상도 실제 플레이는 검증하지 않았다.

최종 네 실행의 입력150개 SHA-256이 현재 파일과 모두 일치하고 빌드 출력183개도 provenance와 일치한다. 실행 중 입력 변경은 없다. 기존 승인 전 기능과 UI 작업은 보존했으며 HEAD는 `7d20688`이다.

## 후속 사용자 확인 (2026-11-15)

사용자가 “모두 정상으로 확인했어”라고 보고했다. 위의 사용자 확인 대기는 당시 기록이며 현재는 정상 확인 완료다. 별도의 해상도/OS/장시간 GPU 검증을 수행했다는 의미는 아니다. 이번 커밋 제안 검토에서 최종 검사 입력150개와 빌드 출력183개의 현재 해시 일치를 재확인했다. 새 Unity 검사는 실행하지 않았다.
