# 독립 타이틀 화면 검증

일반 실행의 첫 씬은 Title이다. 중앙 메뉴에서 새 게임과 불러오기를 고르고, 화면 설정과 저장 목록도 타이틀 안에서 조작한다. 제목은 기존 임시 명칭 ‘정착지’를 쓴다. [타이틀 렌더](Images/main-title.png) · [저장 목록 렌더](Images/main-load.png)

## 기능별 확인

| 상황 | 확인 방법과 관찰 결과 |
|---|---|
| 일반 시작과 화면 이동 | 실행 파일의 일반 진입 경로에 관찰자를 붙였다. 첫 화면, 빈 목록, 설정, 메인 복귀, 손상 저장 복귀에서 활성·비활성 실행기, 지도, 지도 입력기, 기존 화면과 HUD 모두 0개이고 입력 시스템은 1개였다. |
| 새 게임 | ‘새 게임’에 첫 키보드 포커스가 놓였다. Submit을 연속 두 번 전달한 뒤 나온 정착지는 250×250, 정착민 3명, 실행기·지도·HUD 각각 1개였다. |
| 메뉴에서 저장 열기 | 빈 목록에서는 안내가 보였다. 최근 기록이 없는 후보를 선택하면 확인을 거쳤고, 손상 파일은 비활성으로 표시했다. 파일 구조를 읽는 검증과 선택 후 월드 복원 검증을 분리한 EditMode 사례도 확인했다. |
| 메인 복귀와 취소 | 메인으로 돌아가기 확인을 취소하면 같은 세션이었다. 빈 이름으로 저장에 실패했을 때도 같은 세션과 저장 창을 유지했다. 유효한 이름으로 저장한 뒤에는 타이틀에서 기존 실행기의 해제를 확인했다. |
| 목록이 열린 뒤 파일 손상 | 정상 슬롯을 목록에 표시한 뒤 격리된 검사 파일을 손상시키고 선택했다. 오류를 표시하는 타이틀 목록으로 돌아왔고 해당 슬롯은 비활성이었다. |
| 복원과 재시작 | 정상 슬롯을 복구한 뒤 목록과 이어하기로 각각 열어 저장 당시 7틱과 슬롯 ID를 대조했다. 메인으로 다시 돌아와 새 게임을 시작하면 이전 슬롯 ID와 일시정지 상태가 해제됐다. |
| 화면 크기와 기존 스타일 | 1920×1080 UI 100%와 1280×720 UI 150%에서 타이틀·빈 목록·정상 목록·손상 목록 각각 4장을 렌더했다. 실제 버튼의 화면 좌표·상호 겹침·스크롤 영역·문구 필요 높이를 검사했고 PNG에서 한국어 버튼과 안내를 확인했다. 기존 HUD와 타이틀이 같은 9분할 스프라이트, 글꼴, 버튼 상태색을 사용한다. |

초기 Player 검사에서 하단 버튼 행이 목록 공간을 차지하는 현상과 손상 슬롯 안내의 마지막 줄 잘림을 발견했다. 하단 행을 고정 높이로 두고 슬롯 행은 줄바꿈에 맞게 높이를 정하도록 고쳤다. 기존 재실행 검사에서는 숨겨진 Windows 창의 캡처가 단색이었다. 창의 실제 버퍼를 검사하는 모드에 일반 창 표시 방식을 적용했다. 타이틀 PNG는 Player 카메라로 실제 메뉴 Canvas를 렌더한 자료다. 입력 검사는 Unity 버튼 이벤트를 사용했다.

## 직접 확인

1. `E:\Dev\RimworldTweak\Builds\Windows\RimworldTweak.exe`를 실행하면 지도 없이 타이틀이 뜨고 새 게임에 포커스가 놓인다.
2. **불러오기 → 돌아가기**를 누르면 타이틀로 되돌아온다. 기존 저장이 있으면 목록에 이름과 진행 시점이 보인다.
3. **새 게임**을 누르면 세 정착민이 있는 지도가 열린다. **Esc → 메인 메뉴 → 취소**를 누르면 일시정지 메뉴에서 현재 게임을 재개할 수 있다.
4. **메인 메뉴 → 저장 후 계속**을 선택하고 새 이름으로 저장하면 타이틀이 열린다. **불러오기**에서 방금 만든 슬롯을 고르면 그 정착지로 돌아간다.

마우스·키보드 조작감과 스타일 선호도는 사람 확인 항목이다. 확인 결과는 ‘모두 정상’ 또는 ‘불러오기에서 돌아가기를 눌러도 목록이 남음’처럼 알려주면 된다.
