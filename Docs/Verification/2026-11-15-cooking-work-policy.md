# 조리·작업계획 통합 검증

2026-11-15. 사용자 승인 범위: 조리 C1/C2와 개인 작업계획 J1/J2. S0 통합(E:/Dev/RimworldTweak), SA 조리(feature-a), SB 작업계획(feature-b). Computer Use·UI 자동화·커밋·원격 연결·push 없음. 파일 저장 구현은 범위 밖이다.

## 실제 변경

- 실제 건설한 조리대에 기본 중지/목표12 주문이 생긴다. 식재료2를 반입하고40Tick 작업해 식사1을 남쪽 출력칸에 만든다. 출력50, 가동/중지, 목표0~99, 삭제/재생성을 지원한다.
- 완성 식사는 기존 음식 점유·섭취·운반과 같은 ResourceState로 한 번만 등록한다. 입력 투입/소비와 생산을 각각 장부에 남긴다. 정지/R/개인 작업 끄기는 작업자 점유를 해제하고 진행·투입분을 보존한다. 운반물은 취소 시 현재 위치에 한 번 떨어진다.
- Pawn별 채집·운반·건설·농사·조리 설정은 끔/1/2/3이다. 1이 우선, 기본 운반1/나머지2. 수행 가능한 후보를 종류 전체에서 비교하고 우선순위→거리→요청순→대상ID→단계 순으로 선택한다. 숫자 변경은 현재 행동 유지, 끔은 해당 행동 즉시 취소다. 생활·소집이 우선한다.
- 건설/계획 화면 아래에 개인 설정을 두고 조리대를 선택하면 가동/목표/입력/진행/출력을 표시한다. 정지 중 명령과 정보가 즉시 바뀌며 다음 자동 작업은 Tick 재개 때 시작한다. 미소집 수동 이동 차단과 건설 작업자 현장 표시는 유지한다.

## 교차 검토와 보완

SA는 재생성 주문의 삽입순 문제, 기존 출력 스택의 CreatedTick, 접근 불가 조리대 회차 선점을 확인했다. stove ID 순 정렬, 산출 Tick 갱신, 구조상 실행 가능한 시설에 한정한 신규 회차 할당을 반영했다. 출력은 스택 단위이므로 새 생산이 추가된 Tick에는 기존 잔량도 일반 운반 후보에서 제외한다.

SB는 실제 화면으로 연결되지 않은 NoWorker 진단, 끔→켬의 오래된 안내, 조리대에서 물류 보기로 전환할 수 없는 문제를 확인했다. S0 읽기 진단 API와 화면 연결, 설정 재활성 시 이전 안내 해제, 선택 변경 때만 자동 열기를 반영했다. 진단 읽기는 Tick·경로 검색 계수·점유를 변경하지 않는다.

확장 첫 EditMode144 중143 통과. 주문 순서 검사가 유일 식재료 스택을 첫 작업자가 점유 중인데 다음 Tick에 두 회차가 즉시 생길 것으로 가정했다. 실제 스택 해제 후 두 회차가 활성화되도록 대기하고, 식사 생산 이전이라는 전제는 유지했다. 제품의 스택 독점 규칙을 완화하지 않았다.

## 직접 확인 순서

실행 파일: `E:/Dev/RimworldTweak/Builds/Windows/RimworldTweak.exe`.

1. 건설/계획에서 조리대를 빈 칸에 지정하고 완공을 기다린다. 조리대 본체와 남쪽 칸은 비어 있어야 한다. 목재15가 필요하며 완공 주문은 중지/목표12다.
2. 조리대를 선택하고 Space로 멈춘 뒤 가동/목표 버튼을 누른다. 시간이 흐르지 않아도 표시가 바뀐다.
3. 식재료를 채집하거나 밭을 수확한 뒤 재개한다. 반입2→조리40→식사1의 흐름을 확인한다. 목표는 바닥·저장·운반·출력의 모든 식사를 센다. 이미 식사가12 이상이면 목표를 늘린다.
4. 조리 작업자를 선택하고 건설/계획 하단의 조리 버튼을 눌러 끔으로 바꾼다. 작업·점유는 즉시 해제되고 입력/진행은 남아야 한다. 다시1로 켜고 재개하면 이어서 작업한다.
5. 조리대를 선택해 물류 보기로 바꾼다. 다음 화면 갱신에도 물류 보기가 유지되어야 한다. R 소집은 작업을 즉시 취소하고 소집된 정착민만 우클릭 이동할 수 있어야 한다.
