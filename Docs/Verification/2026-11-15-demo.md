# Windows 초기 정착지 데모 검증

날짜: 2026-11-15. 작업 0-C, 0-D, 0-E2, 0-F.

## 결론

초기 상태 표시, Tick·Pause·Step·Reset, Windows 빌드와 실제 Player smoke를 완료했다. 이동·생활·생산·전투는 구현하지 않았다. 사람의 화면·마우스 조작은 별도 미검증이며 [체크리스트](../Demo.md)를 제공한다. Computer Use와 입력 주입은 사용하지 않았다.

Unity 6000.3.28f1 (8f082d2fe476), 기존 manifest와 lock 고정. 공유 폴더 E:\Dev\RimworldTweak 유지. 기준 커밋 784f242 이후 변경은 미커밋이며 원격 연결·push 없음.

## 기능별 관측

- 초기 월드: 8×8, (3,3) 장애물. 정착민 3명 (1,1), (2,1), (1,2). 목재 40 at (4,1), 식사 18 at (4,2).
- PlayMode는 metadata뿐 아니라 실제 Image/Text/RectTransform 좌표·수량·타일 색, 활성 상태, 표시 개수와 다른 Runner 재연결을 검사한다.
- EditMode에서 100번 단일 Step, 10.037초 입력과 분할 입력의 100 Tick·0.037초 잔여 일치, 경계 시간 이월, 음수·overflow 거부, 독립 세션과 이전 World 보존을 확인했다.
- 실제 Player 자동 Tick은 검사 시점 30이었다. 이는 시작·프레임 지연을 포함한 관측값이고 현실 0.35초에 정확히 30 Tick이란 뜻이 아니다. 정확도 검사는 별도 명시 시간 10초→100 Tick으로 수행했다.
- smoke 초기 2회 Reset 뒤 반복 Reset 10회로 ResetCount 12. 이전 World는 Tick 1 유지, 새 World는 Tick 0, 잔여 시간 0, pause 유지.
- marker 69개(타일 64 + 정착민 3 + 자원 2), Canvas 하위 Transform 164→164. Bind 반복 후 Step 한 번은 1 Tick, Reset 한 번은 ResetCount +1. 상태 이벤트 구독은 없고 버튼 리스너는 UI 생성 시 한 번 등록한다.
- Pause/Resume 이벤트 직접 호출 정상. 실제 마우스 입력 경로는 미검증이다.

## 실제 렌더 증거

[Windows 데모 PNG](Images/demo-windows.png)는 최종 smoke에서 저장한 원본의 복사본이다. 이미지 검토에서 8×8 맵, 삼각형 3개, 목재 40·식사 18 사각형, 어두운 장애물, Tick 0/PAUSED/RESETS 12와 버튼·범례·합계를 확인했다. 이미지 검토는 사람이 직접 플레이했다는 뜻이 아니다.

## 실패와 수정 기록

실패 실행은 삭제하거나 통과로 변경하지 않았다. 자세한 판단은 [교차 검토 기록](../Reviews/2026-11-15-demo-review.md)을 따른다.

1. 20261115T064716811Z-prepare: BuildReport 카운트 int/uint 컴파일 오류. int로 수정 후 20261115T064812570Z-prepare 성공.
2. 20261115T064843697Z-43f3f7f2: testPlatform 인자 누락. 고유 실행 경로에 해당하는 자체 프로세스만 종료, 종료 -1/결과 없음으로 실패 기록. 인자와 사전 검사 수정 후 실제 검사 통과.
3. 20261115T065812416Z-build: 빌드 자체 성공, URP/Volume/Standalone 설정 재직렬화로 입력 해시 실패. 변경 검토 후 20261115T070040603Z-build부터 입력 안정화 확인.
4. 20261115T070127120Z-smoke: 숨긴 D3D12 창의 PNG 저장 실패. 20261115T070224705Z-capture-diagnostic의 D3D11 PNG도 검은 화면으로 렌더 증거에서 제외. 실제 창 표시로 기본 D3D12 렌더 성공. 그래픽 API는 바꾸지 않았다.
5. 빈 화면 판정 보완: 검은 PNG 1색은 거부, 실제 PNG 70색은 통과. 최종 smoke는 PNG 디코드와 크기·빈 화면 검사까지 포함한다.

종료 후 남은 UnityLockfile은 삭제하지 않았으며 실행 프로세스가 없고 독점 열기가 가능한 경우만 Unity 자체 복구를 허용했다. 사용자 에디터 강제 종료는 없었다.

## 한계와 미검증

- 사람의 실제 마우스·키보드 입력, 창 크기 변경, 일반 실행의 가독성과 수동 종료는 미검증이다. [실행 방법과 체크리스트](../Demo.md) 참조.
- 최종 Player 종료 로그에는 ComputeBuffer 정리 및 D3D12 4096-byte 리소스 해제 경고가 있다. 자체 코드에는 ComputeBuffer 할당이 없으나 엔진 원인으로 확정하지 않았다. 이번 결과는 UI 객체·버튼 동작 중복 검사와 정상 종료를 증명하며 GPU 리소스 누수가 없음을 증명하지 않는다. 장시간 실행·메모리 프로파일링은 미실행이다.
- 빌드 대상은 Windows64 한 환경(RTX 3070 Ti, 기본 D3D12)이다. 다른 GPU·운영체제 호환성은 미검증이다.
- 저장, 이동, 생활, 생산, 전투, Fog of War는 범위 밖이다.

## 후속 사용자 확인 — 2026-11-15

사용자가 기존 Windows 데모에 대해 “모두 정상으로 확인했어”라고 보고했다. 위 미검증 표기는 자동 검증 종료 당시 기록이며, 기존 데모의 화면·조작 체크리스트는 사용자 확인 보고로 갱신했다. 에이전트가 직접 입력을 실행했다는 의미는 아니다. 확인 환경의 상세 수치는 별도로 제공받지 않았다. 그래픽 리소스 경고 원인과 장시간 프로파일링은 이 보고만으로 해결된 것으로 처리하지 않는다.
