동일 상태에 준비한 후보라도 다른 Pawn이 먼저 시작하거나 지정/필터가 바뀌면 보수적으로 폐기하고 다음 재평가에서 다시 만든다. 후보는 점유권이 아니다. 미래 규칙에서 후보 값을 제안하더라도 S0이 문맥에 등록하고 실행 종류를 연결해야 실제 시작된다. 다른 월드/Reset 이전 후보를 재사용하지 않는다.

기존 운반 우선 → 채집 순서를 유지한다. 운반이 가능하면 이 문맥에는 운반 후보만 들어간다. 후보 정렬은 거리→요청순→ID이며 운반 요청순은0이다. 매 프레임 조회나 개인 우선순위 선택은 구현하지 않는다. J2에서 모든 종류를 수집하는 정책으로 명시적으로 확장해야 한다.

기존 HaulToStorage의 TargetId와 SourceId는 모두 출발 스택 ID다. WorkCell은 출발 접근 위치다. 저장 목적지 점유는 집기 순간에만 잡는다. 미래 DeliverBuild/DeliverCook의 TargetId는 최종 현장/시설, SourceId는 출발 스택이라는 G0-D 규칙을 그대로 따른다. 기존 오류 표시를 유지하기 위해 WorkReasonCode에 NoAllowedStorage/DestinationReserved/StorageFull을 추가했다.

WorkReadContext는 이번에 필요한 Pawn 식별·위치와 기존 후보의 대상·경로 값만 제공한다. 미래 시설/작물/내부 자재/정책 스냅샷, FeatureWorkResult, 각 Rules, 새 명령·Runtime 전달·저장 캡처/복원 API는 아직 없다. 이들은 기능별 데이터가 들어오는 통합 단계에서 S0이 계약과 코드를 함께 확장한다. 미래 타입을 참조하는 빈 스텁은 없다. 독립 규칙은 live World/ColonistState/ResourceState를 받아 직접 변경하지 않는다.
