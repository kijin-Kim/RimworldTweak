## 구현 범위

한 슬롯 UTF-8 JSON, schema/scenario/rules 버전1 및 계약 settlement-five-v2. enum은 문자열, long은 정확한 정수, decimal 시간 잔여는 invariant 문자열이다. 타입 메타데이터와 Unity 객체는 저장하지 않는다. BCL DataContractJsonSerializer를 사용해 패키지 버전은 변경하지 않았다.

진행 중인 이동/수동 이동 큐/칸 진행, 식사/침대·바닥 수면, 점유·예약 수량, 반입·운반·시공·철거, 성장·수확·조리, 출력·현장 자재, 개인 작업 설정/저장 필터, Tick/잔여 시간/배속/일시정지, 초기 시나리오/ResetCount를 캡처한다. 삭제/소진 기록과 생산·소비·외부 변경 장부도 보존한다.

토폴로지 또는 시험용 생활 큐가 적용 대기면 SavePendingCommands로 거부하고 시간은 진행하지 않는다. 수동 이동 큐는 저장한다. 새 후보 월드를 검증한 후 한 번 교체하며 실패하면 기존 Session/World/시간/선택을 유지한다. 성공하면 선택·도구·미리보기를 초기화하고 새 월드로 다시 그린다. 경로가 무효하면 후보에서만 기존 취소 경로로 정리하며 물자는 한 번 낙하한다. 정상 경로의 칸 진행과 행동ID를 임의 초기화하지 않는다.

파일은 같은 디렉터리 .tmp 쓰기→flush/close→재읽기·완전 복원 검증→replace/move로 교체한다. 실패 시 기존 최종 파일을 삭제하는 fallback은 없다. 16MiB 초과/손상/추가 JSON root/미지원 버전/중복 ID/잘못된 점유·장부·행동 단계는 거부한다. 임시 파일을 저장 슬롯으로 읽지 않는다. 동시에 진행 가능한 파일 요청은1개다.

## 직접 확인

실행 파일: `E:/Dev/RimworldTweak/Builds/Windows/RimworldTweak.exe`.
실제 Player에서 확인한 제품 기본 슬롯은 `C:/Users/kijin/AppData/LocalLow/RimworldTweak/RimworldTweak/Saves/settlement-v1.json`이다. 코드는 `Application.persistentDataPath`를 사용하며 확인창에 실제 경로를 표시한다. 검사에서는 이 경로를 TestResults로 바꿨으므로 제품 사용자 슬롯을 쓰지 않았다. 한 슬롯이므로 저장 버튼에 덮어쓰기를 명시했다.

1. 정착민이 반입·시공·조리 중일 때 Space로 멈추고 진행 수치/운반량/개인 설정을 확인한다. 오른쪽 아래 **저장 덮어쓰기**를 누른다. 시간과 설정은 그대로여야 한다.
2. 재개해 진행을 바꾸거나 개인 설정을 변경한 뒤 **불러오기**를 누른다. 확인창 동안 Tick이 멈춰야 한다. 취소하면 현재 진행과 이전 배속/정지 상태가 유지되어야 한다.
3. 다시 불러오기→**현재 진행 교체**를 누른다. 저장 당시 시간·정지/배속·물자·작업 진행·개인 설정이 돌아오며 선택과 도구는 해제되어야 한다.
4. 작업자를 다시 선택하고 재개한다. 이전 작업을 이어 완료하며 물자가 중복되거나 점유가 남지 않아야 한다.
5. 정상 종료 후 실행 파일을 다시 열어 불러온다. 같은 슬롯에서 복원되어야 한다. 초기화 버튼은 저장 당시 상태가 아니라 원래 시작 시나리오로 돌아가야 한다.

답변 예: “모두 정상” 또는 “조리39에서 불러오면 투입 식재료가 사라짐”. 실제 디스크 고갈·OS 권한 변경·프로세스 강제 종료 중 전원 장애는 유발하지 않았으며 그 환경까지 재현한 증거는 없다. 실제 슬롯 교체와 잠금 실패는 자동 검사에서 구분해 확인한다.
